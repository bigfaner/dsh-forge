# 1.4: 薄宿主装配：apps/host 四基础子模块 + profile 首启落地

## Description

按 S1 结论装配正式薄宿主（若 1.1 裁决 fallback vendor，本任务按 vendor 模式修订后执行）：`main`（~100 行编排纪律）、`profile/`（产品 profile 模板组装 + 首启落地 `{app-data}/dsh-forge/profile/`）、`boot/`（boot manifest 与 injections 组装）、`ipc/`（`{url, injections}` IPC + `forge:*` 通道注册与 allowlist 骨架）、`window/`（窗口生命周期）。全部基础/装配定位，零业务。

- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Layer Placement（apps/host 行）与包内子模块表（main/profile/boot/ipc/window）
- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Monorepo 工程规范（profile 组装与插件分发段）(ref: Monorepo 工程规范与协作机制)
- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Interface 4（IPC allowlist 通道约定）(ref: Interface 4: Web RPC 面（renderer ↔ main，IPC allowlist 通道）)

## Acceptance Criteria

- [ ] main 入口 ≤~100 行且仅编排四子模块，无业务语义
- [ ] 首启将 profile 模板（官方行 + `@dsh-forge/core` / `@dsh-forge/knowledge` 行）落地 `{app-data}/dsh-forge/profile/`，重复启动幂等不重写
- [ ] `{url, injections}` IPC 注入 renderer 成功（e2e 或集成自证：renderer 收到 boot manifest）
- [ ] `forge:*` 通道注册走 contracts 通道常量 + allowlist 校验（未列通道拒绝，负样例自证）
- [ ] 宿主经 `runProfile`（或 vendor 等价路径）拉起 dsh 宿主进程内插件面

## User Stories

No direct user story mapping.（宿主基建；Story 1–4 的运行时地基。）

## Hard Rules

- 宿主无业务：任何 forge/知识域逻辑一律落 core / knowledge / web（改动判据：必须改基础才能完成 ⇒ 业务放错层）。

## Implementation Notes

- 文件清单：`apps/host/src/main.ts`、`src/profile/*.ts`、`src/boot/*.ts`、`src/ipc/*.ts`、`src/window/*.ts`。
- 通道 handler 本体属 core（2.x 注册），本任务只立机制与 allowlist 骨架。
- dev profile（链 workspace 构建产物）与打包 profile（extraResources 资产）双形态自本任务区分，供 4.1 消费。
