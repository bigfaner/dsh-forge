# 2.4: IPC RPC 面机制 + forge:projects/* 通道（三处一体）

## Description

RPC 面落地：`forge:projects/*`（register/list/get/update/reconcile）五通道 main 侧注册（经 1.4 的 ipc/ 机制与 allowlist）、typed error 边界序列化 `{code, message, data}`、`apps/web/src/rpc/` client 封装（消费 contracts 通道常量与 DTO）。通道契约三处一体：`contracts/{channels,dto}` → `web/src/rpc` → `core` 对应域。

## Acceptance Criteria

- [ ] 五通道端到端通：renderer 侧调用得 typed 结果（集成测试经真实 IPC 或测试替身双层自证）
- [ ] typed error 经边界序列化/反序列化保真（六错误码至少两码自证：ERR_WORKSPACE_CREATE / ERR_COMPENSATION）
- [ ] 通道名仅出自 contracts 常量；allowlist 拒绝未列通道（负样例自证）
- [ ] `web/src/rpc` 不 import 任何服务端实现代码（lint + 构建图自证）
- [ ] UI 按 code 可映射状态（错误条/空态的最简消费约定文档化于 rpc 层）

## User Stories

- Story 1: 注册我的代码项目（表单提交与列表读取的通道）

## Hard Rules

- 新通道三处一体，禁单侧私改（contracts → web/rpc → core 同步变更）。
- 仅修改 `packages/contracts/src/channels.ts`（如需补通道）、`apps/web/src/rpc/**`、`apps/host/src/ipc/**` 注册行、core forge 域 handler 挂接——不触及其它域。
