# 1.1: S1 spike：薄宿主 runProfile 直跑可行性裁决

## Description

M0 首任务（路书既定）。验证 dsh 公开 npm 栈（`@deepseek-ai/dsh-app-boot` 的 `loadProfileDirectory` / `runProfile`）能否以 ~100 行 Electron main 直跑一个最小产品 profile。产出 spike 结论与契约 pin：profile 目录形状、两函数签名、首启落地行为。失败则触发总纲既定 fallback（vendor desktop-host），并即时更新 1.4/1.5 的实现注记。

- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Overview（两条关键缝）/ Dependencies（上游精确 pin）/ Appendix·契约面清单（G1 pin 池第 8 项：dsh profile 目录形状，S1 pin）
- docs/proposals/dsh-forge-redesign/tech-research.md — §1.5–1.7 与 S1 spike 方案及 fallback
- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Architecture（apps/host 薄宿主职责边界）(ref: Layer Placement)

## Acceptance Criteria

- [ ] 最小 Electron main（独立 spike 工程）以 `runProfile` 启动官方 profile 成功开出窗口
- [ ] 自定义 profile 目录（`cordis.patch.yml` 雏形：官方行 + 预留 `@dsh-forge/core` / `@dsh-forge/knowledge` 行）被 `loadProfileDirectory` 接受
- [ ] spike 结论文档化：直跑可行/不可行裁决 + fallback 触发条件 + 两个 API 的实测签名，回填 G1 契约面清单第 8 项（pin 内容）
- [ ] spike 代码隔离存放（spike 草稿目录），不与 1.4 正式装配混同
