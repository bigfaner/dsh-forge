# 1.3: packages/contracts：跨工件契约层（DTO / 错误码 / frontmatter 常量 / 通道名）

## Description

`@dsh-forge/contracts` 全量落地（基础定位：纯类型与常量，零逻辑零依赖）：`dto/`（RPC DTO 与双服务方法签名类型——ProjectService / KnowledgeService 全量）、`errors.ts`（六错误码 typed 定义）、`frontmatter.ts`（最小契约常量）、`channels.ts`（`forge:projects/*` + `forge:knowledge/*` 全通道名）。共享类型唯一源，防 schema 漂移。

## Reference Files

- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Interfaces（Interface 1–4 全量签名）(ref: Interface 1: ProjectService（core · forge 域 → `ctx.forgeProjects`）)
- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Error Handling（六错误码）/ frontmatter 最小契约 (ref: Error Types & Codes)
- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Interface 4（通道清单）(ref: Interface 4: Web RPC 面（renderer ↔ main，IPC allowlist 通道）)

## Acceptance Criteria

- [ ] 六错误码（ERR_WORKSPACE_CREATE / ERR_PROJECT_WRITE / ERR_COMPENSATION / ERR_ENTRY_NOT_FOUND / ERR_INDEX_STALE / ERR_INVALID_KNOWLEDGE_DIR）typed 定义与 Error Handling 表一致
- [ ] frontmatter 常量落地：summary/keywords 必填、title 缺省=文件名去扩展名、status 默认 draft、id 存而不强求、域 ≤3 层
- [ ] 通道名常量覆盖 Interface 4 两域全部通道（projects: register/list/get/update/reconcile；knowledge: browse/listEntries/entryDetail/heat/sessionRecall）
- [ ] 包零运行时依赖、零逻辑；`tsc -b` 通过且被四工件 references 引用

## User Stories

No direct user story mapping.（契约基建；Story 1–4 的数据形状由此承载。）

## Hard Rules

- 契约层只描述形状不实现业务——禁止引入函数逻辑或运行时依赖（定位铁律）。

## Implementation Notes

- DTO 与两服务签名按 tech-design Interfaces 1/2 逐项对照，不自行增删字段；RPC DTO 含 typed error 序列化形状 `{ code, message, data }`。
- 此后任何通道/DTO 变更 = 三处一体（contracts → web/rpc → core 对应域），落点速查表约束。
