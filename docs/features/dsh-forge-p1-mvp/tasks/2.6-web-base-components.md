# 2.6: web/components 领域无关基础组件（MarkdownDoc / StateChip / HeatBadge / EmptyState）

## Description

`apps/web/src/components/` 基础子模块：`MarkdownDoc`（`MarkdownText` 族唯一包装入口，variant = body | compact——安全渲染纪律：产品不自建渲染器）、`StateChip`（状态徽章）、`HeatBadge`（热度徽章）、`EmptyState`（统一空态简版）。全部领域无关、吃令牌、零业务逻辑、不发起 RPC。

## Reference Files

- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Monorepo 工程规范（apps/web/src/components 行）与 Security·Mitigations（MarkdownText 族）
- docs/features/dsh-forge-p1-mvp/design/page-map.md — Shared Components（四组件消费方清单）
- docs/features/dsh-forge-p1-mvp/prd/prd-ui-functions.md — UF-6 Data Requirements（热度 = 事件计数展示）/ UF-4 States（空态）

## Acceptance Criteria

- [ ] 四组件可用并具备最简交互态（EmptyState 引导插槽 / HeatBadge 数值展示）
- [ ] `MarkdownDoc` variant=body 正文区不含 frontmatter 字段；variant=compact 预留（M4 消费）
- [ ] 组件零业务语义：不含 RPC 调用、不含 forge/知识域类型（props 为原始形状）
- [ ] 样式全 `--dsw-*` 令牌（令牌 lint 过）；官方已有件一律复用不自绘

## User Stories

No direct user story mapping.（Story 3/4 的展示件基座。）

## Hard Rules

- Markdown 渲染只经 `MarkdownDoc` 单一包装（架构基线渲染纪律），产品内禁止直接使用裸渲染器。

## Implementation Notes

- 文件清单：`apps/web/src/components/{MarkdownDoc,StateChip,HeatBadge,EmptyState}.tsx` + storybook 式演示页或单测快照自证（按仓库既有测试形态择一）。
