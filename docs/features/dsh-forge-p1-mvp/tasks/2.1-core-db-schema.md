# 2.1: core/db 基座：SQLite 句柄唯一落点 + schema v1 前向迁移（五表）

## Description

`packages/core/src/db/` 基础子模块（无域语义）：better-sqlite3 句柄唯一落点（`{app-data}/dsh-forge/state.db`，WAL，prepared statements 纪律）、schema v1 前向迁移机制（五表 + 七索引，DDL 单一来源 = `design/schema.sql`）、事务助手、`schema_meta` 版本门（version 超支持上限明确拒绝——旧应用打开新 schema 不支持）。全 CREATE 无 ALTER。

## Reference Files

- docs/features/dsh-forge-p1-mvp/design/tech-design.md — Layer Placement（core/db 行：句柄唯一落点、schema 迁移、事务助手）
- docs/features/dsh-forge-p1-mvp/design/schema.sql — 五表 DDL + 索引 + CHECK 约束（迁移唯一蓝本）
- docs/features/dsh-forge-p1-mvp/design/er-diagram.md — Index Design（七索引清单）与各表约束

## Acceptance Criteria

- [ ] DDL 全五表 + 全部索引在临时库执行零错（db-schema 规则：DDL executes / FK resolve / indexes created 三项合并覆盖）
- [ ] FK 全解析 + CHECK 约束生效：verb / level / scope / forge_dir_external 非法值被拒（负样例自证）
- [ ] `schema_meta` 前向门：v1 写入 applied_at；version 超支持上限时明确拒绝打开
- [ ] db/ 子模块零域语义（不出现 forge/知识业务概念），迁移函数与 DDL 单一来源对齐 schema.sql

## User Stories

No direct user story mapping.（数据基建；Story 1/3/4 的落库地基。）

## Hard Rules

- SQLite 句柄仅 core/db 持有（L1 单写者纪律）；一切 SQL 走 prepared statements。
- 仅创建 `packages/core/src/db/**`（+ core 插件定义占位）；域表消费方（forge/knowledge 子模块）不在本任务范围。

## Implementation Notes

- **db-schema 规则裁决说明**：规则默认按 er-diagram 实体逐个建 Schema 任务；本设计为绿地单 DDL 单迁移文件、全 [NEW] 无 ALTER、五表一次落地，逐实体拆分无独立验证价值——合并为单任务，AC 显式覆盖全部实体（LLM override，理由记录）。
- 全 CREATE TABLE → `breaking: false`。
- 迁移以 TS 代码内嵌 DDL 执行（产出可编译代码 → coding 类目），`design/schema.sql` 为对照蓝本。
