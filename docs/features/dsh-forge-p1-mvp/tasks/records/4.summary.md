## Conventions Established
- 打包形态三形态解析口径（4.1）：dev（profile.dev 树）/ staged（DSH_FORGE_RESOURCES_DIR 掌舵）/ installed（app.isPackaged 注入）——后续 resources 消费方一律经 {resources}/runtime/package.json 合成 anchor 驱动 resolution BFS，禁在 profile 放 node_modules（junction 被 ESM realpath 逃逸，探针实证）
- 打包树 peer 自足纪律（4.1）：profile.install（hoisted + autoInstallPeers:true）与 profile.dev（autoInstallPeers:false S1 pin + workspace 隐藏仓兜底）分立维护——打包闭包/插件面变更后必须重过 dist:win 真机探针（与「插件 tarball 需重 stage」教训同型）
- dogfood e2e 纪律（4.2）：凭据经 dsh profile 域外部叠层（产品不经手）；缺席 = 留痕 skip 不伪造；官方首启模态 = 叠层预确认 + 稍后配置 fallback（修实现不修断言）；录制回放仅 flake 触发后评估、不预建
- 真安装链路冒烟形制（4.3）：NSIS 静默 /S /D= + assemble --check 同口径 + playwright _electron executablePath 探测法 + 干净环境 Hard Rule（每跑全新 userData、首启 profile 真覆盖、静默卸载 + rmSync 兜底零残留）；环境前置（TEMP/TMP 重定向、盘根短路径）在套件内自处置不外溢
- 实测坑排障入档形制（4.1/4.3）：环境级陷阱（filter 硬编码剔除根级 node_modules、%TEMP% 物化解压静默 exit 2、MAX_PATH 深路径、慢盘收敛窗）记入 record/SMOKE-LEDGER 台账供后续里程碑引用，不散落
- RPC 桥 wire 契约纪律（fix-1）：boot 选项 argv[2] JSON 单串、Map 经 __dshForgeMap__ 信封、方法白名单双面锚定（主侧代理 = 子侧可达面）——后续跨进程面新增服务方法先扩白名单常量
