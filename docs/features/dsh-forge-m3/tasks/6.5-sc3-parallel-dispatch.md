# 6.5: SC3 e2e:3 任务并行派发 + 注入三要素断言 + 审批可见可操作

## Description

SC3 验收腿:已迁移项目 3 个无依赖任务从看板多选并行派发,各 subagent 独立启动互不串扰;每个 subagent 注入内容(stub journal 逐字符)可断言包含三要素(任务类型协议 + feature 目标摘要 + 生效偏好);审批请求在工作台可见,批准/拒绝操作有效;派发 → 可交互 ≤3s(stub 计时)。

## Acceptance Criteria

- [ ] 并行派发:3 无依赖任务多选 → 派发 → 各 dispatch 行独立、角标互不串扰(看板断言)。
- [ ] 注入断言:3 个 subagent 注入内容逐字符断言含各自任务类型协议 + 同 feature 目标摘要 + 生效偏好;journal 与 prompt_hash 口径一致(spike③)。
- [ ] 审批:stub 注入审批请求 → 看板可见(dock + 角标 + 计数)→ 批准 → 回执行中;拒绝 → 失败态 + 重派发可用。
- [ ] 时效:派发 → stub 可交互 ≤3s(计时断言);状态回流 ≤5s。
- [ ] 腿纳入 e2e 套件并通过。

## User Stories

- Story 2: 看板派发与并行执行闭环(e2e 验收)
- Story 3: 派发即得预合成专业化上下文(注入内容断言)

## Hard Rules

- 注入断言必须逐字符(journal oracle),不接受「包含子串」弱断言三要素之一缺席的回归。
