# 3.3: dispatch 内核域:dispatch/approval_request 仓储 + 编排动词 + 审批决策 + 事件

## Description

编排域内核(不含 subagent 启动——host 侧归 3.5):dispatch(5 态)/approval_request(3 态)仓储;动词 dispatchTasks(可派发集校验:状态允许 + 依赖终态;含依赖 → 阻止;checkStageArtifacts 消费:缺失且未 acknowledgeMissing → blocked:artifacts-missing)/redispatch(重走检查)/getDispatches/listApprovals/decideApproval(显式决策,重复决策 → ERR_APPROVAL_DECIDED,decided_by 审计);事件 dispatch_updated/approval_received;不变式 dispatch.state='awaiting' ⇔ 存在同 dispatch pending 审批。subagent 启动位点留 host 回调接口(session_id 回填、launch 失败 → failed 态)。

## Acceptance Criteria

- [ ] dispatchTasks:依赖未满足/终态任务集 → 阻止并返回依赖提示;产物缺失未确认 → blocked 返回缺失清单;acknowledgeMissing → 受理;同批多任务 batch_id 聚合。
- [ ] 状态机:dispatch 5 态(starting/running/awaiting/failed/done)合法迁移;host 回调(session_id 回填/failed+error)驱动迁移,内核事务落库。
- [ ] 审批:approval_request 创建 → awaiting 联动;decideApproval 批准/拒绝显式操作,decided_by/decided_at 审计;重复决策 → ERR_APPROVAL_DECIDED;失效条目 → ERR_APPROVAL_NOT_FOUND。
- [ ] 不变式守护:awaiting ⇔ pending 审批(同 dispatch)在全部迁移路径成立(测试断言)。
- [ ] 事件:dispatch_updated/approval_received 经批量通道推送(≤500ms 节流,M2 机制延续)。
- [ ] vitest 行覆盖 ≥80%。

## User Stories

- Story 2: 看板派发与并行执行闭环(编排域内核;UI 归 3.6-3.9)

## Hard Rules

- 审批仅显式动词决策,无默认自动批准;决策留 decided_by 审计(T5)。
- 内核不持会话创建权:subagent 启动仅经 host 回调接口,dispatch-launch 归 host 半身(裁决:dispatch 逻辑入内核)。

## Implementation Notes

- 并行语义:每任务独立 dispatch 行(N 次派发互不共享),并行互不串扰断言在 3.5 实测。
