### Key Decisions
- COMMIT 收口在归档改名之后(归档在迁移事务边界内):归档失败或 COMMIT 失败 → 事务 ROLLBACK + index.json 改名回滚(备份整树拷回兜底),库与文档树全程不出现半迁移态;满足 Hard Rule『置位与全量摄入同事务』且免去对打开连接做库文件级恢复(Windows 不可行)
- migration_event 审计行不进迁移大事务:backup 相在开事务前落档(成败均留痕),ingest/verify/switch/archive 相随事务原子提交,失败路径在 ROLLBACK 后补记失败相+rollback(失败审计不被回滚吞掉);大事务只触碰 task 行 + projects 增列
- 已迁移项目再发起 startMigration → ERR_MIGRATION_GUARD(消息注明 already migrated/one-shot):设计错误表面迁移域封闭三码,无 already-migrated 专属码,折入守卫相并显式记录;自然回退面(全部 index.json 已归档)会以 ERR_MIGRATION_VERIFY 噪音失败,显式守卫更优
- 摄入复用 indexer 同一解析器 parseFeatureTasks(逐字同源校验/方言),这是对拍零差异的结构前提;task_type/desc_path 按 entries.id 回查推断(entry.type 原词 / <slug>/tasks/<file>,file 缺省 <stem>.md);updatedAt 沿用 forge 工件 mtime 派生时钟,不重铸
- startMigration 为异步动词(备份/归档走 fs/promises):迁移中判定 = 服务实例间共享的 in-flight projectId 集合,第二个发起在首个 await 挂起窗口内确定性落入 ERR_MIGRATION_IN_PROGRESS;handlers register 辅助函数扩展 then 链异步拒绝同码封装(同步路径不变)
- in-flight 集合为模块级(单进程内核单迁移窗口),按 projectId 键控;归档/备份/摄入的 feature 枚举统一字典序钉定,失败注入与恢复断言不依赖平台 readdir 顺序
