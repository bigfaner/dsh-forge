## Conventions Established
- Write-face lazy discipline now applies to every new face: absent write member = disabled control + tooltip; absent read member = null; mock twins mirror kernel semantics exactly (3.9 precedent, extended by StageFace).
- Client/server twin optionality rule: server-mandatory fields may be optional in client twins when required-ness would churn existing fixtures (deviated?, goal/summary? precedents); render gates use === true / field presence.
- Manifest write discipline: status-only in-place replacement preserving key order and body; data-endangering states get dedicated rejection codes (ERR_STAGE_MANIFEST_UNREADABLE) instead of best-effort rewrites.
- Domain event payload convention: carry {projectId, featureSlug} so consumers filter by active project; when distinct events share one batch channel, extend the batcher coalesce key with the distinguishing fields.
- Perception-face read failures degrade to prior-milestone presentation (undefined → M2 rendering), never error cards; hooks on the perception seam never throw.
- Terminal-state suppression: completed features suppress advancement UI (no gate state, no advance button) rather than rendering disabled controls.
- After any forge-workbench client src change: rerun pnpm build:plugins before lib-loading tests (stale-lib trap).
- Whenever BRIDGE_MEMBERS grows, extend the three assembly specs' fullBridgeFake fixtures (member-callable check).
- Additive-extension-point pattern for shared M2 components: optional props gate new visual states; absent/false must leave M2 rendering byte-identical (FeatureStepper gatePending, FeatureDocs sixth tab).
