## Summary
Implemented external-write reingest + deviation marking on migrated projects (Interface 4 step 7 / T3). New migration/reingest-watcher.ts attaches to the M2 perception base (watcher scan seam + services rescan): after each scan, on data_authority='sqlite' projects, any reproduced tasks/index.json (migration archived them all, so presence = external write; kernel never writes files on sqlite projects) triggers an idempotent reingest — sha256 fingerprint set dedupes repeated perception rounds of the same external write — followed by projects.deviated=1 + deviation_detected event (independent commit so the mark survives failures) and a single-transaction replace (deleteTasksByFeature + insertTask rows from the shared collectFeatureIngestRows mapping extracted from 1.4 ingest) verified by the same verifyMigrationParity oracle, with migration_event(reingest ok|fail) audit. ### Key Decisions
- Presence-based detection: after migration all index.json files are archived and the kernel performs zero file writes on sqlite projects, so any tasks/index.json under the features root IS the external-write signal (no host intrusion, no content heuristics)
- Idempotency = sha256 fingerprint set (slug+hash, sorted) recorded in every reingest audit detail (ok and fail): a matching latest fingerprint set skips silently — one audit/event per actual external write, and a corrupt file does not retry every scan until its bytes change
- Reingest write path = per-feature delete-then-insert through task-repo (deleteTasksByFeature added, single-write-entry discipline preserved) reusing the exact 1.4 mapping via the extracted collectFeatureIngestRows — parity between task and task_snapshot is guaranteed structurally and re-checked by verifyMigrationParity inside the transaction (mismatch = wholesale ROLLBACK, zero half-ingest)
- deviated=1 + deviation_detected commit before the reingest transaction so AC-3's '偏离标记保持、事件照发' holds on failure; ok audit commits atomically with the reingest, fail audit is written outside the rolled-back transaction
- deviation_detected modeled as the project-level variant { projectId } of the tech-design event; the featureSlug variant belongs to 4.2 (feature-level manifest deviation)
