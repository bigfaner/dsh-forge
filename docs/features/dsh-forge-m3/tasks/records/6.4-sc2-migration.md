### Key Decisions
- Failure injection as an env-seam-family stub switch (session-channel-stub precedent) rather than data-level corruption: the AC names the base stub switch, and the archive fault exercises the strongest zero-half-migration path (post-switch, mid-rename rollback with doc-tree rename-back) that a verify-diff fault cannot reach
- MigrationFaults seam accepts a per-run resolver (union type) resolved once at each startMigration entry — same service instance supports 注错→回滚→清错→重试 within one boot; backward compatible with the static-object form the unit lane uses
- Control file re-read per startMigration (never snapshotted at boot) — the retry journey is file-driven end to end
- AC-2 parity uses three faces (task ↔ task_snapshot ↔ generator ground truth): the third face kills the trivial two-empty-tables pass; task_snapshot is materialized by startMigration's own pre-scan (6.3 seam) and stays untouched post-migration (no watcher on a never-activated project)
- Leg 1 corpus sized 300 tasks/6 features so the running window is seconds-scale — the close-guard observation (Esc mid-run + absent ✕) is not a race
- Wizard-path complement chosen as external docs root + explicit authorization (the M2 fixture writer's anticipated 6.4 shape), distinct from 6.3's in_repo leg
