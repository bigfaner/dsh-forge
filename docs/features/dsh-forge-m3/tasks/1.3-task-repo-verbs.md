# 1.3: task 权威仓储与 CRUD 写集动词:7 态唯一写入口 + 读路由 data_authority + actor 审计

## Description

task 表(SQLite 权威)仓储与内核 CRUD 动词:taskAdd/taskClaim(依赖终态前置 → ERR_TASK_DEPS_UNSATISFIED)/taskTransition/taskSubmit/taskReopen 全部经 1.2 状态机校验(唯一写入口,内核事务);taskGet/taskQuery 读路由按 `projects.data_authority`(files → task_snapshot 派生投影,sqlite → task 权威表);每笔变更强制记 `updated_by`(actor:session:<id>|external|kernel);taskKey 校验 = 看板限定地址(单 `/` 分隔 + 两段非空 + 禁路径分隔/控制字符,弃裸 ID 数字正则)。

## Acceptance Criteria

- [ ] 五个写集动词全部经状态机合法边校验后落库(单事务);非法迁移边返回 ERR_TASK_STATE_INVALID,不产生部分写入。
- [ ] taskClaim 依赖终态前置:上游未终态 → ERR_TASK_DEPS_UNSATISFIED(含悬空 blocker 语义 = 显式标记不阻断判定外的误通过)。
- [ ] 读路由:files 项目 taskGet/taskQuery 走 task_snapshot(M2 行为不变);sqlite 项目走 task 权威表;切换仅随迁移事务置位生效。
- [ ] actor 审计:每笔写动词记 updated_by + updated_at;taskKey 校验拒绝非法形态(路径分隔/控制字符/裸数字单段)。
- [ ] IPC 动词注册进 channel-allowlist 常量表(通道命名 v1 惯例),preload/main 共享同源,无两侧手写。
- [ ] vitest 行覆盖 ≥80%(含 7 态动词矩阵与读路由双分支)。

## User Stories

- Story 9(agent 会话内经 tool 执行 claim/submit,留 actor 标识)——动词与审计层的内核地基

## Hard Rules

- SQLite 单写者纪律:task 表唯一写入口 = 本仓储的内核事务路径;禁任何旁路写。
- 通道常量表追加式修改:本任务仅追加 tasks 动词段,禁改写 M2 既有动词定义。
