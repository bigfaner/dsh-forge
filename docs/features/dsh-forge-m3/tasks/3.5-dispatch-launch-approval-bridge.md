# 3.5: dispatch-launch 与 approval-bridge:host subagent 创建 + 审批路由往返 + 降级链

## Description

host 半身编排通道:①dispatch-launch:消费内核预合成产物,经 sessionController 创建 subagent(`create({cwd})` + 注入契约按 spike③ 裁决),N 次独立 create 互不共享上下文(G3 并行);session_id 回填 dispatch 行,失败 → dispatch failed 态 + 原因(ERR_DISPATCH_LAUNCH_FAILED);契约不满足 → 派发前检查拒绝(ERR_SYSTEM_PROMPT_CONTRACT)。②approval-bridge:宿主 subagent 审批事件(按 spike② 契约)→ tool 桥 → 内核 approval_request(pending)→ 事件推送 UI;decideApproval 反向经桥回 subagent 审批通道;FORGE_ACTOR 语义延续(dispatch 行 + task 变更记 actor)。

## Acceptance Criteria

- [ ] 派发链:内核 dispatchTasks → host launch → subagent 创建成功 → session_id 回填 → dispatch running;stub 实测派发 → 可交互预算 ≤3s(计时断言,stub 环境)。
- [ ] 并行:≥3 无依赖任务同批派发,各 subagent 独立 create 互不共享上下文,dispatch 行互不串扰(stub 断言)。
- [ ] 注入:预合成内容按 spike③ 契约完整交付(逐字符断言,hash oracle 形态);契约不满足 → ERR_SYSTEM_PROMPT_CONTRACT 拒绝派发。
- [ ] 审批往返:subagent 审批事件 → approval_request(pending)→ awaiting 联动 → 事件推送;decideApproval 批准/拒绝经桥回注 subagent;FORGE_ACTOR 透传按 spike② 形态落在 dispatch 行与 task 变更。
- [ ] 降级链:launch 失败 → dispatch failed 态 + 原因(可重派发);桥不可用 → 会话内明确提示(重试一次,禁静默)。
- [ ] vitest + stub:派发/审批/降级三组主路径。

## User Stories

- Story 2: 看板派发与并行执行闭环(subagent 通道层)
- Story 3: 派发即得预合成专业化上下文(注入交付层)

## Hard Rules

- dispatch-launch 仅 host 半身持会话创建权;内核不创建会话(裁决:dispatch 逻辑入内核 + host 仅持 launch)。
- 并行 = N 次独立 create,禁止共享上下文/会话复用(G3)。
