# UI Design: dsh-forge M3 流程即产品

> 设计对象 = M2 工作台的**扩展**:tab 序修订(概览/提案/Feature/任务)+ UF1-UF5(派发编排 / 阶段化 / 迁移 / 偏好 / 提案看板);会话视图 100% 继承上游 GUI(TECH-ui-reuse-001),仅作为 subagent 执行跳转目标。M2 既有组件(UF1-UF6)的形态与令牌为本文基底,不做重设计——仅按 M3 语义演进(见 UF1 的「发起会话 → 派发执行」演进声明)。

## Design System

**上游 dsh 设计语言**,完整提取见项目根 [DESIGN.md](../../../DESIGN.md)(源:上游 `packages/client/ui-theme/src/styles/`)。与 M2 同源同则:

- **色彩**:一律语义别名(`--dsw-alias-*`),亮暗双主题经 `body[data-ds-dark-theme]` 自动切换;品牌动作/执行中态 `--dsw-alias-link`;审批/门未满足/偏离 = `state-warn-primary`;失败 = `state-error-primary`;完成 = `state-success-primary`
- **字体**:系统栈;12/18(辅助)/ 14/22(正文)/ 16/24(标题,500);键名/路径/ID = mono 代码栈
- **动效**:`cubic-bezier(0.4,0,0.2,1)`,0.1/0.2/0.3s;侧板 slide-in 0.2s;编排态与回流高亮 0.3s
- **几何**:r14(卡片/小面板)/ r20(菜单)/ r24(对话框,mask-1 + blur(2px));按钮胶囊 md h36 r18 / sm h28 r14
- **组件先例**(上游 ui-primitives):StateDot(编排态点,`aria-label` 全称)/ Pill(状态与徽标)/ Menu 卡(层级与 feature 选择)/ Modal(迁移与派发确认)/ Toast(偏好保存等轻反馈)
- **M3 先例外溢声明**:① checkbox 为上游先例清单外**新增控件原语**——28×28 r14 · focus ring 2px `--dsw-alias-link` · 勾选 = 品牌蓝填充 + 白勾,原生 checkbox 语义(`checked` / `aria-label` = 任务标题);② 「审批 N」以 Pill 形态充当可点按钮(warn 填充)——刻意混血以延续状态徽标语义,键盘/焦点契约按 Button(Tab 可达 · Enter/Space 触发 · 同款 focus ring),不另设新组件类目

## Component: 任务派发与编排(UF1)

### Placement

- **Mode**: existing-page
- **Target**: 工作台 · 任务看板(`workbench/tasks`,第四 tab)
- **Position**: 工具栏(派发/审批入口)+ 视图主区(选择模式与编排态角标)+ 任务详情侧板(派发主按钮与编排分区);审批面板 = 右侧 dock 侧板(与任务详情侧板同构、互斥呈现)

### Layout Structure

**工具栏追加(M2 工具栏右侧)**:

```
│ …(视图/筛选/排序,继承 M2)…  [派发](md 主)  [⬤审批 2](warn Pill 按钮) │
```

- 「派发」:md 主按钮,常驻;无可派发任务(依赖未满足/终态)disabled + tooltip 原因
- 「审批 N」:warn 填充 Pill 按钮 + StateDot 呼吸点;N = 待审批数;N = 0 时隐藏(非 disabled)
- **工作台级审批指示**:「任务」tab 标签右上追加 warn 计数徽标(N,12/18,`aria-label="N 项待审批"`;N = 0 不渲染)——用户身处概览/提案/Feature tab 时仍可见待审批信号(点击任务 tab 后由工具栏「审批 N」承接操作);会话视图 = 上游 GUI 零侵入,**不呈现审批指示**(G3「可见可操作」由工作台侧全量承载,显式裁决)

**选择模式(点击「派发」进入)**:

```
┌ 视图主区(选择模式)────────────────────────┐
│ ☑ ┌─T1.2────⤢┐   ☐(disabled)┌─T1.3───┐    │
│   │● 任务标题 │              │● 任务   │    │  checkbox 28×28 r14,出现于
│   └─────────┘   ⚠ 有依赖    └────────┘    │  卡片左上(覆盖);⤢ = 详情入口
└─────────────────────────────────────────────┘
│ 浮动操作条(r14 · bg-layer-2 · 阴影 · z200):已选 2 项  [取消(ghost)] [派发所选 2 →](md 主) │
```

- **命中区域划分**:选择模式下卡片/行**整面点击 = 切换勾选**;M2「点击卡片打开详情」收窄为卡片右上「详情」icon(⤢,28×28 ghost,仅选择模式显现,`aria-label="打开任务详情"`)——打开 UF3 侧板,不退出选择模式;视图 C(列表)勾选呈现 = checkbox **内嵌行首**(左缘,非覆盖),行主体点击同 = 切换勾选
- **键盘契约**(M2 依赖树 Tab/方向键遍历延续):Tab / 方向键在卡片/行间移动焦点(焦点边框 `--dsw-alias-link`);选择模式内 **Space = 切换焦点卡片勾选**(显式覆写 M2「Enter/Space = 打开 UF3」),Enter = 打开焦点卡片详情;浮动操作条入场后 Tab 可达(计数文本 → 取消 → 派发所选)
- **Esc 分层**:confirming / warning 对话框打开时 Esc = 关闭对话框(事件不透传),**留在选择模式、已勾选保留**;无对话框打开时 Esc = 退出选择模式并清空已选
- **浮动操作条几何**:视图主区底缘居中、距底 16px、左右 inset ≥16px,z200(介于侧板 z100 与 toast z1100,防侧板遮挡)
- 依赖未满足/终态任务:checkbox disabled + tooltip「存在未完成依赖」;多选含互相依赖 → 后续者 disabled
- 并行派发:存在在跑编排时「派发」仍可进入选择模式发起新派发(并行派发 = G3 场景),新旧派发任务角标独立呈现、互不串扰
- 单任务捷径:UF3 侧板「派发执行」主按钮(等价于选中 1 项派发)

**编排态角标(节点卡/列表行,沿用 M2 Pill 形态)**:

| 编排态 | 角标 |
|--------|------|
| 待启动 | 中性描边 Pill「待启动」(次文字,无填充)——dispatching 受理后、subagent 实际执行前 |
| 执行中 | 品牌蓝 Pill「执行中」+ StateDot 呼吸点 |
| 待审批 | warn Pill「待审批」;**可点击** = 打开审批面板(dock)并滚动定位对应条目(卡片侧审批入口,PRD Placement) |
| 失败 | error Pill「失败」 |
| 已提交 | success Pill 一闪(0.3s)后回落普通状态角标 |

- 枚举对齐:PRD 运行态「待启动/执行中/待审批/失败/完成」与角标一一对应——「待启动」的呈现载体 = 上行角标(dispatching 的卡片面);「完成」= 「已提交」(success 一闪后回落);**不再使用「半透明角标」处理**(opacity 半透明与 DESIGN.md 的 disabled 语义冲突,收编为系统内 Pill)

**审批面板(右侧 dock,宽 `min(440px, 45vw)`,与 UF3 侧板同构互斥)**:

```
┌─ 待审批(2)────────────────────────── ✕ ─┐
│ T2.3 实现 SQLite 迁移原子性       详情 ↗ │  ID mono + 标题(12/18 次文字)
│ 执行 git commit(工作区写入)             │  请求正文(14/22,≤3 行截断
│                                             │  + [展开] 行内展开)
│                [拒绝(sm ghost)] [批准(sm 主)] │
│───────────────────────────────────────── │
│ T2.5  …(下一条)                          │
└───────────────────────────────────────────┘
```

- **信息层级(裁决对象优先)**:请求正文 = 14/22 正文层级、任务行降为 12/18 次文字——批/拒判断的核心依据为面板内最高文字层级;正文 >3 行截断 + 「展开」(行内,不弹层);按钮右对齐(拒绝 ghost 在左、批准主在右)
- **任务上下文入口**:「详情 ↗」= 切换到该任务详情侧板(同层互斥);从审批面板进入的详情,头部追加「◂ 返回审批(N)」(sm ghost)——返回时恢复审批面板剩余条目与滚动位置(上下文取用不断路)

**任务详情侧板(M2 UF3 演进)**:

- 头部主按钮「▶ 派发执行」(md 主,整宽)——**M2「发起会话」的 M3 演进**:同一位置同一形态,语义从「主会话直注」升级为「预合成 systemPrompt + subagent 派发」;无执行条件(依赖/终态)→ disabled + tooltip
- 新增分区「编排」(置于「执行记录」之上):当前编排态 + 派发时间 + subagent 会话链接 [进入会话](sm ghost)+ 失败时的 [重派发](sm ghost)+ 预合成要素行(「协议 ✓ · 目标摘要 ✓ · 偏好 ✓」12/18 次文字,tooltip 展开三要素来源);当前编排态 = 待审批时追加 [去审批](sm 主)——切换到审批面板(**侧板侧审批入口**,PRD Placement;面板 ✕ 后侧板可重开)
- M2「挂接历史」分区语义延续(挂接索引记录 subagent 会话)

### States

| State | Visual | Behavior |
|-------|--------|----------|
| idle | 「派发」disabled + tooltip;无审批按钮 | 无可派发/无待审批 |
| selecting | 选择模式 + 浮动操作条 | 进入派发流程;Esc/取消退出,视图复原 |
| warning(产物缺失) | 确认对话框(r24):warn 图标 + 「当前阶段产物不齐全」+ 缺失清单(逐行,mono 路径)+ [继续派发(md 主)] [取消(ghost)] | 确定性检查未过;**不阻断**(PRD 硬约束) |
| confirming | 派发确认对话框(r24):所选任务列表 + 预合成三要素说明 + [派发(md 主)] [取消] | 检查通过或用户确认继续后 |
| dispatching | 按钮 spinner「正在派发…」;目标卡片即时呈现「待启动」角标 | ≤3s 预算;超时 → error 对话框 + 重试 |
| running | 「执行中」角标(品牌蓝 + 呼吸点) | subagent 执行中;编排态回流 ≤5s |
| awaiting-approval | 「待审批」角标(可点)+ 工具栏「审批 N」warn 按钮 + 任务 tab 计数徽标 | 审批请求到达;**批准 → 回「执行中」,拒绝 → 转「失败」**(侧板编排分区呈现原因「审批请求被拒绝」,[重派发] 可用) |
| failed | 「失败」角标(error)+ 侧板编排分区原因 + [重派发] | subagent 失败;重派发二次确认 |
| done | success 一闪 0.3s → 状态角标 | agent 经 dsh tool 提交,≤5s 回流 |
| updating(回流) | 编排态角标按上表迁移(0.3s 高亮);不打断焦点/滚动 | DF004;M2 属性级/结构性口径延续 |

### Interactions

| Trigger | Action | Feedback |
|---------|--------|----------|
| 点击「派发」 | 进入选择模式 | checkbox 显现(0.2s);M2 全部只读浏览交互保持可用 |
| 勾选任务 | 累加所选 | 浮动条计数更新;依赖冲突项 disabled |
| 「派发所选 N →」 | 产物齐全性检查 → confirming / warning 对话框 | 见 States;确认后派发,退出选择模式;**取消/Esc(对话框)= 关对话框、留在选择模式、已勾选保留**(浮动条计数不变) |
| warning 对话框「继续派发」 | 视为确认,进 confirming | 缺失清单留档日志 |
| 审批「批准」/「拒绝」 | 提交决定 | 该条目滑出(0.2s);**批准 → 任务回「执行中」角标;拒绝 → 「失败」角标 + 侧板原因 + [重派发] 可用**;N-1(tab 徽标同步);**必须显式点击,无默认自动批准**(PRD) |
| 「重派发」 | 二次确认对话框(标题 + 原因回显) | 确认后重新派发(重走检查) |
| 「进入会话」 | 切会话视图 + session-focus | subagent 会话定位;返回 = M1 视图切换既有契约(顶栏切换,session-focus 定位),不新增返回面 |
| 点击「待审批」角标 / [去审批] | 打开审批面板并定位该条目 | 角标 hover 提示「点击进入审批」 |
| 审批条目「详情 ↗」 | 切换到任务详情侧板 | 详情头部「◂ 返回审批(N)」;返回恢复剩余条目与滚动位置 |
| Esc(对话框打开时) | 关闭 confirming / warning 对话框 | 留在选择模式,已勾选保留(事件不透传) |
| Esc(选择模式,无对话框) | 退出选择模式 | 复原;已选清空 |

### Data Binding

| UI Element | Data Field | Source |
|------------|-----------|--------|
| 可派发集/依赖冲突 | 任务状态 + 依赖图 | 内核任务数据(DF004) |
| 产物检查结果 | 缺失清单 | 内核确定性检查(prd-spec 阶段产物清单) |
| 编排态(待启动/执行中/待审批/失败/已提交) | subagent 编排状态 | 内核编排状态(DF004) |
| 审批条目 | 审批请求(任务 + 请求正文) | 宿主会话通道(spike ②) |
| 审批计数(工具栏按钮 + 任务 tab 徽标) | 待审批请求数 | 宿主会话通道(spike ②)聚合 |
| 预合成要素行 | 三要素合成标识 | 内核预合成(DF002) |
| 挂接/进入会话 | 挂接索引 | 工作台自有状态 |

## Component: 阶段化呈现与阶段资产(UF2)

## Component: 显式迁移(UF3)

### Placement

## 全局规则(工作台视图,M2 继承 + M3 增补)

**层叠与共存(M2 继承 + M3 增补)**:对话框 z1200(mask + blur);toast z1100;侧板 z100;**浮动操作条 z200(选择模式期间,介于侧板与 toast 之间)**;回流高亮不抬升 z。审批侧板与任务详情侧板同层互斥(打开一时另一关闭;经「详情 ↗」/「◂ 返回审批」往返时恢复对侧状态)。

**主题与双语(M2 继承 + M3 增补)**:全部组件双主题适配(语义别名);文案经上游 locale 机制(zh/en),不自建文案通道。**数据衍生枚举 label 映射**:编排态、提案 status、feature 阶段等数据衍生 Pill 的标签文字 = UI 层「枚举值 → 文案」映射表,经上游 locale 句集双语呈现(zh:待启动/执行中/待审批/失败/已提交,草稿/已接受/已拒绝/被取代;en:Pending/Running/Awaiting Approval/Failed/Submitted,Draft/Accepted/Rejected/Superseded);映射键集 = forge 数据枚举闭集,映射外未知值兜底 = 数据原值原样透出(中性 Pill)——色谱与文案均为呈现约定,状态语义归 forge 数据。

**键盘与可访问性(M2 继承 + 增补)**:侧板/向导/对话框焦点陷阱(Esc 关闭、Tab 循环);**迁移进度对话框例外——执行中 Esc/mask/✕ 全部无效(原子性,Esc 不注册关闭)**;选择模式键盘契约(Tab/方向键遍历、Space = 勾选、Enter = 详情、Esc 分层)见 UF1;编排态角标/审批按钮/stepper 门态一律 `aria-label`(全称);回流与编排态变化 `aria-live="polite"`,**播报节流口径**:同一任务 2s 窗口内多次态变仅播报终态;批量回流(并行派发/批量提交)聚合为一条计数播报(如「3 个任务进入执行中」);一次感知批至多 1 条聚合播报,审批计数变化单列 1 条;节流独立于动效降级;仅图标按钮必须具名;`prefers-reduced-motion: reduce` 降级(呼吸点/位移禁用,保留淡入)。

**markdown 只读渲染(M2 继承)**:提案/阶段资产/文档一律只读渲染——禁 raw HTML、禁脚本、禁外链离开应用;渲染区不含交互元素。

**审批纪律(PRD 硬约束)**:批准/拒绝仅经显式点击,无默认自动批准;审批请求到达仅呈现提示(warn 角标/按钮计数),不弹模态。

**数据时效**:编排态/审批计数/偏离标识/提案变化回流 ≤5s 免手动刷新;属性级变更不打断焦点/滚动(M2 口径延续)。

**性能预算**:派发 → subagent 可交互 ≤3s(dispatching spinner 期间不阻塞看板其余交互);看板首屏 ≤2s(500 任务);骨架先行,禁止白屏等待。
