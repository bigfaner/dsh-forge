# 2.2: 自有 SoT repos：projects / app_state(单激活事务)/ session_links

## Description

实现工作台自有状态三表的仓储层:projects(注册/更新/移除/列表)、app_state(单激活项目,事务内保证「至多一个 active_project_id 且引用有效」)、session_links(挂接登记/结束,UNIQUE(project_id,task_key,session_id) 与 FK CASCADE 语义)。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — §Interfaces Interface 1(projects/registerProject/updateProject/removeProject/activateProject/recordSessionLink/endSessionLink 动词的语义与类型)、§Data Models
- docs/features/dsh-forge-m2/design/er-diagram.md — projects/app_state/session_links 实体细节(UNIQUE 约束、status active/ended、FK CASCADE)

## Acceptance Criteria

- [ ] projects CRUD 齐全:插入(display_name/code_root/doc_location 三型)、更新 patch、按 id 删除(FK CASCADE 波及 session_links,快照表不动)、列表查询。
- [ ] app_state 读写:activateProject 在单事务内完成「清旧 + 立新 + 引用有效性断言」,任何时刻至多一个 active_project_id。
- [ ] removeProject 后 getActiveProject 不再返回被删项目(自动回退空或保持空,不抛 FK 错)。
- [ ] session_links:recordSessionLink 幂等(重复登记不炸 UNIQUE,语义=刷新)、endSessionLink 置 ended 不删行、按项目/任务查询含历史。
- [ ] vitest 覆盖:单激活并发写序列、CASCADE 删除、UNIQUE 幂等、ended 后再 active 恢复语义(同 session 复挂)。

## User Stories

- Story5 多项目管理:第 2 项目注册/切换完整/移除不动仓内文件(repos 层语义)。
- Story2 一键发起:重启后挂接仍在(session_links 持久化)。

## Hard Rules

- 自有表只经本 repos 层写入;禁止任何调用方手写 SQL 直改三表。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/repos/projects.ts`、`repos/app-state.ts`、`repos/session-links.ts`,共享 `repos/types.ts`(行类型 ↔ Interface 1 DTO)。
- 单激活不变量为 app 层事务纪律(er-diagram 注记),不是 SQL 约束——测试必须覆盖违反序列。
