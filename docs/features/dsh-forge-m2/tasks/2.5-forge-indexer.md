# 2.5: forge 文件 indexer：扫描/解析 → 快照,属性级与结构性 diff,来源判定序

## Description

实现 forge 文件 → 快照的索引器:扫描项目 .forge(任务:状态/依赖/blockers/branch/worktree)与 docs/features(feature 清单、manifest status、五类文档存在性),解析写入 2.3 快照 repos;diff 分属性级(内容变更 → upsert)与结构性(任务消失 → 删除行 + 事件);来源判定按 tech-design Interface 3 序:①FORGE_ACTOR 环境值透传 ②无 actor 时挂接推断(该任务存在 active session_link → [会话],否则 [终端])。

## Acceptance Criteria

- [ ] 全量扫描:fixture 工程的任务/依赖/blockers/branch/worktree/feature 清单全部入库,字段与 forge 文件语义一致(含依赖树可重建:任务引用的 blocker 存在或显式标记悬空)。
- [ ] 增量 diff:单任务状态变更走属性级 upsert(updatedAt 前移);任务文件删除/移相位走结构性路径(行删除 + 对应事件),不留孤儿行。
- [ ] 来源判定:actor 环境值存在 → 透传;无 actor 且任务有 active session_link → [会话];否则 [终端];三条路径单测固定。
- [ ] 解析失败(损坏 md/frontmatter 缺失)不崩溃:跳过该文件、记录 sync_state 错误项、继续其余文件。
- [ ] 每轮扫描结束写 sync_state(游标 + 统计),支持 2.6 的「感知触发增量扫」复用同一入口。
- [ ] vitest:全量/属性级/结构性/来源三路径/损坏容错五组用例。

## User Stories

- Story1 任务可视化浏览:依赖树一致(indexer 是树的事实来源)。
- Story3 状态回流与来源:历史挂接回溯与 [会话]/[终端] 判定基础。

## Hard Rules

- indexer 只读 forge 文件,任何情况下不写回 forge 仓(BIZ-task-ops-001:看板仅呈现)。
- forge 文件为唯一事实源:解析层不得虚构字段(如 branch 缺失即空,不推断)。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/indexer/scan.ts`、`indexer/parse-task.ts`、`indexer/parse-feature.ts`、`indexer/diff.ts`、`indexer/source.ts`。
- 解析器属内核数据适配(非 forge 行为),归 main 而非插件——沿用 2026-09-21 架构约束裁定。
- FORGE_ACTOR 依赖 1.1 结论:若 spike 判不可行,路径①保留代码位但恒空,路径②为主——两者对 indexer 接口无差。
