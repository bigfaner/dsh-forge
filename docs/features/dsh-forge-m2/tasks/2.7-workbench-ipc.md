# 2.7: IPC 动词面：preload dshForge.workbench.* 白名单扩展 + main handlers + sender 校验

## Description

落地主数据面:preload 扩展 `dshForge.workbench.*` 命名空间(15 个语义动词,每动词一条白名单通道 `dsh-forge:workbench-<name>`),main 侧 handler 装配 2.2-2.6 各仓储与服务,含 getState/registerProject/updateProject/removeProject/activateProject/getTaskBoard/getTaskDetail/getFeatureBoard/readFeatureDoc/listPlugins/setPluginEnabled/recordSessionLink/endSessionLink/onEvents(事件推送通道 `dsh-forge:workbench-events`);每 handler 做 sender frame 校验。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — ### Interface 1: IPC 语义动词面 `dshForge.workbench.*`(preload 白名单扩展)(动词/类型/通道命名全表)、§Security Considerations(sender 校验 T 面)、### Error Types & Codes(错误沿动词面回传的封装)
- apps/desktop/src/preload/index.ts — 既有 dshDesktopBoot/__DSH_FORGE_SHELL__/dshForge(update/recovery)桥,workbench 命名空间追加于此
- docs/conventions/electron-ipc-security.md — TECH-electron-ipc-001(白名单通道 + sender 校验纪律)

## Acceptance Criteria

- [ ] 15 动词全部注册且类型与 tech-design Interface 1 一致(请求/响应 DTO、错误封装结构)。
- [ ] 每动词对应唯一白名单通道,preload 侧不暴露任意 invoke 透传;未注册通道调用被拒。
- [ ] 每 handler 完成 sender frame 校验(来源窗体/帧合法性),非法来源拒绝并记录。
- [ ] onEvents 订阅/退订生命周期正确(渲染层销毁即退订);事件通道批推接 2.6 缓冲。
- [ ] setPluginEnabled 经 3.1 守卫:对 mandatory 插件调用返回 ERR_PLUGIN_MANDATORY,成功路径只写 userData 覆盖文件。
- [ ] vitest:动词路由表、sender 拒绝、事件订阅生命周期、错误封装四组用例。

## User Stories

- Story1-Story7 全部 UI 故事的数据面支撑(工作台全部读写经此动词面)。

## Hard Rules

- 每动词一条通道,禁止复用通道名;新增动词必须同步更新 Interface 1 表(契约纪律)。
- handler 内不得内联业务规则——只做参数校验 + 仓储/服务调用 + 错误映射。

## Implementation Notes

- 文件清单:修改 `apps/desktop/src/preload/index.ts`(追加 workbench 命名空间);新建 `apps/desktop/src/main/workbench/ipc/handlers.ts`、`ipc/channel-allowlist.ts`、`ipc/sender-validate.ts`、`ipc/types.ts`(DTO 与 client 侧共享)。
- breaking: true 依据:preload 桥为渲染层共享契约面(上游 SPA + 壳 UI 消费),本任务扩展其类型面;既有 M1 消费方(update-banner/crash-recovery)签名不变、行为不变,属纯增量扩展,但契约文档与类型声明整体演进。
- 与 3.1 的接线:setPluginEnabled handler 经依赖注入接收守卫函数(2.7 内以桩占位并定义接口),3.1 完成后装配处替换为真守卫——不设任务依赖边,避免前向跨相位依赖破坏 phase 顺序闸语义;集成正确性由 6.5 e2e 兜底断言。
