# 5.6: UF2 视图 A Build：@xyflow 依赖树(布局/fit-view/键盘遍历/结构性增量)

## Description

new-page Build 任务(拆分 2/2):任务依赖树视图 A——以 @xyflow/react 渲染 task_snapshot 依赖图(blockers → 边),自动布局(分层/力导二选一,定形后记录)、fit-view、pan/zoom、键盘遍历(方向键在依赖链上移动焦点)、节点卡(任务号/标题/状态色/worktree/来源徽标/分支);结构性增量更新(任务增删只改对应节点/边,不整图重建)。依赖树一致性:与 forge 文件派生的 blockers 关系逐边一致(悬空依赖显式呈现)。

## Acceptance Criteria

- [ ] 依赖树与快照 blockers 关系一致:每条边可溯源到任务 blockers 字段;悬空依赖节点显式标记(不静默丢弃)。
- [ ] fit-view 初始视野包含全图;pan/zoom 流畅;500 节点量级首次布局与交互不卡顿(SC1 预算分摊)。
- [ ] 键盘遍历:方向键沿依赖边移动节点焦点,焦点节点即选中态(与 5.8 侧板联动预留回调)。
- [ ] 结构性增量:事件推送的任务增删只增删对应节点/边;状态变更只更新节点样式(整图重建=缺陷)。
- [ ] 节点卡字段与视图 C 行一致(任务号/标题/状态/分支/worktree/来源),视觉按 ui-design。
- [ ] 组件单测:图构建一致性(含悬空)、增量更新 diff 断言、键盘遍历路径。

## User Stories

- Story1 任务可视化浏览:依赖树一致(核心 AC)。

## Hard Rules

- @xyflow 仅经插件 bundle 引入;不得泄漏为壳或上游 SPA 依赖(裁决 D4)。
- 不得为布局引入原生依赖;布局算法用 JS 实现(必要时内联 vendored,记入依赖决策)。
