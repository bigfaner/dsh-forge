# 3.1: 双层防护：产品清单 mandatory 只读分区 + userData 覆盖文件 + 单写路径守卫

## Description

落地 G6 执行点(Interface 4):host-profile 消费 plugin-bundles.json 的 `mandatory` 字段(forge 核心=必备,清单只读);运行时启停态写入 userData `plugin-runtime.json`(schema 仅 `{disabled:[...]}`,结构上排除必备名);setPluginEnabled 唯一写路径经守卫——对 mandatory 名返回 ERR_PLUGIN_MANDATORY,对畸形运行时文件返回 ERR_PLUGIN_RUNTIME_STATE 并隔离重建。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — ### Interface 4: 基座消费面(双层防护,G6 执行点)(分区 schema/守卫语义)、§Security Considerations(打包后 resources 只读 → 运行时态必在 userData)
- apps/desktop/resources/plugin-bundles.json — 现有清单(bundles 数组),本任务为其追加 mandatory 字段约定并新增 forge-workbench 条目占位
- docs/features/ui-plugin-foundation/manifest.md — 基座交付物边界(本任务消费其「产品级配置装配」,不重复实现装配机制)

## Acceptance Criteria

- [ ] plugin-bundles.json 支持 mandatory: true;host-profile 解析后必备插件无视 disabled 态始终加载。
- [ ] plugin-runtime.json 仅纳第三方:{disabled:[mandatory 名]} 结构被守卫在写入前拒绝/清洗;文件缺失=空覆盖,等价全启用。
- [ ] setPluginEnabled 经唯一写路径:mandatory → ERR_PLUGIN_MANDATORY;第三方成功即写覆盖文件并触发生效(重载/退出注入)。
- [ ] 畸形运行时文件(坏 JSON/未知字段)→ ERR_PLUGIN_RUNTIME_STATE,隔离原文件重建空覆盖,不阻断启动。
- [ ] 产品清单在运行时全程只读:任何启停操作后清单文件字节不变(测试断言)。
- [ ] vitest:必备恒载、写入拒绝、畸形重建、清单只读四组用例。

## User Stories

- Story7 插件管理两级模型:必备无禁用入口、第三方启停、产品清单只读。

## Hard Rules

- 运行时任何路径不得写 apps/desktop/resources(打包后只读;写即违宪)。
- 跨 feature 硬前置:依赖 ui-plugin-foundation 基座任务 2(清单配置化)交付;若其未完成,本任务 blocked 而非绕道自实现装配机制。

## Implementation Notes

- 文件清单:修改 `apps/desktop/src/main/host-profile/index.ts`(消费 mandatory + 守卫接线);新建 `apps/desktop/src/main/plugin-runtime/overlay.ts`(覆盖文件读写)、`plugin-runtime/guard.ts`;修改 `apps/desktop/resources/plugin-bundles.json`(mandatory 字段约定,forge-workbench 实条目由 3.2 落)。
- 双层为纵深防御:即使覆盖文件被手改塞入必备名,守卫在加载侧再拦一次。
