# 2.3: 派生快照 repos：task_snapshot / feature_snapshot / sync_state(可重建语义)

## Description

实现派生缓存三表的仓储层:task_snapshot 复合主键 upsert(7 态 CHECK、blockers JSON、branch/worktree/source)、feature_snapshot(manifest 词表直通、doc_kinds JSON、任务计数)、sync_state 1:1(感知游标/上次同步时间)。核心纪律:三表均为可 DROP 重建的缓存,rebuild 全量入口不触碰自有表。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — §Data Models(SoT 与派生缓存分区)、§Interfaces Interface 1(getTaskBoard/getTaskDetail/getFeatureBoard 的读路径)
- docs/features/dsh-forge-m2/design/er-diagram.md — task_snapshot/feature_snapshot/sync_state 实体细节(复合 PK、7 态 CHECK、manifest 词表直通 'in-progress')

## Acceptance Criteria

- [ ] task_snapshot upsert:同 (project_id,task_key) 重复写入走更新不炸;状态值越界被 CHECK 拒绝;blockers JSON 读写往返一致。
- [ ] 查询面:按 feature 聚合、按状态过滤、按 updatedAt 排序均有索引命中(idx_task_snapshot_feature/status)。
- [ ] feature_snapshot:status 取 manifest 原词(含连字符 'in-progress' 直通,不改写)、taskTotal/taskCompleted 维护一致。
- [ ] sync_state:项目 1:1 读写,支持「游标 + 全量重建」两种复位。
- [ ] rebuild 入口:清空三表重扫不影响 projects/app_state/session_links 任何一行;rebuild 后内容与逐笔 upsert 等价(vitest 对拍)。
- [ ] vitest 覆盖上述全部路径,含 500 行批量 upsert 性能基线(单事务)。

## User Stories

- Story1 任务可视化浏览:看板首屏走快照免整树扫描(repos 层支撑)。

## Hard Rules

- 派生表禁止成为任何事实源:任何字段不得在快照层「补写」forge 文件中不存在的语义。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/repos/task-snapshots.ts`、`repos/feature-snapshots.ts`、`repos/sync-state.ts`。
- 500 行基线为 SC1(≤2s 首屏)的内层保障,只断言写入侧 < 数百 ms 量级,首屏整体断言归 6.2。
