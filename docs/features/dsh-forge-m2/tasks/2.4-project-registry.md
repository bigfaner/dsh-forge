# 2.4: 项目注册校验：forge 检出探测 / 路径规则 / 仓外授权 / 冲突码

## Description

实现 registerProject/updateProject 的校验链:code_root 可读性与 forge 检出判定(.forge 目录 + forge CLI 探测)、doc_location_type/path 规则(仓内默认/仓外可选)、重复注册与文档路径冲突(ERR_PROJECT_EXISTS/ERR_DOC_PATH_CONFLICT)、不可读路径错误码(ERR_CODE_ROOT_UNREADABLE/ERR_EXTERNAL_PATH_UNREADABLE)。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — ### Error Types & Codes(四个错误码语义)、§Security Considerations(外部路径授权 T 面)、§Interfaces Interface 1 registerProject 语义
- docs/features/dsh-forge-m2/prd/prd-spec.md — G/SC 中项目三分模型(仓内默认/仓外路径可选)与操作主体模型

## Acceptance Criteria

- [ ] 非 forge 检出目录(无 .forge)注册被拒,错误信息指明缺失项;检出判定不依赖 forge CLI 在 PATH。
- [ ] 仓外 doc_location:必须显式授权标记(用户确认过的路径登记),未授权即拒;仓内默认路径规则正确派生。
- [ ] 重复 code_root → ERR_PROJECT_EXISTS;doc 路径与既有项目冲突 → ERR_DOC_PATH_CONFLICT。
- [ ] code_root/仓外路径不可读 → 对应错误码,错误含路径与原因(权限/不存在)。
- [ ] updateProject 重指向走同一校验链(编辑模式改仓外配置同样需授权)。
- [ ] vitest 覆盖:合法注册、六类拒绝路径、重指向成功与拒绝。

## User Stories

- Story5 多项目管理:第 2 项目 ≤3 步注册(校验链即时反馈内联错误)。
- Story6 feature 文档与仓外注册:仓外注册全功能、默认仓内。

## Hard Rules

- 仅对已注册(或注册中已通过授权)的路径执行 fs 操作;授权状态持久化,不可由 IPC 单方面绕过。
- 注册校验不得执行任何 forge CLI 写操作(只读探测)。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/registry/validate.ts`、`registry/forge-detect.ts`、`registry/authorize.ts`(仓外授权登记,落 app_state 或独立 kv)。
- forge CLI 探测与 4.1 resolveCli 分工:此处仅判定「项目是 forge 工程」,不解析 CLI 可用性(那是发起链的事)。
