# 2.6: 文件感知 watcher：fs.watch 递归 + 400ms debounce + 轮询兜底 + 事件批推

## Description

实现 DF003 感知面的触发侧:对激活项目的 code_root 与 doc_location 根启用 fs.watch({recursive:true});变更批 400ms debounce 后触发 2.5 增量扫;平台不支持递归 watch 时走降级链(非递归目录树 watch → 2s 轮询兜底);索引 diff 产生的 WorkbenchEvent 经统一通道批推(≤500ms 合并),满足 SC3 的 ≤5s 端到端回流预算(其中感知侧配额 ≤1s)。

## Acceptance Criteria

- [ ] 激活项目切换时 watch 目标正确重建(旧 watch 全部释放,无句柄泄漏;项目移除即停)。
- [ ] 变更 → debounce(400ms)→ 增量扫 → 快照落库全链在感知侧 ≤1s(不含渲染);连续多次写入合并为单轮扫描。
- [ ] 降级链:recursive watch 不可用 → 非递归目录树 watch;再不可用 → 2s 轮询;三级策略对上层(indexer/事件)行为一致,当前策略可观测(日志/sync_state)。
- [ ] WorkbenchEvent 批推:同批事件 ≤500ms 合并发送,事件顺序与快照最终态一致(无乱序导致的回退闪烁)。
- [ ] watch 错误(目录被删/权限变化)不崩溃:转入轮询并上报,目录恢复后自动回到更高一级策略。
- [ ] vitest:触发/合并/降级/恢复四组用例(轮询用假时钟)。

## User Stories

- Story3 状态回流与来源:终端变更 ≤5s 标 [终端](感知侧预算保障)。
- Story4 双形态一致:终端 forge 操作 ↔ 应用呈现同源同频。

## Hard Rules

- 仅对已注册项目路径建立 watch;仓外 doc_location 未授权不得 watch。
- 主进程内不得因感知风暴阻塞 IPC 主循环(扫描必须异步分片)。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/watcher/watch.ts`、`watcher/fallback.ts`、`watcher/events.ts`(批推缓冲)。
- Windows/macOS/Linux recursive 支持差异以运行时探测为准,不以平台硬编码分支。
