# 3.3: 壳级导航注入与双视图切换：上游导航槽位优先,插件内 rail 降级

## Description

实现 D3 渲染载体的导航层:按 1.1 spike 槽位结论,首选向上游 SPA 导航区注入「工作台」入口(双视图切换:会话/工作台);槽位不可用时降级为插件自绘 slim rail(左侧窄栏);两种形态行为契约完全一致(同一 view-key 状态机,零壳代码改动);切换状态持久化(重启回到上次视图)。

## Acceptance Criteria

- [ ] 上游槽位路径:工作台入口出现在上游导航区(槽位契约按 spike 结论),点击切换 会话↔工作台。
- [ ] 降级 rail:槽位不可用时自动启用,视觉为左侧窄栏,切换行为与槽位路径逐项一致(同快捷键/同持久化/同视图键)。
- [ ] 双视图切换零壳代码改动:壳仓库(apps/desktop 除资源清单外)无 diff;全部交付在插件 bundle。
- [ ] 视图状态持久化:重启应用回到上次视图;首次启动默认会话视图。
- [ ] 工作台视图容器挂载 3.2 占位容器并预留 5.x 视图挂载点(view-key → 容器映射表)。
- [ ] 冒烟:两种形态手动/自动切换路径验证,焦点管理与 aria(role=tab/aria-selected)达 ui-design 全局规则。

## User Stories

- Story1-Story7 全部故事的入口载体(工作台可达性)。

## Hard Rules

- 两形态行为契约必须逐项一致:任何交互差异视为缺陷(裁决 D3 约束)。
- 注入不得修改上游 DOM 结构以外的全局样式(作用域样式,防污染上游界面)。

## Implementation Notes

- 文件清单:`packages/plugins/forge-workbench/src/client/nav/{slot-inject.ts,rail.ts,view-switch.ts}`,视图键状态机 `src/client/store/view-key.ts`。
- 槽位契约(名称/order/locale 文案)以 spike 报告为唯一依据,不得自行猜上游内部结构。
