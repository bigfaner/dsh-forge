# 6.5: SC6/SC7 e2e 腿：插件两级模型 + 双形态一致脚本断言

## Description

SC6/SC7 验收腿:①SC6——必备插件(forge-workbench)行无禁用入口(DOM 断言),手改 plugin-runtime.json 塞入必备名后启动仍全量加载且覆盖文件被守卫清洗;第三方插件(hello-world 升格装置)启停往返:禁用即退出注入内容、启用恢复、产品清单字节不变;②SC7——双形态一致:终端侧 `forge task status`(stub CLI)输出与应用看板状态对拍一致;应用侧变更与终端侧读取同源。

## Acceptance Criteria

- [ ] SC6-1:必备插件行 DOM 无禁用控件;IPC 直调 setPluginEnabled(mandatory 名)返回 ERR_PLUGIN_MANDATORY(纵深两层都断言)。
- [ ] SC6-2:预置畸形 plugin-runtime.json(含必备名/坏 JSON 两型)启动不阻断、守卫清洗/隔离后必备全载。
- [ ] SC6-3:第三方启停往返:禁用后其注入内容从上游 SPA 消失、启用后恢复;期间产品清单文件字节不变。
- [ ] SC7-1:终端形态 `forge task status` 输出与看板状态集合一致(同 fixture 对拍,词表直通)。
- [ ] SC7-2:应用侧发起的变更(stub 会话)在终端读取路径同样可见(同源断言)。
- [ ] 两腿纳入 `test:e2e` 套件,tag 可过滤。

## User Stories

- Story7 插件管理两级模型:四 AC 端到端验收。
- Story4 双形态一致:三 AC 端到端验收。

## Hard Rules

- 跑全量 e2e 前必须检查本机无活跃 dsh-forge 实例(ERR_SINGLE_INSTANCE 教训)。
- 清单只读断言用文件哈希前后对拍,不以「没报错」为据。
