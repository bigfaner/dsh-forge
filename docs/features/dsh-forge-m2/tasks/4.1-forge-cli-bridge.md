# 4.1: ForgeBridge(host 半身)：resolveCli 解析链 + getTaskPrompt 安全 spawn

## Description

实现 Interface 2 host 半身服务的 CLI 桥:resolveCli 按解析链(设置显式路径 → PATH 探测 → ERR_FORGE_CLI_UNAVAILABLE,含版本兼容探测);getTaskPrompt(taskKey) 以参数数组 spawn forge CLI 取任务执行 prompt,经 cordis 服务暴露给 client 半身(5.10 入口消费)。prompt 全程按数据传输,不作指令解释。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — ### Interface 2: 插件 host 半身服务面(cordis 服务,client↔host rpc)(resolveCli/getTaskPrompt 签名)、### Dependencies(forge CLI 解析链)、### Mitigations(spawn 参数数组/注册路径 allowlist/taskKey regex)
- docs/features/dsh-forge-m2/prd/prd-spec.md — Story2 AC「首条消息含完整 prompt」、操作主体模型(变更执行归 forge CLI)

## Acceptance Criteria

- [ ] resolveCli:显式设置路径优先 → PATH 探测 → 均失败返回结构化 ERR_FORGE_CLI_UNAVAILABLE(含两路径诊断信息)。
- [ ] getTaskPrompt:taskKey 严格匹配 `^\d+(\.\d+)*$`,非法即拒;仅对已注册项目(code_root allowlist)内的任务发起 spawn。
- [ ] spawn 一律参数数组形式,不经 shell 拼接;stdout/stderr/退出码完整回传;CLI 超时有上限并中断子进程。
- [ ] prompt 作为数据返回(字符串),host 半身不解析/不执行其中任何指令性内容。
- [ ] ERR_NO_PROMPT 场景(任务不存在/CLI 无法产出)错误语义与 tech-design 一致。
- [ ] vitest:解析链三态、taskKey 拒绝、allowlist 拒绝、超时中断、正常往返(stub CLI 脚本)。

## User Stories

- Story2 一键发起:首条消息含完整任务 prompt(桥的取数正确性)。

## Hard Rules

- spawn 仅限注册路径 allowlist + 参数数组;禁止 shell 字符串拼接(注入面)。
- 不得缓存 prompt 跨任务复用(任务状态变更后 prompt 即失效)。

## Implementation Notes

- 文件清单:`packages/plugins/forge-workbench/src/host/forge-bridge.ts`(服务实现)、`src/host/cli-resolve.ts`;client 侧服务声明 `src/client/services.ts`。
- stub CLI fixture 与 6.x e2e 共用(6.1 落);本任务单测先行内联 stub。
