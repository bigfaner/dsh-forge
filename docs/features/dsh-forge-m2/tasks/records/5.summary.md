### 4. Conventions Established

- Three-wave grammar per page family: BUILD (component family over mock twins + DTO half, no IPC runtime touched) -> INTEGRATE (mount, stores, real rpc where owned) -> ASSEMBLY (mock 全撤 via the DI switch: bridge-live runs the real chain; explicit seat or hostless mount reproduces the build-stage page). Unit tests keep running on mocks after assembly; a real-chain e2e smoke per family proves the swap.
- Faces mirror Interface 1 verbs 1:1 (one face per verb family) delivered through seats; mock twins model real verb semantics — transaction ordering, serialized WorkbenchVerbError shapes, failWith test pokes — so build-stage tests exercise real failure classes, not happy paths only.
- IPC adapter pattern (5.16 canonical): guarded window.dshForge.workbench read with a full-members presence walk (partial bridges degrade to absent); one createIpcXxxFace factory per contract face with try/catch routing to normalizeWorkbenchVerbError; a view-level assembly wrapper resolving its own active project over getState with a guidance/retry/error machine; unit tests install a full-verb fake on globalThis.dshForge and assert qualified args + envelope mappings.
- Error envelopes have ONE authority: normalizeWorkbenchVerbError folds plain / serialized-IPC-envelope / unknown rejections into {code,message,detail?} with the ERR_WORKBENCH_DB fallback; code-specific branches (e.g. ERR_SNAPSHOT_STALE) route through it, never through raw message parsing at call sites.
- Shared vocabulary modules for status words: canonical order doubles as UI order and sort rank; raw manifest tokens pass through verbatim in both locales (词表直通, test-asserted); labels ride the upstream locale mechanism and carry precision over any color/dot reduction (never color-only). One sibling file per vocabulary, identical API shape.
