### 2. Key Decisions

- [2.1] Schema DDL carried as an inline TS constant (`schema-v1.ts`) over a build step — plain import graph, packaged app needs no resource file; `schema-v1.sql` stays the projection record with a drift-guard test binding constant<->file.
- [2.1] The two PRAGMAs are connection-level settings applied by `db.ts` on every open, intentionally NOT in the v1 DDL (`foreign_keys` does not persist in the file; `journal_mode` cannot change inside a migration transaction) — declared in the schema-v1.sql header.
- [2.1] `process.features.sqlite` is only a fast negative hint; the authoritative boot probe is dynamic import + in-memory trial open. Corruption classified by SQLite errcode (26 NOTADB / 11 CORRUPT) or message; non-corruption failures (e.g. newer schema_version) stay fatal and never wipe user data.
- [2.2] Single-active invariant is app-layer transaction discipline: existence-assert + app_state upsert + `last_activated_at` stamp inside one `BEGIN IMMEDIATE`; violation sequences roll back leaving the pointer intact.
- [2.2] `removeProject` clears the app_state active pointer in-transaction; session_links and derived snapshot rows are removed by the engine-level FK CASCADE declared in schema v1 — the repo layer issues no snapshot SQL.
- [2.2] `recordSessionLink` = refresh: upsert on UNIQUE(project_id,task_key,session_id) resets started_at, restores active, clears ended_at with a stable row id (covers duplicate registration and ended->re-mount).
- [2.3] Filtered task queries order by `updated_at DESC` (not task_key) — ORDER BY task_key let SQLite satisfy ordering via the composite-PK autoindex and skip the design indexes; EXPLAIN QUERY PLAN assertions now pin index hits.
- [2.3] feature_snapshot task_total/task_completed computed inside the upsert via SQL COUNT over task_snapshot (consistency by construction); snapshot updatedAt is caller-supplied (derived from forge mtimes) — the repo never fabricates timestamps.
- [2.4] Authorization is read at validation time from the app_state registry (no authorization flags in the input) — later IPC faces cannot unilaterally bypass; authorization check precedes any fs probing of the path (Hard Rule: fs ops only on registered/authorized paths).
- [2.4] `ERR_PROJECT_EXISTS` is mapped single-point from the repos UNIQUE violation (registry does not pre-query); forge detection deliberately does not probe forge CLI availability — that belongs to 4.1 `resolveCli` (detection stays PATH-independent).
- [2.4] `normalizeCodeRoot` renamed/exported as `normalizeRegisteredPath`: one normalization convention shared by UNIQUE comparison, authorization registry, and conflict comparison.
- [2.5] TaskRecord dialect adaptation (spike-1-findings 4.1): one write-once record .md per task; `at` = completed (degraded to started, verbatim local string), `kind` = task type from index.json (record file carries no kind), `source` = optional actor frontmatter line (FORGE_ACTOR slot) else null with no historical inference, `summary` = ## Summary section verbatim; no fields invented beyond what forge writes.
- [2.5] task_key stored as qualified address `<featureSlug>/<localId>` — the live dialect collides local IDs across features (this repo M1 vs M2 overlaps 33 keys; SC1's 50-feature fixture forces collisions too); bare IDs would silently overwrite. blockers stay verbatim local IDs resolved within the row's feature namespace.
- [2.5] No gate/summary/T-* exclusion: snapshot is the full faithful index.json task graph (SC1 board = `forge task list` consistency; business tasks legitimately depend on phase gates like `5.gate` — excluding them would fabricate dangling blockers). Dangling blocker refs preserved verbatim and flagged in scan stats.
- [2.5] Degraded-scan semantics: parse failures still commit the parseable data but the round ends in sync_state error with cursor NOT advanced (last_scan_at = last clean scan); corrupt index.json preserves that feature's existing rows; unchanged rows are never rewritten so updated_at cannot drift.
- [2.6] Current watch strategy observable via `WORKBENCH_WATCH` structured log + strategy getter, not sync_state (2.3 Hard Rule forbids adding semantics to the snapshot layer); polling tier probes upward (recursive->tree) each tick, giving automatic recovery to the highest workable tier; `stopPolling` only on successful tier establishment.
- [2.7] "15 verbs" resolved as 13 data verbs + the onEvents subscribe/unsubscribe pair, each on its own whitelisted channel; sender rejection follows the M1 discipline exactly (plain Error + `ERR_IPC_SENDER_REJECTED` log, before the envelope path); all other handler failures reject `WorkbenchIpcError` whose message is the JSON envelope.
- [2.7] Perception orchestration wired per Interface 1 notes: activateProject -> retarget + synchronous rescan (board first paint); updateProject repoint -> rescan + retarget-when-active; removeProject of the active project -> retarget(null); `start()` resumes the persisted active project on boot without touching `last_activated_at`.
- [2.7] Plugin overlay parse-time validation (T5 mitigation): mandatory/unknown/corrupt disabled entries stripped + `ERR_PLUGIN_RUNTIME_STATE` log (manifest state wins); `setPluginEnabled` success path writes only `<userData>/plugin-runtime.json` — manifest bytes asserted unchanged.

### 4. Conventions Established

- Qualified task_key dialect: every task address crossing a layer boundary (IPC verbs, snapshot PK values, session_links, depChain) is `<featureSlug>/<localId>`; blockers inside a row stay verbatim local IDs resolved within that row's feature namespace. Tasks 3.x-6.x must not regress to bare local IDs (collision risk is real: 33 overlapping keys in this repo alone).
- Owned-table write discipline: owned SoT (projects / app_state / session_links) is written exclusively through repos; app_state kv access goes through `readAppStateJson`/`writeAppStateJson`. No hand-written SQL outside the repos layer; structural snapshot deletes live in repos. Raw SQL in tests only where no repo path exists (seeding derived tables, fault injection).
- Derived-table purity: snapshot layer carries no semantics beyond what forge files provide — updatedAt always caller-derived from forge mtimes, missing dialect fields = empty/null (never inferred), corrupt inputs preserved/skipped not fabricated.
- Error contract: structured error classes with `ERR_*` codes; IPC failures reject with the JSON envelope `{code,message,detail?}`; sender rejection precedes the envelope path (M1 discipline); unknown errors -> `ERR_WORKBENCH_DB` + log.
- Channel single-source: `channel-allowlist.ts` is dependency-free and imported by value by both preload and main; preload exposes only per-verb functions, never a generic invoke passthrough. Every new verb = allowlist entry + handler + preload fn.
- DI seam pattern: cross-phase collaborators (plugin guard today) are injected via `createWorkbenchIpcServices` deps at the single assembly point in main/index.ts — later tasks swap implementations, not call sites.
- fs operations only on registered/authorized paths; in the validation chain, authorization always precedes fs probing of the target path.
- Watcher mechanics: fs callbacks only reset the 400ms debounce; scans run in a `setTimeout(0)` macrotask slice; event batches coalesce same-key events to final form in first-seen order.
- Testing patterns: `buildForgeProject` synthetic forge-project fixture builder (workbench-indexer.spec.ts) is the seed for 6.1's generator; fake-clock `advanceAndSlice` (clock must move >=1ms past nested timers) for watcher tests; EXPLAIN QUERY PLAN assertions pin index usage.
- Repo baselines: repo-wide tsc TS5097 (.ts-extension imports) and pre-existing lint findings in untouched e2e files are documented baseline — do not fix incidentally; no fmt recipe exists (oxlint @stylistic is the style gate).

### 5. Deviations from Design

- [2.1] Design schema.sql places `PRAGMA journal_mode`/`foreign_keys` in the DDL; implementation applies them per-connection in `db.ts` (foreign_keys is non-persistent; journal_mode cannot change inside a migration transaction) — declared in the schema-v1.sql header.
- [2.2] SPEC contradiction resolved: task AC said the repo layer writes no snapshot SQL while er-diagram declares engine FK CASCADE for snapshot cleanup — resolved in favor of Reference Files (CASCADE kept; no hand-written snapshot deletes).
- [2.2] `ERR_SESSION_LINK_NOT_FOUND` added beyond the tech-design error table (needed for endSessionLink on unknown id; no design code existed).
- [2.5] task_key stored qualified `<featureSlug>/<localId>` vs design Cross-Layer Data Map / Interface 1 ("forge ID 形如 N.N", key 如 "2.1") — forced by live-dialect cross-feature collisions; record 2.5 locks this dialect for 2.6/2.7/4.2/6.1.
- [2.5] Source determination runs on rewrite only (unchanged rows keep historical source/updatedAt) — design Interface 3 implies per-change determination; unchanged-row stability is the stronger guarantee.
- [2.6] Design's degrade path ("watcher 报错 -> 降级") was implemented as a runtime-probed strategy chain with upward recovery (polling tier re-probes recursive/tree each tick); design did not specify recovery, implementation added it.
- [2.7] Interface 1 lists `onEvents` as one verb; implemented as a subscribe-events/unsubscribe-events pair on separate whitelisted channels (only reading that reconciles the "15 动词" count with AC-4's explicit subscribe/unsubscribe lifecycle); push channel stays off the invokable whitelist.
- [2.7] Task's 4-file module list extended with `services.ts` + `plugins.ts` to honor the handlers-thin Hard Rule (handlers = param validation + service call + error mapping only) — file-list deviation from the task, not the design.
- [2.7] `getTaskDetail` depChain policy concretized beyond design ("拓扑序"): cycles cut, dangling refs skipped, resolution scoped to the feature namespace.
