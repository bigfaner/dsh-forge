### Key Decisions
- Single-active invariant is app-layer transaction discipline (er-diagram note): activateProject runs existence-assert + app_state single-row upsert + projects.last_activated_at stamp inside one BEGIN IMMEDIATE; violation sequences roll back leaving the pointer intact (covered by tests).
- removeProject clears the app_state active pointer (no FK on JSON value) in the same transaction as the projects DELETE; session_links and the three derived snapshot tables are removed by the engine-level FK CASCADE declared in schema v1 — the repo layer issues no snapshot SQL (task-AC snapshot-tables-untouched read as: no hand-written snapshot deletes; SPEC CONTRADICTION vs er-diagram CASCADE resolved in favor of the Reference Files).
- code_root is normalized (resolve + forward slashes + trailing-slash strip, drive roots preserved) inside the repo so UNIQUE(code_root) comparison is reliable across separator variants.
- recordSessionLink semantics = refresh: upsert on the UNIQUE key resets started_at, restores status='active' and clears ended_at with a stable row id — covers both duplicate registration and ended->re-mount (same-session re-attach).
- Added repo-level error code ERR_SESSION_LINK_NOT_FOUND for endSessionLink on an unknown id (no code for this exists in the tech-design IPC error table; IPC-face mapping is a later task).
- Raw SQL in tests only where no repo path exists: seeding derived snapshot tables (indexer is a later task) and fault injection (dangling pointer, CHECK violations), mirroring the task-2.1 spec precedent; owned-table writes in production go exclusively through the repos layer (Hard Rule).
