### 2. Key Decisions

- [3.1] Guard placement in a new `plugin-runtime/` module instead of consolidating into `workbench/ipc/plugins.ts`: host-profile (startup projection domain) needs overlay reads and importing the IPC face from it would invert repos-style layering; `ipc/plugins.ts` delegates overlay I/O to `plugin-runtime/overlay.ts` and re-exports the 2.7 seam contract (`PluginEnableGuard`/`PluginMandatoryError`) so existing import paths stay stable; single write path preserved (`writePluginRuntimeOverlay` the only overlay writer, `setPluginEnabled` its only caller).
- [3.1] Malformed-vs-violating split: structural malformation (bad JSON / non-object root / unknown keys / missing or non-array disabled) -> `ERR_PLUGIN_RUNTIME_STATE` + isolate as `plugin-runtime.json.corrupt-<ts>` (ERR_WORKBENCH_DB backup precedent) + rebuild empty overlay, never blocking startup; schema-valid violations (mandatory names / unknown names / non-string entries) keep the 2.7 strip+log semantics (manifest state wins).
- [3.1] Strict loader accepts only literal `mandatory: true` (absent = third-party); false/other values fail loud (`ERR_PLUGIN_BUNDLES_CONFIG`) rather than half-marking the protected partition.
- [3.1] forge-workbench manifest entry intentionally deferred to 3.2 (its AC owns both the plugin package and the manifest entry); 3.1 lands the mandatory convention on `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app` only — a placeholder name that cannot resolve from the vendored closure would risk host boot.
- [3.1] Overlay consumed by host-profile via optional `deps.overlayPath` (missing/absent = empty overlay = all enabled); main/index.ts passes `<userData>/plugin-runtime.json` — the same file the `setPluginEnabled` verb writes.
- [3.2] Slot names use the spike-1 resolved contract (task AC's 占位名 fallback obsolete): `main` keyed `'workbench'` + `sidebar.panellist` list id `'workbench'` order 10, verbatim ui-plugin-manager precedent; NS `'workbench'`, label thunk via `ctx.locale.bind`.
- [3.2] Host half source at `src/host/` per tech-design layer placement, but the artifact stays `lib/index.js` (the stage-channel contract name).
- [3.2] `@xyflow/react` as a regular dependency (bundled, never a module-table external); react/react-dom stay baseline externals — single React instance via host-profile module resolution, machine-checked by bundle-artifact.spec.ts (external require set ⊆ baseline, no inlined React markers).
- [3.2] `ReactFlowProvider` wraps the board placeholder in the shell (genuine xyflow use today; 5.x views consume `useReactFlow` without own providers); tsdown `define process.env.NODE_ENV="production"` because inlined xyflow branches on it and the browser has no process.
- [3.2] Distribution form = mandatory + tarball-sourced entry in the product config (the ui-plugin-foundation task-6 landed channel); consequences wired same-diff: CI desktop-e2e stages tarballs after build:plugins, desktop-package builds+stages before electron-builder (verify-package asserts embedded tarballs), step-6(a) `--check` means real artifact presence.
- [3.2] AC3 minimal rpc ping interpretation: the shipped host half stays `apply(): void` with zero unimplemented references; the ping verification loads BOTH real artifacts through their real channels — node half as ES module, browser half through a minimal `__ModuleLoader__` whose require answers exactly the module-table baseline (the surface every later client->host exchange rides) — plus live-boot roster evidence.
- [3.2] Pre-existing blocker fixed inline (exposed by first dist rebuild): preload imported channel-allowlist VALUES from main, vite split a shared chunk, and Electron's sandboxed preload cannot require relative chunks -> preload died at load, SPA stalled at `Loading plugins…` (baseline configs too). Fix = preload-local channel-allowlist copy + sync lock (workbench-ipc.spec deep-equal) + `dist/preload.cjs` self-containment assertion. Not a plugin-scaffold regression; e2e could not run without it.
- [3.2] Sidebar icon = upstream `IconBranchOutline16` from ui-primitives (module-table external; jsdom unit tests stub it — the npm node entry carries undeclared transitive deps only the upstream monorepo supplies, the known dsh-client-store quirk family).
- [3.3] Form-identity is structural (Hard Rule): both the slot path and the rail call the SAME `ViewSwitchController` methods over the SAME view-key machine and the SAME persistence projection, and the workbench content is the SAME `WorkbenchShell` component receiving the SAME view face — divergence impossible by construction rather than asserted.
- [3.3] Fallback-rail trigger = grace timer over slot declarations (`RAIL_GRACE_MS`=5s, `ctx.slots.spec` on both nav slots): healthy boots declare during roster assembly and onPathLive clears the timer; expiry without declarations mounts the rail — overlay mode when the plugin owns the surface, chrome-only when the main registration is live but sidebar.panellist is missing (mixed drift); late declarations stand the rail down; a mid-boot main arrival rebuilds an engaged overlay rail as chrome (no zombie surface).
- [3.3] `ctx.layout` consumed OPTIONALLY (`ctx.get`, never the plugin inject array): a hard service dependency would gate this plugin's whole load on ui-layout and kill the fallback rail it exists to guarantee.
- [3.3] Restart restore = carrier attach-time projection: the slot carrier's first `present()` re-selects the persisted panel when the registration commits — no separate restore path; a one-shot restore hold (`armRestoreHold`) re-presents once against the upstream boot session auto-restore (home-scoped session hydration ends in `selectPanel(null)` seconds after ui-ready, which would otherwise defeat AC4 on every real restart); the hold is consumed by the first dismissal so genuine user intent afterwards adopts normally.
- [3.3] External selection sync rides the keyed main slot's mount/unmount lifecycle (mount = presented, unmount = dismissed -> `adoptExternalView` persists without re-presenting, no loop); the rail instead keeps its shell mounted and faded (session-memory retention by construction, the ui-design 切出后保留 clause).

- [3.3] Rail is a plugin-owned React root under a body-appended `display:contents` host with inline styles only — zero stylesheet injection, zero upstream DOM mutation (Hard Rule 防污染); scoped-styles assertion machine-checked in rail.spec.
- [3.3] Live rail boot cannot be forced without removing the upstream bundles (which kills the SPA the rail switches back into), so the rail's automated leg is a real-DOM jsdom mount (`installRailNav` + createRoot) driving the identical machine; the slot path gets the live e2e legs (click + Enter keyboard switch, aria, two-boot restart).

### 4. Conventions Established

- Dual-layer protection invariants: mandatory identity derives only from the product manifest (literal `mandatory: true`); the runtime overlay schema admits third-party names only; `writePluginRuntimeOverlay` is the only writer and `setPluginEnabled` its only caller — tampering with userData cannot remove a mandatory assembly.
- Runtime-state-file failure handling: structural malformation = isolate (`.corrupt-<ts>`) + rebuild empty + `ERR_PLUGIN_RUNTIME_STATE` log, never blocking startup; schema-valid violation = strip + log (manifest state wins). Follows the `ERR_WORKBENCH_DB` corrupt-backup precedent.
- Plugin package shape (cordis dual-half): client half owns all UI (slot registrations + locale + views), host half `apply(): void` with zero unimplemented references until its real faces land; artifact names follow the stage-channel contract (`lib/index.js`) regardless of source layout; package form machine-checked (package-form.spec).
- Slot registration dialect: keyed main slot by key; list slots by id + order (ui-plugin-manager precedent shape); label via `ctx.locale.bind` thunk; NS-level locale with en fallback.
- Single-React discipline: react/react-dom stay module-table baseline externals; plugin-only deps get bundled (with `NODE_ENV=production` define); bundle-artifact.spec machine-checks external require set ⊆ baseline and no inlined React markers.
- Zero shell-code diff for plugin-delivered UI: apps/desktop diffs limited to the resources manifest and e2e tests; fallback UI = plugin-owned React root with inline styles only — zero stylesheet injection, zero upstream DOM mutation.
- Optional-service consumption: upstream host services (layout/slots) are consumed via `ctx.get` (optional), never as hard plugin inject dependencies — a hard dependency would gate plugin load on the host service and kill the fallback the plugin exists to guarantee.
- Form-identity by construction: alternative UI forms of one behavior must call the same controller/machine/persistence projection over the same content component — divergence impossible by construction, not asserted by tests.
- Preload self-containment: the sandboxed preload must not import values from main (vite splits shared chunks Electron's sandbox cannot load) — preload-local copies + deep-equal sync lock.
- Dev workflow: boots of the default config require `pnpm build:plugins && pnpm stage:plugin-tarballs` first (CI wired); `pnpm verify:plugins` is the plugin gate.
- Testing patterns: real-artifact verification through real channels (ES-module node half, minimal `__ModuleLoader__` browser half); scoped v8 coverage over plugin src; e2e localStorage shared across boots within a suite.

### 5. Deviations from Design

- [3.1] Guard placement: design Interface 4 places the guard as a `host-profile 守卫函数` behind the setPluginEnabled verb; implementation places guard + overlay in a new `plugin-runtime/` domain module with host-profile consuming overlay reads via `deps.overlayPath` — layering-driven (the startup projection domain must not import the IPC face); the verb still routes through the single write path, so the design contract (唯一写入口) holds.
- [3.1] Corrupt-overlay recovery added beyond design: Interface 4 specifies only parse-time strip of violating entries (违规条目剔除 + log); implementation adds structural-malformation isolate-and-rebuild (`.corrupt-<ts>` backup + empty overlay rebuilt, startup never blocked) — design did not specify corrupt-file behavior.
- [3.1] Strict literal loader (`ERR_PLUGIN_BUNDLES_CONFIG` on non-literal mandatory values) added beyond design's `条目扩展 "mandatory": true 字段` — prevents half-marked protected partitions.
- [3.2] Host-half artifact name: design Module Layout places the host half at `packages/plugins/forge-workbench/src/host/`; the artifact stays `lib/index.js` per the stage-channel contract (source layout ≠ artifact layout).
- [3.2] Distribution concretized: design says `产品清单新增 forge-workbench 条目(mandatory: true)`; implementation = mandatory + tarball-sourced entry via the ui-plugin-foundation task-6 channel with CI desktop-e2e and desktop-package staging — same manifest semantics, the concrete distribution channel added.
- [3.3] SPEC contradiction resolved: tech-design Integration (壳级导航注入) says `视图切换状态(会话期内存,不持久化)` while task AC4 requires `重启回到上次视图` — resolved in AC's favor (persistence under `dsh.forge.workbench.view`); design body-text drift already flagged by T-review-doc.
- [3.3] Rail automated leg = real-DOM jsdom mount, not live e2e: live rail boot cannot be forced without removing the upstream bundles (which kills the SPA the rail switches back into) — a verification-approach deviation; contract identity is still machine-checked and the slot path carries the live e2e legs.
