## Summary
Implemented the ForgeBridge host-half CLI bridge (tech-design Interface 2): resolveForgeCli resolution chain (设置显式路径 → PATH → structured ERR_FORGE_CLI_UNAVAILABLE with both-stage diagnostics, version evidence via `forge version` — the live CLI has no --version flag), and getTaskPrompt with qualified→local taskKey translation (2.5 dialect `<featureSlug>/<N.N>` → `<N.N>`, hardened against traversal/multi-slash), `^\d+(\.\d+)*$` whitelist, registered-project allowlist gate (fail closed), argument-array spawn with bounded output (stdout/stderr caps) and timeout-with-child-termination. ### Key Decisions
- resolveCli returns a reasonCode union ({available:true,path,version} | {available:false,reasonCode:'ERR_FORGE_CLI_UNAVAILABLE',detail}) — the reasonCode realization of Interface 2's failure comment, mirroring getTaskPrompt's discriminant (host-half services return reasonCode, not IPC envelopes)
- Version probe uses the `forge version` subcommand (verified live: `forge --version` → unknown flag, exit 1) — spike/live-CLI contract supersedes the body-text '版本兼容探测' framing
- All post-resolution failures that yield no prompt (exit≠0, empty/oversized/late output, invalid key, unregistered root) map to ERR_NO_PROMPT with disambiguating detail; only resolution-class failures (resolve/spawn-start) map to ERR_FORGE_CLI_UNAVAILABLE — matches the AC's 'ERR_NO_PROMPT = 任务不存在/CLI 无法产出' semantics under the spec's two-code union
- PATH lookup accepts only directly-spawnable forms (win32: .exe/.com; posix: bare executable): script shims (.cmd/.bat/.ps1) are rejected with shim diagnostics because executing them requires cmd.exe — a shell (T2 Hard Rule); forge ships as a native exe so the real distribution is covered
- Allowlist delivery seam = DSH_FORGE_PROJECT_ROOTS (JSON array of normalized code_roots) + DSH_FORGE_CLI_PATH env vars read lazily per call, fail closed on absent/invalid — workbench projects table stays the single source of truth; shell-side feeding belongs to the wiring task (host-supervisor spawn, DSH_FORGE_PRIMARY_RUNTIME precedent)
- Root comparison folds input through the repos-layer normalization convention (resolve → forward slashes → no trailing slash, mirrored — the plugin cannot import the app) + win32 case folding
- Decorator-bearing rpc class split into forge-bridge-rpc.ts (pure core stays decorator-free in forge-bridge.ts): the workspace test transform (vite 8.3) does not lower standard decorators, while tsc --build does — class/apply tests load the tsc-lowered build output (the suite already gates on built lib/ artifacts)
- tsdown node-half externals predicate made absolute-path-proof (rolldown hands the external callback RESOLVED absolute ids for relative imports — a blanket neverBundle would silently externalize the plugin's own files)
- Stub CLI is an inline temp-dir script executed through the REAL spawner (process.execPath + script via the spawnFn seam): real pipes/close/kill without any real-CLI unit dependency; resolution env is pinned hermetic (empty PATH) so no test can ever reach the machine forge
