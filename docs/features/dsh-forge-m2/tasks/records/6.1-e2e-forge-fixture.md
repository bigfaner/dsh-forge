### Key Decisions
- Win32 stub CLI = a copy of the builtin standalone node.exe renamed forge.exe: the T2 resolver only spawns native executables (.cmd/.bat shims rejected), and node under any filename resolves its MAIN ENTRY against the spawn cwd — version.js in the electron launch cwd (the cwd-less probe inherits the host child cwd), prompt.js/task.js written per project root by stub.attachProject; the subcommand is recovered from the resolved main basename (node consumes it as the entry, argv keeps the literal extensionless spec). POSIX uses a plain shebang script — no cwd cooperation.
- Session-channel stub = env seam DSH_FORGE_SESSION_STUB_DIR inside the plugin host half (cordis provide() throws on duplicate service names, so no in-process stand-in can register beside the web-app sessionController — verified against cordis 4.0.2 source). File protocol: control.json (create/prompt = ok|fail|hang, re-read per call) + journal.jsonl (create rows, prompt rows carrying the composed first user message verbatim = the SC2-2 hash oracle, session-ended markers appended by the test-side markSessionEnded helper).
- Env feed = createHostSpawnEnvFeeder (per-process): refreshes DSH_FORGE_PROJECT_ROOTS from the projects table before every startHost, but a value it did not itself write (an external explicit set, e.g. 5.11 leg B) wins — the test-profile override channel stays intact.
- DSH_FORGE_USER_DATA seam (app.setPath before ready) pins workbench DB + plugin-runtime overlay + the single-instance lock to a per-journey temp dir; launchPluginShell grew cwd/userDataDir options. The workbench journey family (launch/nav/features/overview/tasks) opted in — the shared real userData had accumulated 47 stale fixture project rows (5.14's flag), widening the boot-restore bounce until switchToWorkbench flaked; with isolation the launch pair is 3/3 stable and the whole family is 11/11 green. The 3.2 scaffold overlay legs deliberately keep the real userData (they test that exact path).
- Generator treats taskCount as the EXACT total (phase-gate tails included) via a converging budget allocator (degenerate volumes drop gates rather than miscount); branch/worktree are never generated — the dialect pins them null/false (Hard Rule: do not invent what forge never wrote).
- 6.1 also repaired a latent phase-5 breakage found while validating: 5.11 leg A's dock click targeted the mock-era node key dsh-forge-m2/5.6 which the 5.14/5.15 mock-withdrawal removed (verified failing on stashed baseline code; the 5.gate had verified e2e per family records without re-running).
