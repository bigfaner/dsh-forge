### Key Decisions
- task-status.ts is the contract-stable shared vocabulary: TASK_STATUSES canonical order doubles as view B column order AND status-sort rank; labels carry the precision over the 7->5 StateDot reduction (never color-only)
- Dangling blockers resolve same-feature (2.5 dialect: blockers are local upstream keys) against the FULL task set, never the filtered subset - a filter must not manufacture dangling marks
- StateDot reused from upstream ui-primitives per TECH-ui-reuse-001 (module-table external, zero bundle cost); jsdom specs stub it - the five shell-rendering specs that mount the tasks seat got the stub added
- Hard Rule (switch preserves filters/scroll): filter/sort/collapse state lives in the page above the views; view B horizontal scroll is captured at switch time (effect cleanup would see the next view's DOM) and restored on re-entry; the vertical scroller is the shell's content area, never remounted
- sync error is a toolbar light with a retry that re-loads quietly and keeps the last good board (sync error != view error); the updating state is row highlight + aria-live only, the data merge behind events is 5.15's
- TaskBoardFace seam = getTaskBoard + onEvents (single-subscriber, batched); the mock twin's emit poke is the build-stage event driver
- 500-task scale: view B rides group collapse, view C rides per-row content-visibility progressive rendering (inert in jsdom, effective in Chromium)
