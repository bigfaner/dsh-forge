### Key Decisions
- Layout 布局定形 (task Description's 分层/力导 choice): LAYERED top-down per ui-design 视图 A ('自上而下分层 DAG, blocker 在上') — longest-path layering + 2-down/2-up barycenter sweeps with cycle guard, ~180 lines of pure TS; NO dagre/elk (Hard Rule: 布局算法用 JS 实现, no layout lib enters the bundle).
- ReactFlow's own stylesheet is NOT imported: the client bundle is a CJS closure-factory single artifact (a CSS side-asset would never load) and lib CSS is global. Instead ONE mount-scoped <style> whose every rule is namespaced under .dsh-forge-dag (the canvas root's className) — satisfies the 作用域样式 Hard Rule (防污染上游界面); unmount removes the sheet, so the other views' zero-<style> assertions stay intact.
- Keyboard traversal is a delegated listener on the view container (closest [data-id]) rather than per-node domAttributes: the lib's Node type explicitly omits event handlers from domAttributes, and delegation keeps the memoized node objects untouched (attribute-only rerenders cannot churn them).
- fit-view 仅首载 via the fitView prop (init-time only); the Hard Rule's 切换不重置滚动位置 extends to the DAG's pan/zoom through a settled-viewport stash (onMoveEnd → page ref → defaultViewport on re-entry; no re-fit).
- Default board view flipped to 'tree' per ui-design '(默认)' — the 5.5 placeholder contract (disabled tab + treeHint) retired; the locale key became tasks.tree.canvasLabel (en/zh balanced, treeHint removed).
- jsdom strategy: the real ReactFlow needs d3-zoom + an unguarded ResizeObserver (absent in jsdom), so every board-mounting spec (task-board/shell/chrome/rail/task-dag) mocks '@xyflow/react' at the lib boundary via tests/helpers/xyflow-standin.tsx (nodes as focusable data-id wrappers applying domAttributes + custom node via nodeTypes, edges as placeholders, canvas-props recorder, per-id mount counters) — the real engine rides the e2e lane (StateDot stub precedent).
- proOptions.hideAttribution = true keeps the workbench link-free (consistent with the T3/防注入 posture; xyflow's MIT permits removal) — the license text ships in the plugin's LICENSE.
- Launch entry: the node card RESERVES the hover/:focus-within 28x28 mount point (empty positioned slot, revealed by the scoped stylesheet); 5.10's own docblock assigns the actual SessionLaunchEntry mount to 5.11 — this task does not mount it.
