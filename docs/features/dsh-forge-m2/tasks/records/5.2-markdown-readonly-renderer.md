# Task Record: 5.2 只读 markdown 渲染组件(防内容注入白名单)

## Summary
Implemented MarkdownView, the shared read-only markdown renderer for all workbench prose surfaces (task descriptions, execution records, five feature doc kinds), with a default-deny whitelist security model: marked v18 lexer-only tokenization mapped onto a fixed vocabulary of inert React elements (no HTML string is ever built, dangerouslySetInnerHTML does not exist), raw HTML/script/style/on* payloads degrade to literal text, and a protocol-whitelist URL gate (http/https/mailto after entity-decode + WHATWG parse) renders links as non-navigating labeled text. Long-document path tokenizes once and memoizes per-block chunks (10k-line doc: 1012ms mount / 6ms re-render, recorded in the perf test).

### Key Decisions
- Renderer choice: marked 18.0.13 (zero-dep, plugin-bundled into lib/client.js exactly like the @xyflow precedent — nothing enters the shell/preload, G6) used LEXER-ONLY: markdown -> token tree -> fixed inert React elements; marked.parse is never called so no HTML string exists to sanitize downstream
- Sanitize approach is whitelist-by-construction, not a filter: the token->element map can only produce h1-h6/p/ul/ol/li/blockquote/pre/code/table-family/hr/br/strong/em/span/text; a/img/iframe/script/style/form-controls are unproducible, and unknown token types degrade to text via default-deny arms
- Upstream MarkdownText reuse evaluated and declined: it is a chat-streaming renderer (delegate-mediated links, katex math, file mentions) and the npm-pinned alpha.2 copy tests would exercise differs from the vendored tree that runs — the drift gap would hollow out exactly the injection guarantees this task must prove (decline recorded in the component header)
- Single URL gate resolveDocHref: entity-decode (decimal/hex/named, browser-aligned) -> 2048-char cap -> WHATWG URL parse -> protocol must be http/https/mailto; javascript:/data:/vbscript:/ftp:/relative/scheme-relative/entity-smuggled/case-flipped/tab-smuggled all fail closed; whitelisted links render as span with label + safe URL on title (never an anchor, never navigates away)
- Images are outside the doc subset: image tokens render alt text only — no <img> element, no remote fetch, no onerror face; code blocks render as plain text with no highlight engine (Hard Rule: no execution-capable plugins)
- Perf chunking unit = one memoized block element (MarkdownBlockView over stable token identities from a single useMemo tokenization); virtualization rejected because scroll-container ownership belongs to the 5.7/5.9 consumers
- Test location: tests/markdown.spec.tsx instead of the task note's __tests__ beside-source form — the root vitest include only picks packages/plugins/*/tests/**, so the note's location would never run (5.1 precedent followed)
- Entity display semantics: prose/heading/codespan text entities decode for display (marked pre-decodes codespans); fenced code blocks keep entities literal per CommonMark; the shared decoder also vets hrefs so entity-smuggled schemes are judged post-decode
