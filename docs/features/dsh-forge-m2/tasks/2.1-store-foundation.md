# 2.1: SQLite store 基座：node:sqlite 打开/初始化/schema v1 迁移器 + boot 探针

## Description

在 `apps/desktop/src/main/workbench/` 落地数据内核基座：以 node:sqlite(Electron ^44 内建,零原生重编译)打开 `<userData>/workbench/workbench.db`、执行 schema.sql v1 DDL、维护 schema_version 应用层迁移器,并提供 boot 探针——探针失败必须拒绝启动工作台(ERR_WORKBENCH_DB),禁止静默无库降级。

## Reference Files

- docs/features/dsh-forge-m2/design/tech-design.md — §Architecture Layer Placement(`apps/desktop/src/main/workbench/`)、§Data Models(`<userData>/workbench/workbench.db` 分区)、### Error Types & Codes(ERR_WORKBENCH_DB、损坏库 backup-rebuild)
- docs/features/dsh-forge-m2/design/schema.sql — 全部 DDL(6 表 + 5 索引 + 行级 CHECK + PRAGMA WAL/foreign_keys)
- docs/features/dsh-forge-m2/design/er-diagram.md — 实体与索引设计依据

## Acceptance Criteria

- [ ] `openDatabase(userData)` 建库/开库成功,PRAGMA journal_mode=WAL、foreign_keys=ON 生效。
- [ ] schema.sql 全部 CREATE TABLE(6 表)一次执行无错误,所有 FK 引用可解析,5 个索引全部建立(含行级 CHECK 约束生效验证:违反 CHECK 的写入被拒)。
- [ ] schema_version 迁移器:首次建库写入 v1;重复启动为 no-op;版本号单调,预留 v2 挂载点。
- [ ] boot 探针:node:sqlite 不可用/开库失败时返回结构化 ERR_WORKBENCH_DB 并阻断工作台启动,不落任何静默降级路径。
- [ ] 损坏库路径:检测损坏 → 备份原文件 → 重建空库(自有 SoT 之外仅快照,可接受重建),错误上报含备份路径。
- [ ] vitest 单测覆盖:全新建库、重复启动幂等、CHECK 拒写、探针失败路径。

## User Stories

- No direct user story mapping.(内核基座,间接支撑 Story1/Story3 的快照读)

## Hard Rules

- 禁止引入原生依赖(better-sqlite3 等);node:sqlite 之外零新增依赖。
- 快照表与自有表分区注释必须保留(SoT 纪律:派生表可 DROP 重建,自有表绝不)。

## Implementation Notes

- 文件清单:`apps/desktop/src/main/workbench/store/db.ts`(open/probe)、`store/migrate.ts`(schema_version 迁移器)、`store/schema-v1.sql`(自 design/schema.sql 投影,build 步骤或内联常量二选一并在注释声明来源)。
- schema 任务义务(db-schema 规则):AC 2 即「DDL executes without error / All FK references resolve / Indexes created」三义务的合并表述。
- 设计偏离说明:6 实体合为单任务——全部为全新 CREATE、单一 v1 迁移、无 ALTER 演进,按实体拆分无独立验证语境;后续演进表结构时按 db-schema 规则逐实体拆。
- 复杂度 high 判定依据:AC=6。
