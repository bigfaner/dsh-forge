# 2.4: 任务域派发动词 claimTask + submitTask（守卫/就绪选择/幂等重入/恢复钩子/事件）

## Description

`forge/tasks/` 派发对偶动词：claimTask（依赖守卫 + 就绪选择 + links + 幂等重入 + dispatchPrompt 合成）与 submitTask（转移 + record + 恢复钩子 + 相位重算）。写后事件 emitTasksChanged 接入 tasks 域全部写动词闭包尾部（四域覆盖面裁决的 tasks 侧）。

- docs/features/dsh-forge-m2-pipeline/design/tech-design.md — Interface 1 claimTask/submitTask 签名（含 no-ready 出口与并发重入域） (ref: Interface 1: `ctx.forgeTasks`（任务域）)
- docs/features/dsh-forge-m2-pipeline/design/tech-design.md — 交互一派发链时序（含 fix 链与中断恢复） (ref: 交互一：派发链（SC-M2 门，含 fix 链与中断恢复）)
- docs/features/dsh-forge-m2-pipeline/design/tech-design.md — 交互二写后事件链（emitTasksChanged → process.send） (ref: 交互二：惰性首开 + 事件推送（§7-11/12 裁决落地）)

## Acceptance Criteria

- [ ] claimTask 守卫：依赖全 ∈ {completed, skipped}（未满足 ERR_DEPENDENCIES_UNMET data 带清单）+ 就绪选择（分支延续优先 → priority → 创建序）；claim record 存 digest
- [ ] links upsert-ignore（claim = 唯一写源）+ in_progress 幂等重入（reclaimed=true + 简报重合成 digest 新值）；无 taskRef 的盲选不领 in_progress（双 dispatcher 并发不双派发）
- [ ] 无就绪任务出口 `{ task: null, dispatchPrompt: '', digest: '', reclaimed: false }`（Z1 出口信号——run-tasks 循环等待/收工判据）
- [ ] submitTask：success（转移 + record files/gate/commit + ERR_SUMMARY_REQUIRED）与 blocked（reason 必带 ERR_REASON_REQUIRED → fix 链）
- [ ] 恢复钩子：`idx_edges_prerequisite` 反查，前置**全**满足才 auto-restore（边不删）+ 相位重算
- [ ] emitTasksChanged(projectId) 接入 tasks 域一切写动词闭包尾部（同通道同载荷 {projectId}）

## User Stories

- Story 2: 派发链 dogfood
- Story 3: fix 链自动恢复（blocked → 恢复钩子）
- Story 4: 中断幂等重入（reclaimed + digest 新值）

## Hard Rules

- 就绪选择仅扫 pending 池；单事务全成全败；prepared statements。
- 事件发射经 store 事件底座（1.2）——process.send 防护发送，direct 形态缺席静默。
