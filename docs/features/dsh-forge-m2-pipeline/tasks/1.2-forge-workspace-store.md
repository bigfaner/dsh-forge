# 1.2: ForgeWorkspaceStore：工作区 schema v1 迁移 + 惰性多句柄生命周期

## Description

core 新增 `forge/workspace/` 模块（共享基建）：ForgeWorkspaceStore 按工作区 lazily open + migrate + 结构健全性检查；工作区 schema v1 迁移序列（`design/schema.sql` 全量 DDL：七域表 + schema_meta + app_key_logs 基建表 + 索引 ×6 + append-only 双触发器 + CHECK 全集）；库缺席补建分支；失败 = 工作区隔离（不抛断用户流程）；事件发射器底座与 store.dispose。中央 state.db 零改动。

## Acceptance Criteria

- [ ] schema.sql ↔ MIGRATIONS 逐条 pin（G1-12）；DDL 干净执行、所有 FK 引用解析、索引建立；append-only 双触发器拒绝 UPDATE/DELETE（B.5 触发器 ABORT 锚）
- [ ] ensureOpen 惰性链：openDatabase（参数化传入迁移序列）→ 版本门（FORGE_DB_SCHEMA_VERSION=1 独立版本线）→ 单事务/版本迁移 → 结构健全性检查（版本 + `PRAGMA foreign_key_check` + 表在场，恒轻量，不开库全库派生复检）
- [ ] 库文件缺席 → 新建 v1（P1 存量工作区升级 M2 首次触达补建；预留发现面扫描协作者挂点，由 1.3 实现）
- [ ] 开库/迁移失败 → ERR_WORKSPACE_DB_UNAVAILABLE + 工作区 app_key_logs 记账（scope: tasks|workspace——中央 ck_akl_scope 四值不含，写中央必炸 CHECK）+ 该工作区隔离，其余库照常
- [ ] 事件发射器底座（emitTasksChanged(projectId) 挂点）+ store.dispose（进程内常驻句柄统一关闭）
- [ ] 单测：临时 SQLite 夹具（db.test.ts 形制）覆盖迁移/版本门/隔离/补建四路径

## User Stories

No direct user story mapping。（数据基座；Story 1–7 的持久层由此承载。）

## Hard Rules

- 一律 prepared statements；FK 不带 ON DELETE。
- openDatabase 参数化传入工作区迁移序列——中央 state.db MIGRATIONS 硬编码 import 勿照抄。
- 中央 state.db schema 零改动；app_key_logs 为工作区库基建表（豁免 updated_at）。

## Implementation Notes

- 新建目录 `packages/core/src/forge/workspace/`：`store.ts`（句柄表 + ensureOpen + dispose）、`migrations.ts`（v1 序列）、`events.ts`（发射器）、`app-key-logs.ts`（工作区记账）+ `.test.ts`。
- 保留字清剿与全表 updated_at 按 schema.sql 定稿落列（task_key/task_type 等保留字禁用）。
- dispose 接入插件 disposer 的 host 侧收口在 3.4。
