# 1.1: contracts 扩池：forge 四域 DTO / 通道常量五族 / 15 错误码 / 词汇标签 / 桥事件信封

## Description

`packages/contracts` 扩池 M2 契约面（纯类型与常量，零逻辑零依赖——P1 铁律沿袭）：forge 四域 DTO 与方法签名类型（`ctx.forgeTasks` / `ctx.forgeFeatures` / `ctx.forgeProposals` / `ctx.forgeDocs` + `forgeProjects` 扩展 `deriveTaskStoreDir`）、通道常量五族（`forge:tasks|features|proposals|docs/*` + `forge:projects/deriveTaskStoreDir` + `forge:events/tasks-changed`）、`errors.ts` 扩池 15 新码、TaskType 20 值 + TaskStatus 七态 / FeatureStatus 六态 / ProposalStatus 五态中英标签常量、XML 标签集四枚常量、`BridgeEventMessage` 信封形状。共享类型唯一源，防 schema 漂移。

- [ ] forge 四域 DTO 与输入/输出类型按 Interface 1–5 逐项落地；TaskSnapshot/TaskCard/TaskDetail 恒含 `{ taskId, slug, localId }`（身份双轨：taskId 代理主键锚 + TaskRef 自然键）

## Hard Rules

- 契约层只描述形状不实现业务——禁止引入函数逻辑或运行时依赖（P1 铁律）。
- 通道/DTO 变更 = 三处一体（contracts → web/rpc → host ipc），禁单侧私改。

## Implementation Notes

- 仅修改/新增：`packages/contracts/src/{channels.ts, errors.ts, index.ts}` + 新 `dto/forge.ts`、`labels.ts`、`xml-tags.ts` 及对应 `.test.ts`；不触及其它包。
- 身份双轨落点（Interface 1「身份解析约定」）：agent 面输入 = `slug` + `local_id` 两显式参；UI/RPC 面 = `taskId`；dispatchPrompt TASK_ID 与界面展示 = `slug/localId`。
- 错误码 data 载荷：ERR_DEPENDENCIES_UNMET（未满足清单）、ERR_CYCLE_DETECTED（完整环路径）、ERR_SUSPECTED_MOVE（手工指引）。
