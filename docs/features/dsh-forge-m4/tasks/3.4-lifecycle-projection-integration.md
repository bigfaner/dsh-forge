# 3.4: 生命周期×投影集成:注册 push/改名 rename/删除 delete+FK/归档不动 + 偏差对账链路 + 派发会话归组验证

## Description

投影全链集成(1.3 hook × 3.1/3.2/3.3):registerProject 成功 → 期望 push(ensure);renameProject → rename op;removeProject → 语义扩展(投影 delete + FK cascade + 拆出窗关闭注记——窗口关闭由 4.2 hook 承接);archiveProject/restoreProject → 零投影 op(workspace 保留);偏差链路 = dsh 侧手改 → follow 快照 → diff → deviation 提示;会话归组验证 = 派发会话 cwd=anchor 经原生 canonical 匹配自动归组(DF002 零代码,e2e 验证口径)。

## Acceptance Criteria

- [ ] 四操作投影集成:注册 → ensure push(同名同序:sort_order = forge 侧顺序权威);改名 → rename 同步;归档/恢复 → 零 op(workspace 保留,会话仍按项目分组);删除 → delete op + 项目条目 FK cascade(布局记忆/期望快照随之清除)。
- [ ] 降级不阻断:投影写失败(注入)→ 注册/改名/归档本地生效不被阻断;degraded 状态 + plan 保留;恢复后 retryProjection 成功即两侧一致。
- [ ] 偏差链路:dsh 侧手工改名/删除/乱序 → follow 快照上报 → diff → deviation 状态 + DeviationRow 明细;不回流(零反向写断言)。
- [ ] 派发会话归组:cwd=anchor 的会话在 dsh 原生 UI 归组到对应 workspace(DF002 原生承载,零 forge 代码;本任务以集成测试桩验证)。
- [ ] dsh 侧删除重建:workspace 消失后 ensure 按 path 复连(workspace_id 更新)。
- [ ] vitest:四操作集成矩阵(mock relay)/降级不阻断/偏差三分类/复连。

## User Stories

- Story 4: 注册即归组(SC3 数据面全链)
- Story 5: 归档不丢历史、改名不丢归档(SC3 生命周期全链)

## Hard Rules

- 单向投影:任何路径不得写 dsh 侧数据经 forge 直写;偏差仅呈现(BIZ-006)。
- 归档 ≠ 删除:archive 不得触发 workspace 删除/移除。
