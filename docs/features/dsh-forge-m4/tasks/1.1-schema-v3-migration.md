# 1.1: schema v3 迁移段:store MIGRATIONS {version:3}(projects ALTER ×10 + 2 新表 + 2 索引 + TS 回填)+ 漂移对账

## Description

## Acceptance Criteria

- [ ] v3 段在自有事务内顺序执行:ALTER ×10 + 2 张 CREATE TABLE 一次成功,所有 FK 引用可解析(CASCADE),idx_projects_code_root_key(UNIQUE)与 idx_projects_sort_order 建立。
- [ ] TS 回填(v3 事务内,失败不阻断):code_root_key/identity ← 归一化管线 best-effort(失败 → 字符串回退 + identity_verified=0);in_repo→'repo-existing'、external→'custom'(授权在案)/'app';sort_order ← created_at 序;存量 projection_state='pending';折叠键碰撞 = 迁移失败显式暴露。
- [ ] 版本纪律:schema_version 单行只进不退;v2 库升级到 v3 幂等重跑 no-op;库版本 > 已知迁移即拒开(ERR_WORKBENCH_DB)。
- [ ] CHECK 生效验证:docs_placement 5 值、projection_state 4 值违规写入均被拒。
- [ ] M2/M3 既有表与数据零破坏(升级路径:v2 库迁移后 v1/v2 表内容原样)。
- [ ] vitest 覆盖:全新建库(v1+v2+v3)、v2→v3 升级、幂等重跑、CHECK 拒写、回填矩阵、拒新库。

- 文件清单:`apps/desktop/src/main/workbench/store/migrate.ts`(追加 v3 段 + TS 回填)、`store/schema-v3.ts`(新,内联常量,头注声明来源 = design/schema.sql 投影)、`store/workbench-store.spec.ts`(追加漂移对账与升级用例)。
