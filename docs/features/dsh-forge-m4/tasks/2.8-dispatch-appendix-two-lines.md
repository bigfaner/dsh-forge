# 2.8: 派发追加行两行化(内核 presynth:归因行 + 命名行;prompt_hash 口径不变;e2e 断言口径两行化)

## Description

Interface 7(Story 7 命名约定):内核 `workbench/dispatch/presynth/` 追加行由一行扩展为两行——`appendix = ${attributionLine}\n${namingLine}`;namingLine =「执行本任务时,你 spawn 的 subagent 会话须以『<taskKey> <title>』命名」。prompt_hash 口径不变 = sha256(预合成内容 + 追加行全文);追加行不在 Go 对拍集内,模板基线零影响;M4 specs 断言口径由「恰好一行」更新为「恰好两行 + 逐行前缀对拍」。

## Acceptance Criteria

- [ ] 追加行两行化:归因行(既有) + 命名行(新);命名行文案含 taskKey + title;全部派发模式(标准/PTC/极简)一致。
- [ ] prompt_hash 口径:sha256(预合成内容 + 追加行全文)留档可审计;dispatch 表关联字段不变。
- [ ] 追加行不在 Go 对拍集内(forge-cli 模板基线零影响;`Z:\project\ai\forge\forge-cli` 对拍面零改动)。
- [ ] M4 specs 断言口径更新:「恰好两行 + 逐行前缀对拍」(既有「恰好一行」断言同步改写,全绿)。
- [ ] vitest:两行结构/哈希口径/多模式一致性。
