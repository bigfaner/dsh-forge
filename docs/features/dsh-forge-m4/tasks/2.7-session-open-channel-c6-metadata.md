# 2.7: 会话打开通道 openSessionTarget(顶层/SubagentAddress/旁置)+ C6 元数据条(会话域槽注入,bound/ambiguous/unbound)

## Description

Interface 6 会话打开通道(C2/C5 消费):`openSessionTarget(SessionId | SubagentAddress)` —— 顶层走 `ctx.uiWorkspace.openSession(sessionId)`(session-handover 既有缝,唯一写路径);subagent 走同 API 原生收参 SubagentAddress;旁置走 `ctx.sidebarRight.openResource(subagentChatAddress(address), { preferNewPane: true })`(ui-subagent 先例)。C6 元数据条:上游 `conversation.session` 会话域槽注入(仅 subagent 实例,头部下方 h40 条:r12/bg-layer-2,任务号+标题+状态 Pill + 「查看任务」ghost 双向跳转)。

## Acceptance Criteria

- [ ] openSessionTarget 三通路:顶层 = ctx.uiWorkspace.openSession(sessionId);subagent = openSession(SubagentAddress)(mode 取上游 SubagentListEntry.mode);旁置 = sidebarRight.openResource(subagentChatAddress, preferNewPane);M1 sessionFocus 主进程通道 = 冻结 fallback 保留,不参与 M4 链路。
- [ ] C6 元数据条注入:仅 subagent 实例呈现(会话域槽,座位形态任务期核对);h40/r12/bg-layer-2;左「⟂ task <key> — <title> / <status>」Pill + 右「查看任务」ghost。
- [ ] 三态:bound(血缘命中唯一任务 → 全量)/ ambiguous(多任务共会话 → 「该会话执行中」次文字)/ unbound(普通 subagent 不渲染)。
- [ ] 双向互通:点击元数据条/查看任务 → 打开任务详情(C5 dock)。
- [ ] 命名与血缘冲突时以血缘为准展示(静默矫正);注入不得破坏原生会话视图功能(零侵入)。
- [ ] vitest + jsdom:三通路分发(mock ctx)/三态渲染/双向跳转。

## User Stories

- Story 2: 从任务直达执行会话(subagent 会话视图展示任务元数据)
- Story 7: 执行 agent 的任务身份可见(会话侧反向识别)

## Hard Rules

- 零侵入:注入经槽位体系声明合并;不得包装/重挂载原生 ConversationPanel。
- 血缘为权威,命名仅辅助(Story 7-3)。
