## Phase 3 — Blindspot 猎查（rubric 之外）

1. **[blindspot] 自动发送的会话就绪竞态。** Step 4/4c/5 断言「新会话模式 + 自动发送消息体」——创建、切模式、消息落账为异步链，若无「消息体完整出现且输入框清空/会话转录含全文」的终态等待口径，断言可能打在中间态（消息已发、座位未切）。4c 为 toast 窗口补了竞态口径，但发送后的就绪口径三步均缺。这是 gen-test-scripts 阶段最常见的 flake 源。
2. **[blindspot] 依赖环夹具的「传染范围」未声明。** Setup 依赖环夹具使工具栏「诊断」恒红——但同一 feature 容器的其他步骤（Step 3 打开新会话、5d 查看任务行）也在该容器语境下执行。子图违规是否影响「打开新会话」预填（文档清单读盘）或任务列表渲染，文档未声明；若校验红字横幅常驻容器头部，Step 3 的「草稿逐行内容」断言可能被遮挡。建议声明夹具的作用域（仅诊断 toast）。
3. **[blindspot] 4c 与 4 的「发送给 agent」按钮同文体双源。** 两路失败 toast 都有「发送给 agent」，4 的按钮在工具栏诊断 toast（锚定诊断按钮左侧）、4c 在详情动作区 toast（锚定详情按钮左侧）——定位器相近，e2e 若以文本定位将撞车；文档已分锚点描述，但未提示用例须以锚定路径区分。轻，但值得一句执行注记。
