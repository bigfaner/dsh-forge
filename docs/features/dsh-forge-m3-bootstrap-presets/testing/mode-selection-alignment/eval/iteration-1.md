1. **[blindspot] 2c 的实现证伪风险未被对冲。** 「blank 期点选后、首回合前重启 → 按已选投影重建」是推断补白（S5-7 实证的是**已确立**会话重启；blank 已选未锁态无直接实证）。若平台实现为「重启回退 registry 默认」，2c 将红灯且无降级判据。建议补一句对冲口径：若实测回退默认，该差异应记为平台行为缺陷上报而非用例失败——否则该步在回归池中是永久 flake 候选。
2. **[blindspot] Step 5 守卫的触发粒度含混。** 「打开此远征 feature 的内容**并继续其任务工作（如经任务子 tab 该 feature 容器的「派发」入口）」——守卫（mode chip 对照 + 派发入口提示）在「打开内容」即呈现还是在「点派发」才呈现，两读皆通。AC4 语义 + UF-1 第 7 条（「打开异模式内容时 mode chip 对照呈现」）指向前者，但「派发入口提示」的触发时点未分陈。下游用例会随机择一。
3. **[blindspot] 1c 与 1b 的夹具串扰。** 1b 要求开关缺席/关闭 + 既有会话在场；1c 要求先关再开并验证「关闭期间新建会话无座位」。若 1c 在 1b 之后执行，1b 的「开关关闭」态正好是 1c 的起点——文档未声明边况执行顺序约束，1b→1c 串联时 1b 的「重开」会把状态留给后续步骤；孤立执行则互不干扰。契约生成者需要知道这两步是否共享状态机。
