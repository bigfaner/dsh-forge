## Acceptance Criteria

- [ ] 视图下拉：当前视图直出 + ▾、选项 列表|DAG|泳道（当前项 ✓）、外点关闭——M2 三视图语义不变（切换保持过滤/排序态）
- [ ] DiagToast：锚定触发按钮左侧；成功「子图健康 ✓」1s / 失败 5s 双档；失败档 = 标题 + 五类检查逐项（✗ 含任务键）+「发送给 agent」；任务失败档 = 状态 + 原因 + 最近记录 ≤3 + 任务键——重跑即重现零陈旧滞留
- [ ] 派发按钮：nonTerminalOf 终态判定纯函数（未终态 = pending/in_progress/blocked/suspended——与相位推导机口径同源）→ 存在未终态亮起（与其它按钮同款式——v24）/ 全终态置灰（深灰实底 --dsw-fg-2 填充 + tooltip「全部任务已处于终态——无可派发任务」）
- [ ] 双路由点击：执行中任务在场 → 跳转其最新派发挂接会话（taskDetail/sessionLinks 双源；不新建不重发不切模式——「按 id 打开」缝经 4.1，OQ#1 兜底届时裁决）；否则 openSessionWithPreset（容器对应模式：feature→远征 / 突击提案→突击）+ autosend `/run-tasks <容器标识>` 单行
- [ ] 容器 pill 双轨数据模型：features ∪ 有任务提案（taskCount > 0 判据——2.3 单查询）+ 突击容器琥珀点 +「突击提案」标记 +「无 feature 阶段」计数注 + 突击容器无「诊断」按钮
- [ ] 组件测试：终态判定纯函数全态 + 双路由分支 + toast 双档计时 + 视图下拉 + pill 双轨（含零任务提案不在列断言）
