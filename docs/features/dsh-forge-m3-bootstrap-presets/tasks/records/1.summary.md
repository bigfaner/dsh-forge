### 4. Conventions Established

- **下游机械对齐承载规则（M2 1.1 先例第二次适用）**：破坏性契约/schema 变更若致全仓编译或测试红，须随当任务承载最小零行为变更对齐（Hard Rule 三处一体优先于 Implementation Notes 文件清单）；vitest 面（含 e2e-support）夹具必须随改，Playwright spec 归 5.3 台账。
- **fail-loud 垫片形制**：未接线新面（setProposalMode/listProposalDocs/proposal 容器写径）落显式 throw 垫片 + 测试 pin + 源码注释任务号锚定承接方——后续阶段勿误当已实现，也勿重复发明。
- **lossless 契约纪律**：契约面落终态形状一次到位；值未就绪（schema 列未到场）时键缺席而非显式 undefined——显式 undefined 拒工具输出面。
- **v1 直改零迁移纪律**：FORGE_DB_SCHEMA_VERSION=1 不变 + 单版本序列原地重写 + 存量库废弃手工删除；schema 漂移防护 = migrations.test.ts ↔ design/schema.sql 机械 diff 逐条 pin（十表/七索引/四触发器）。
- **校验锚单点形制**：写入校验（resolveTaskContainer）与相位守卫（resolvePhaseGuardFeature）各落单点、多动词共用——服务不变量不散落复制。
- **垫片语义边界口径**：feature 容器 = M2 语义等价特例（source 解析后全径不变·零行为变更）；proposal 容器 = fail-loud 至 2.4——「最小垫片」评审以零行为变更为准绳。
- **注释措辞规避字面量块注释终止序列**：test-gen-*/ 等通配形态写进块注释会提前终止注释（TS1127 假语法错）——注释中改写措辞。
- **承接面注记形制**（沿 M2）：记录 Notes 与源码注释以任务号锚定承接方（2.2/2.3/2.4/2.5/3.4/3.8/4.1/4.2/5.1/5.2/5.3），后续阶段按号对账。

### 5. Deviations from Design

- **[1.1] 下游对齐承载者偏离任务书分工**（任务分解偏离，tech-design 语义零偏离）：任务书 1.1 Test Impact 言「下游签名编译面由 1.2 垫片对齐」；实际 1.1 承载 core 六文件垫片 + plugin 工具映射 + host 透传名 + web ui-state 三码（动机 = submit 质量门全仓 build+vitest——1.1 留红则自身无法提交且 1.2 无法兑现全仓绿）；1.2 相应收窄为 schema/store/pin + core 消费面 reconcile。Interface 1/2/4/6 落地语义与设计一致。
- **[1.1] 工具名映射表 = 骨架（仅 forge 面两动词）** vs G1-20「收窄矩阵常量 + 工具名映射表」：逐工具名 pin 延至 5.1 按当期上游工具面枚举核对（OQ#2 既定开口——设计已预留实施期核对，记账防误读为缺席）；族级语义（四族 exhaustive 分割 20 值 + 4×6 矩阵逐格 + 全局拒绝集）本任务已全量。
- **[1.2] e2e/support/replay vitest 夹具对齐超出 Hard Rule 文件清单**（全仓绿优先先例第二次适用）；Playwright m2 五 spec 夹具不动 → 5.3 台账存量库废弃重录——任务 Test Impact 既定，非偏离，记账防返潮。
- **语义分阶段注记（防误读为偏离）**：proposal 容器双轨 1.1/1.2 为 fail-loud → 2.4 写径兑现；setProposalMode/listProposalDocs 垫片 → 2.2/2.3 语义；三新通道常量在场而 host 未注册（m2-wiring pin interim 真相）→ 3.8。终态形状 = tech-design Interface 1/4，无偏离。
