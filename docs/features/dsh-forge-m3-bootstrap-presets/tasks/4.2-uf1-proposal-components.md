## Acceptance Criteria

- [ ] ModeChip 三态：远征（蓝点+「远征」）/ 突击（琥珀点+「突击」）/ 未标记（中性不可点 + 悬停「扫描吸收的旧提案无溯源」）；有溯源可点 = 模式更改对话框快捷入口（同 ⋯ 菜单唯一正门不分叉）
- [ ] ProposalVerdictDialog：目标态仅列五态机允许集（allowedTransitions 服务端同源纯函数）+ reason 必填（空因拒绝留场）+ accepted 分叉文案（远征 → 将单步成链建 feature / 突击 → 直接进入任务阶段·无 feature）
- [ ] ProposalModeDialog：远征⇄突击二选 + 变更说明必填 + 「既有任务按创建时模式照旧执行」一行明示
- [ ] 五态 chips 行：draft/under-review/accepted/rejected/superseded 中文标签 + 计数；0 计数 disabled、多选并集、子 tab 切换清空（机制沿 M2 七态 chips）
- [ ] 组件测试：三组件全态渲染 + 对话框校验路径（空因/允许集/分叉文案）+ chips 过滤行为

## User Stories

- Story 4: 提案评审流转与 mode 人工升降级

## Hard Rules

- 对话框 = 官方 Modal 形制 + 目标态允许集 + reason 必带 + 空因拒绝留场（M2 转移对话框语义沿袭）。

## Implementation Notes

- 新建 `apps/web/src/components/ModeChip.tsx` + `apps/web/src/views/overview/proposal-tab/` 下 {ProposalVerdictDialog.tsx, ProposalModeDialog.tsx, StatusChips 行组件} + .test.tsx。
- 数据绑定：mode chip ↔ proposals.mode（null = 未标记）；裁决对话框提交 → forge:proposals/transition（4.1 通道）；模式对话框 → forge:proposals/setMode。
