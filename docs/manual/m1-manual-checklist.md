# M1 三平台手检清单(SC1 / SC2 / SC4 / SC5 / SC8 / SC9)

> 来源:[PRD Success Criteria](../features/dsh-forge-m1/prd/prd-spec.md#success-criteriav1-验收) · [tech-design Testing Strategy](../features/dsh-forge-m1/design/tech-design.md#testing-strategy)
> 范围:SC1(干净机器零终端)、SC2(离线自足)、SC4(系统通知)、SC5(托盘驻留)、SC8(多装共存)、SC9(宿主崩溃恢复)。SC3/SC6/SC7 由 e2e/脚本覆盖(见 `apps/desktop/e2e/`),不在本清单。
> 录屏与归档要求见 [m1-recording-archive.md](./m1-recording-archive.md) —— **每一条 SC 在每平台执行时必须全程录屏**。

## 0. 公共约定

- **被测产物**(GitHub Releases,免签名,4 资产;本地构建等价物见 `apps/desktop/build/electron-builder.config.mjs`):
  - Windows:`dsh-forge-0.1.0-win-x64.exe`(NSIS,oneClick=false,可选安装目录)
  - macOS:`dsh-forge-0.1.0-mac-arm64.dmg` / `dsh-forge-0.1.0-mac-x64.dmg`
  - Linux:`dsh-forge-0.1.0-linux-x64.AppImage`
- **应用标识**:产品名 `dsh-forge`,版本 `0.1.0`;独立 profile 目录 = `<userData>/host-profile`(环境变量 `DSH_FORGE_PROFILE_DIR` 可覆盖);产品数据共享 `$DSH_HOME`(缺省 `~/.dsh`,与 CLI/官方桌面同源)。
- **强杀宿主子进程命令**(SC9 用):
  - Windows:`taskkill /F /PID <宿主pid>`(宿主 = 内置 node.exe 运行 `desktop-host` entry 的子进程)
  - macOS:`kill -9 <pid>`
  - Linux:`kill -9 <pid>`
- 宿主 PID 获取:进程树中壳主进程 `dsh-forge(.exe)` 的唯一 `node` 子进程(空闲稳态自有进程 = 2,SC3 语义)。
- 每条检查项执行后在录屏口述结论,归档时填写结果列(PASS/FAIL + 备注)。

## 1. SC1 干净机器验证

**定义**(PRD):三平台各 1 台无 Node/git/pnpm 机器,下载→安装→启动(允许平台安全机制一次性引导;零终端)→应用内 API key 配置→真实会话(shell 工具 ≥1 次成功 + 审批 ≥1 次完成)。

**前置**:干净机器(见 [录屏归档文档 §干净机器准备](./m1-recording-archive.md#2-干净机器准备));断网可有网,离线路径由 SC2 覆盖。

### 1.1 通用步骤(三平台逐条)

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 在干净机器浏览器打开 Releases 页,下载对应平台安装包 | 下载完成,无终端参与 |
| 2 | 安装 | 平台各见下表;全程零终端命令 |
| 3 | 双击启动 | 主窗口载入上游会话 GUI(`dsh-app://` 承载),无白屏 |
| 4 | 应用内完成 API key 配置(继承上游配置流) | 配置持久化到 `$DSH_HOME` |
| 5 | 选择/创建 workspace,发起会话 | 会话正常往返 |
| 6 | 让会话执行一次 shell 工具(如 `ls`/`dir`) | shell 工具执行成功 ≥1 次 |
| 7 | 触发一次审批(approval)并批准 | 审批呈现并完成 ≥1 次 |

### 1.2 平台差异项

| 平台 | 安装步骤 | 预期 |
|------|---------|------|
| **Windows** | 双击 `dsh-forge-0.1.0-win-x64.exe` → NSIS 向导(非 oneClick,可选安装目录)→ 安装 → 开始菜单/桌面启动 `dsh-forge` | SmartScreen 免签名提示出现属预期(一次性「仍要运行」引导);安装零网络下载(NSIS `differentialPackage=false`) |
| **macOS** | 挂载 dmg → 拖入 Applications → 首次启动 Gatekeeper 提示(免签名,一次性右键-打开引导)→ 启动 | Gatekeeper 一次性引导后正常启动;无终端(`xattr` 等 CLI 属 FAIL 路径,不得使用) |
| **Linux** | `chmod +x` 属终端命令 —— **AppImage 双击路径**:文件管理器 Properties → Permissions → 勾选 "Allow executing as program"(GUI 操作,不算终端)→ 双击 | AppImage 直接运行;若桌面环境无 GUI 授权手段,记录该平台实际采用的一次性引导方式并在结果中备注 |

**PASS 判定**:三平台各完成 1.1 全部 7 步,全程终端命令 = 0(录屏中不可出现终端窗口),shell 工具 ≥1 次成功、审批 ≥1 次完成。

## 2. SC2 离线自足

**定义**:断网可安装与首启;更新检测失败不阻断启动、不弹错。

**实现口径**(任务 4.3/6.2):更新检测启动时访问 GH Releases atom feed,15s 超时;失败/离线 → 状态 `unavailable` + `ERR_UPDATE_FEED_UNREACHABLE` 仅写主进程 log,无任何 UI,不阻断启动。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 干净机器**断网**(物理断开/关 Wi-Fi)后执行 SC1 全流程(下载步骤可提前在有网机器完成并 U 盘拷贝) | 断网下安装与首启 100% 成功,全程不下载任何运行时组件 |
| 2 | 首启后观察 60 秒 | 无更新失败弹窗/横幅/错误对话框;应用正常进入会话就绪态 |
| 3 | (可选加分)断网下杀宿主/重启应用复验 | 行为与有网一致(SC9 流程不受影响) |

**PASS 判定**:三平台各 1 次断网安装+首启成功,且首启后 60 秒内无任何更新检测错误 UI。

## 3. SC4 系统通知

**定义**:「等待用户输入」「回合完成」两类状态三平台各触发 ≥1 次,点击聚焦对应会话。

**实现口径**(任务 4.5/4.6):通知点击 → 前置主窗口 + `focusSession()`;session-focus 落地为 fallback(恒 false)→ 显示 toast「请手动切换到会话 X」(6s 自动消失)。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 发起一个会话,触发审批或 user-questions(wait-input 类) | 系统通知弹出,标题+会话名(会话名空回退 id 前 8 位) |
| 2 | 触发一次回合完成(turn-end 类) | 第二类通知弹出 |
| 3 | 关闭主窗口(驻留托盘)后再次触发两类事件 | 驻留期通知照常弹出 |
| 4 | 点击其中一条通知 | 主窗口前置;显示 toast「请手动切换到会话 X」(fallback 聚焦,M1 预期行为);再次点击通知中心留存通知行为一致 |
| 5 | **DND/权限拒绝路径**(可选,任一平台):系统开启勿扰/拒绝通知权限后触发事件 | 托盘可用:无系统通知,托盘 tooltip 出现 `dsh-forge(N)` 计数 + 一次性 toast「系统通知已禁用…」;托盘不可用(Linux 无托盘环境):仅 log 静默 |
| 6 | **去重验证**(可选):10 秒内同会话连发同类事件 | 合并为一条通知,内容更新计数,不弹多条 |

**PASS 判定**:三平台各完成 wait-input 与 turn-end 两类通知 ≥1 次触发,且点击后主窗口前置(聚焦 fallback toast 属预期)。

## 4. SC5 托盘驻留

**定义**:关窗驻留;托盘菜单恢复/退出。

**实现口径**(任务 4.2):托盘两项菜单(显示/退出,中英随上游 locale);关窗 = hide 驻留;托盘左击 = 恢复/聚焦窗口;退出 = 先关停宿主子进程再退出(无孤儿进程)。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 启动应用,观察托盘区 | 出现 `dsh-forge` 托盘图标 |
| 2 | 点击主窗口关闭按钮(✕) | 窗口隐藏,应用驻留托盘,**进程不退出** |
| 3 | 托盘菜单 → 显示 | 主窗口恢复显示 |
| 4 | 再次关窗 → 托盘左键单击 | 主窗口恢复/聚焦(两态语义) |
| 5 | 二次启动(双击应用图标) | 单实例锁:新实例退出,既有窗口被聚焦(关窗驻留态则从托盘还原) |
| 6 | 托盘菜单 → 退出 | 应用完全退出;壳进程与宿主子进程均消失(任务管理器/活动监视器/`ps` 复验由录屏者口头确认,不要求终端录制) |
| 7 | **Linux 降级路径**(仅 Linux,可选):在无托盘的环境(GNOME 无扩展等)运行 | `ERR_TRAY_UNAVAILABLE` 静默降级:无驻留,关窗即退出,无报错弹窗 |

**PASS 判定**:三平台各完成关窗驻留 → 托盘恢复 → 完全退出闭环;Windows/macOS 必测,Linux 若托盘不可用则按降级口径记录。

## 5. SC8 多装共存

**定义**:CLI/官方桌面(若装)/本壳共存,`$DSH_HOME` 交替使用互不损坏;独立 profile 与上游 `desktop` 并存。

**实现口径**:本壳 profile = `<userData>/host-profile`(≠ 上游 `desktop` profile);产品数据(会话/凭据/设置)共享 `$DSH_HOME`;单实例锁仅限本壳自身。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 机器上已装(或先装)上游 dsh CLI(与官方桌面,若具备) | 三方并存安装 |
| 2 | 用 CLI 创建一个会话并退出 | `$DSH_HOME` 中存在该会话数据 |
| 3 | 启动本壳,打开会话列表 | 能看到 CLI 创建的会话(共享 `$DSH_HOME`,上游格式兼容) |
| 4 | 在本壳中新建会话、配置/使用 API key | 写入 `$DSH_HOME`,不损坏既有数据 |
| 5 | 退回 CLI,再次列出/打开会话 | 本壳创建的会话对 CLI 可见可读,凭据仍有效 |
| 6 | (若装官方桌面)启动官方桌面 | 其 `desktop` profile 独立存在,与本壳 `host-profile` 互不覆盖;交替使用后三方会话数据完整 |
| 7 | 检查本壳 profile 目录 | 目录名为 `host-profile`(位于本壳 userData 下),与上游 `desktop` 目录并存 |

**PASS 判定**:三平台各完成一轮交替使用(至少 CLI ↔ 本壳),会话与凭据互不损坏;profile 独立性肉眼可验(录屏中展示两目录并存)。

## 6. SC9 宿主崩溃恢复

**定义**:三平台各 1 次强杀宿主 → 壳存活 + 提示 + 重启子进程 + 会话从持久化恢复。

**实现口径**(任务 4.4,F2 状态机):宿主异常退出 → 壳存活,UF4 覆盖层进入 `restarting` → 重启子进程(退避 2s/4s/8s,最多 3 次)→ `restoring` → 回放完成 `recovered`:覆盖层关闭 + toast「已恢复最近会话」;重试耗尽/回放抛错 → `failed` 失败态(原因 + 重启应用按钮)。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 启动应用并打开一个活跃会话 | 正常就绪 |
| 2 | 定位宿主子进程 PID(进程树中壳的唯一 node 子进程) | 确认目标 |
| 3 | 强杀宿主(Windows `taskkill /F`,Unix `kill -9`) | 见下行预期 |
| 4 | 观察壳 | **壳主进程存活不退出**;UF4 全屏覆盖层出现崩溃恢复提示(restarting → restoring) |
| 5 | 等待恢复完成(退避序列最长约 14s) | 覆盖层关闭,toast「已恢复最近会话」;最近会话从 session 持久化恢复,会话内容可继续 |
| 6 | 恢复后继续与会话交互一轮 | 会话功能正常 |
| 7 | (可选)重复强杀 3 次以上 | 重试耗尽 → UF4 `failed` 失败态,不静默消失;点「重启应用」→ 宿主关停 + 全新启动并再次恢复 |

**注**:第 3 步的强杀命令允许使用终端(仅限测试执行者操作,非用户路径;SC9 的「零终端」不适用,PRD 原文为「脚本或手检清单」)。

**PASS 判定**:三平台各 1 次强杀 → 壳存活 + 提示 + 子进程重启 + 会话恢复全链路可见(录屏)。
