# Proposal: dsh-forge M4 —— 项目中心工作台(IA 基石)

> **定向说明(2026-09-23 二次定向;2026-09-24 路线图再修订)**:本日 brainstorm 曾将「模式化管线 + 项目中心 IA + 事件对账」合立 M4;用户随后裁决 **IA 单独成题、先行落地——它是后续一切能力的承重层**。路线图现行定形(2026-09-24):**M4 = 项目中心 IA(本提案)/ M5 = 任务调度补全(事件对账 + bug 看板 + todo 便签板,`dsh-forge-m5`)/ M6 = 质量与收口**(评估器 / Quality Gate UI / CC 插件与 forge 仓 CLI 发布收口)**/ M7 = 模式化管线**(三轨 preset + GUI 管线,2026-09-24 顺延)。主提案(`docs/proposals/dsh-forge/proposal.md`)为方向锚,本文为 M4 范围与验收的唯一权威。

## Problem

核心问题一句话:**「项目」是用户围绕开展工作的中心,但应用 UI 没有「项目」这个一等载体——dsh 原生会话列表按 workspace/未分组散置,forge 看板/提案板是独立平铺的视图,M3 起过程文档又默认仓外;代码会话、worktree 状态、看板、提案、管线分居多处,人与 agent 都无法快速识别「这个项目有什么」。后续一切能力(模式化管线视图、知识区、todo/bug 看板、多端协同)都需要先有这个承重的项目中心 IA。**

两条问题线:

- **线一(IA 割裂)**:dsh 原生 workspace(`ctx.workspaceRegistry`,按目录归组会话)与 dsh-forge 项目(SQLite 注册表)两套项目体系并存且互不感知——forge 派发的会话在 dsh 侧落入「未分组」,dsh 侧的 workspace 心智在 forge 工作台无对应;过程资产(看板/提案/管线/文档)与代码资产(会话/worktree)在不同导航层级,项目维度无聚合视图。
- **线二(地基时序)**:M5 任务调度的 bug/todo 看板、M7 模式化管线的管线视图、后续知识区与各类看板,挂载点都是「项目页」;IA 不先定形,这些能力要么挂错地方(返工),要么各自为政(永远聚合不起来)。IA 是后续一切的地基,必须先落。

### Evidence

- **todo.md 条目 19(2026-09-23 用户澄清)**:「dsh 原生的工作区对齐 dsh-forge 的项目」意为——**项目包含工作区(代码区)、forge 文件区、知识区(后续引入);整个 UI 布局要体现:①用户围绕项目开展工作;②项目相关内容要汇总一起,人与 agent 能够快速识别出来**。
- **dsh 源码核查(2026-09-23,`Z:\project\github\deepseek-harness`)**:`ctx.workspaceRegistry`(packages/workspace)——宿主持久保存命名且有序的项目列表、按目录归组会话(会话头验证归属)、移除项目不删文件夹与会话历史、隐藏/移除的会话仍可作为未分组历史——投影机制的数据面在场,契约以本地源码为唯一权威。
- **M2/M3 视图现状**:看板/提案板为独立平铺视图;UF1 注册向导、UF4 feature 看板、UF5 发起链均已落地并被 M3 演进——IA 重构是收纳重组,不是推倒重做。
- **todo.md 条目 20(2026-09-23 用户补充)**:UI 优化——任务面板从属于 feature;**使用文件选择器选择工作区、forge 文件区以及知识区(后续)**——三区位置在注册/项目设置中经文件选择器选定。
- **subagent 会话归拢与任务反查(2026-09-23 用户补充)**:跟任务绑定的会话(含会话内执行的 subagent 会话)须在任务维度标识,且可通过任务打开会话。dsh 源码核查(vendored 0.1.6-alpha.2):subagent 为独立会话(`origin: 'subagent'`),原生 UI 将其归拢于 parent 会话血缘树下、不顶层平铺(`ui-workspace/client/tree.ts`),SubagentAddress 导航面在场(`ui-workspace/client/navigation.ts`);工作台 `session_links` 现仅挂顶层派发会话——会话内 spawn 的执行 subagent 无任务维度身份,任务→subagent 会话的标识与打开路径缺失。
- **IA 细化与执行态聚焦(2026-09-23 用户二次补充)**:①subagent 会话可能很多,会话列表中默认收起,列表保持优雅;②任务面板从属于 feature(条目 20 落进交付结构:层级 = 项目 → feature → 任务面板);③feature 视图按阶段(manifest 词表:prd/design/tasks/in-progress/completed)展示该阶段重点信息——执行阶段有任务执行中时突出呈现,点击执行中任务打开其 subagent 会话;④subagent 会话视图展示所执行任务的元数据(任务↔会话双向可识别)。
- **决策日志(2026-09-23 brainstorm,全部为用户显式选择)**:①工作区对齐 = 项目三区容器 + **全面 IA 重构**(非仅 registry 投影,「仅概览页」渐进方案被否);②投影语义 = 单向(dsh-forge 项目为权威,注册/改名/归档同步 dsh 侧,dsh 侧手改不回流);③本日二次裁决——**IA 从合立 M4 中单独取出先行,作为后续一切的基础**;模式体系与事件对账后置 M5,质量与收口顺延 M6。

### Urgency

- M3 落地后日常管线全面进入应用,用户每天在「dsh 会话列表 ↔ forge 看板 ↔ 文档根」之间切换——项目中心缺位的摩擦每天都发生,且随能力增多线性放大。
- M5(任务调度)的 bug/todo 看板、M7(模式化管线)的管线视图、后续知识区都以项目页为挂载点——IA 越晚定形,挂错位置的能力越多,返工面越大;先落 IA 是后续一切的地基时序。
- workspaceRegistry 为 dsh 现役机制,随上游 0.1.x-rc 快速演进,对齐窗口会漂移(继承 M1 以来的分叉成本论证)。

## Proposed Solution

**M4 = 「项目中心工作台」**:应用信息架构全面重构为项目中心——项目 = **代码区 + forge 文件区 + 知识区(后续引入,仅扩展位)** 三区容器;全部视图以项目为一级重组;workspaceRegistry 单向投影打通两侧项目归属;项目内分屏/多窗口布局。

**五项交付**:

1. **项目一级导航重组**:导航与全部视图以项目为一级组织;打开项目即进入项目工作台;散置于全局层的 forge 视图(看板/提案板等)全部收纳进项目上下文;无项目上下文的孤儿视图清零。
2. **三区容器项目页**:项目页同时承载——**代码区**(该项目会话列表、worktree/工作区状态;subagent 会话按 dsh 原生语义归拢于 parent 会话血缘树下,不顶层平铺且默认收起——计数徽标呈现,数量增长不损列表优雅;含 workspace 单向投影)、**forge 文件区**(以 feature 为组织中心:任务面板从属于 feature,feature 视图按阶段呈现重点信息——执行阶段突出正在执行的任务;提案板、管线入口收纳为项目页内容,功能面零缩水)、**知识区**(仅 IA 扩展位,本里程碑不建任何空占位视图/数据)。
3. **workspaceRegistry 单向投影**:项目注册/改名/归档经 host 半身同步 dsh 侧 workspaceRegistry(同名同序);forge 派发的会话按项目 cwd 自动归组到对应 workspace;dsh 原生 UI 与 forge 工作台的项目归属一致;dsh 侧手工变更不回流(仅提示)。
4. **项目内分屏/多窗口**:同屏分屏(如左会话右看板)与多窗口并行视图能力(M3 显式后置项吸收),布局状态随项目记忆。
5. **任务↔会话绑定反查**:任务维度标识其绑定会话——顶层派发会话(既有 `session_links`)与会话内执行 subagent 会话(血缘推断或派发回写,PRD 定形);从任务可打开绑定会话(顶层会话复用 M1 session-focus,subagent 复用 dsh 原生 SubagentAddress 导航),feature 执行视图中点击正在执行的任务即达其 subagent 会话;subagent 会话视图反向展示所执行任务的元数据;代码区会话树上反向标识会话的任务归属。

**架构约束(继承 + 新增)**:

- 继承:两级插件模型(forge 核心 = 必备插件,视图重组在插件槽位体系内进行)、宿主与协议缝、electron-ipc-security(origin-lock、typed、版本化、最小必要面)、零侵入上游、操作主体模型(agent 写、人编排观察)。
- 新增:**项目三区容器 = IA 母模型**(知识区仅扩展位,不建空占位——遵循「有真实条目才建」纪律);**投影 = 单向语义**(dsh-forge 项目表为权威,dsh workspace 为投影,禁止反向写);**收纳不推倒**(M2/M3 既有视图以重组收纳为主,路由/组件契约尽量保持,控制回归面)。

### Innovation Highlights

- **项目三区容器**:代码区 / 过程文档区 / 知识区在同一信息架构下聚合(过程文档默认仓外后尤为必要)——把 forge 过程资产从「目录树里的文件」升为「项目页面的一等公民」,人与 agent 共享同一项目归属视图。Linear/Jira 验证了项目中心心智,但无 agent 会话与 SDD 资产层;Jan/Cherry 等会话中心客户端无项目工程层——交叉位继续空缺。
- **单向投影的归属打通**:不搞双向同步,以 forge 项目注册表为权威、dsh workspaceRegistry 为投影——两侧 UI 呈现一致的项目与会话归属,而免掉双写源与冲突合并。
- 诚实声明:项目中心 IA 本身是常规产品能力(行业有成熟先例),非创新项;创新在「agent 工程资产进项目页」的组合位。

## Requirements Analysis

### Key Scenarios

- **项目工作台(happy)**:启动 → 项目列表 → 打开项目 → 代码区(会话/worktree/状态)与 forge 文件区(看板/提案/管线入口)一页可见;项目相关内容汇总一处。
- **三区位置选择**:注册向导/项目设置中经文件选择器选定代码区(工作区)与 forge 文件区位置(知识区入口后续);路径合法性校验与非法路径提示。
- **快速识别(人与 agent)**:任一会话/任务/提案/文档可反向定位所属项目;agent 侧(会话上下文/后续注入)与人类侧共享同一项目归属模型。
- **任务↔会话反查**:任务详情可见绑定会话(active/ended 挂接历史)并可一键打开——顶层派发会话与会话内执行的 subagent 会话均可标识与打开;subagent 会话在代码区 parent 会话血缘树下归组(不顶层平铺、默认收起带计数徽标);subagent 会话视图展示所执行任务的元数据。
- **feature 执行态聚焦**:feature 处于执行阶段且有任务执行中 → feature 视图以正在执行的任务为重点信息(任务与执行会话状态),点击执行中任务 → 打开其对应 subagent 会话;其余阶段(prd/design/tasks/completed)按阶段呈现对应重点信息。
- **投影归组**:注册项目 → dsh 侧出现同名 workspace 且顺序一致;forge 派发会话在 dsh 原生 UI 归组正确;未注册目录的既有会话仍显示为未分组(不破坏)。
- **改名/归档**:项目改名 → dsh 侧同步;归档 → 投影处置策略呈现(保留/移除,PRD 定形);dsh 侧手改 workspace(改名/删除)→ forge 侧不回流,提示偏差。
- **分屏/多窗口**:项目内分屏同屏观察会话与看板;多窗口并行;布局状态随项目记忆,重进恢复。
- **既有能力收纳**:M2 看板、M3 提案板/阶段资产面板在项目页内完整可用;操作路径不长于现状(任务面板从属 feature 的层级变化除外,条目 20 定向)。
- **错误路径**:投影同步失败 → 提示不阻断项目注册;dsh 侧 workspace 不可写 → 降级为无投影继续运行;项目工作台加载失败 → 明确错误与重试。

### Non-Functional Requirements

- 继承 M1-M3:离线自足、三平台、中英双语、IPC 安全约束。
- 项目工作台首屏 ≤2s(500 任务规模继承既有预算);视图切换不劣化既有预算。
- 投影操作(注册/改名/归档)同步完成 ≤2s(失败降级不阻断)。
- IA 重构后既有看板/提案板功能面零缩水(e2e 回归背书)。

### Constraints & Dependencies

- **硬前置:dsh-forge-m3 完成**(看板/提案板/阶段资产/文档根全部就位后收纳重组,避免收纳对象还在漂移)。
- workspaceRegistry / SubagentAddress 接口契约以 dsh 本地源码为唯一权威(禁止凭公开资料猜测);host 半身写入通道的权限面设计期验证。
- dsh vendored 对齐基准与升级纪律继承 M2/M3。
- M5(任务调度补全)与 M7(模式化管线)以本提案为挂载前置——bug/todo 看板与管线视图均挂载于本项目页。

## Feasibility Assessment

### Technical Feasibility

**高**。全部为既有机制之上的重组:视图与导航为应用自有代码(收纳重组自由度 full);workspaceRegistry 为 dsh 现役机制且 host 半身通道有 M2/M3 先例(sessionController 等);任务↔会话反查基于既有 `session_links` 表与 dsh 原生 SubagentAddress 导航面扩展;投影写入契约设计期对照源码定形。无上游依赖;subagent 挂接优先血缘推断(零新协议面),派发回写为 PRD 备选(协议面设计期评估);最大工程量在导航重组的回归面控制。

### Resource & Timeline

单人产品线;量级低于 M3(无引擎/数据迁移,纯 IA + 投影)。建议 PRD 分 phase(导航重组与项目页 → 三区收纳与回归 → 投影 → 分屏/多窗口),每 phase 设 gate。

### Dependency Readiness

无外部 API 依赖;M3 硬前置(当前任务分解已就绪待执行);dsh vendored 基准锁定纪律继承;workspaceRegistry 契约本地源码在场。

## Scope

### In Scope

- 项目一级导航重组:全部视图以项目为一级组织;项目列表入口;孤儿视图清零。
- 三区容器项目页:代码区(会话/worktree/工作区状态)、forge 文件区(看板/提案板/管线入口收纳,功能面零缩水)、知识区扩展位(无空占位)。
- 任务↔会话绑定反查:任务维度标识绑定会话(含会话内执行 subagent 会话),任务→会话打开(顶层走 session-focus、subagent 走 SubagentAddress);subagent 会话归拢语义(挂 parent 血缘树下,不顶层平铺,默认收起+计数徽标);subagent 会话视图展示任务元数据。
- feature 组织与阶段感知:任务面板从属于 feature;feature 视图按阶段展示重点信息,执行阶段突出正在执行的任务(点击打开其 subagent 会话)。
- workspaceRegistry 单向投影:注册/改名/归档同步(同名同序)、派发会话归组、dsh 侧手改不回流仅提示、投影失败降级不阻断。
- 项目内分屏与多窗口布局,布局状态随项目记忆。
- IA 回归盘点:既有 e2e 规格迁移清单与功能面零缩水验收。

- [ ] SC8 feature 阶段感知:feature 视图按阶段呈现重点信息;执行阶段有任务执行中时突出呈现正在执行的任务,点击可打开其对应 subagent 会话(e2e 断言)。
