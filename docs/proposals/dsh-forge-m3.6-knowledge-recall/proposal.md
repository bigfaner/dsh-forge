# Proposal: dsh-forge M3.6 知识召回体验与增强（检索实现可插拔 + Tier 1 分级检索首发）

> 定位：独立小里程碑 **M3.6**（紧随 M3.5，用户裁决 2026-10-06 探索文档 §6.5；插 M3.5 与 M4 之间，M4 编号与排期不动，P1.1/M3.5 插队先例）。
> 承接（M3.5 拆分裁定 2026-10-06）：M3.5 Out of Scope 移交本提案的**零依赖项四件**——Tier 1 分级检索、查找技能（两步法）、召回侧提示词瘦身、`search` 零命中 UX；Tier 2/3 向量分层随本提案锚点记账。

> 宪法输入 = 总纲 [dsh-forge-redesign/proposal.md](../dsh-forge-redesign/proposal.md) §知识库工程机制·延后锚点（向量/语义检索）+ §演进路书 P5 表；探索附件 = [vector-recall-exploration.md](vector-recall-exploration.md)（随本提案立项自 M3.5 目录迁入，方法论与调研底稿）。
> 经验输入（2026-10-07 提取）：`Z:\project\github\transform-and-agent-search`——agentic-search SOP 先例（真实工程目录 333 文件全量验证、262 测试全绿）：查询侧同义扩展、命中明细返回体、零命中重试纪律、SOP 合规测试旅程形态。

## Problem

知识召回有两层欠账：**词面匹配质量过脆**（本里程碑解决）与**语义泛化缺失**（Tier 2 锚点，不在本里程碑）——外加两个使用体验缺口与一个架构缺口。

1. **词面匹配过脆**（现状 `knowledge_search` = keywords 精确 AND + 标题/摘要子串，[recall-service.ts](../../../packages/core/src/knowledge/recall-service.ts) `rankEntries`）：
   - 多词查询部分命中 = **零结果**（AND 语义缺一即排除）；
   - **CJK 复合查询永不命中**：查询「前端部署」成单 token，与预分词标签「前端」零交集（FTS 系分词器对 CJK 无效是已知事实，探索 §6.3）；
   - **无分级相关度**：命中一个常见标签与命中一个稀有标签同权（无 IDF）——排序信号弱。
2. **agent 查询与检索面结构性错位**：agent 查询天然是自然语言短语，与标签/子串匹配错位——e2e 失败台账③已实际发生，现状靠提示词掌舵缓解（**治标**）；查找方法论（关键词提炼 + 同义扩展 → 检索 → rerank）未固化为技能。
3. **零命中即死路**：零命中反馈无替代路径（无相邻域提示、无词表提示）——agent 与用户都只能放弃。
4. **召回提示词未瘦身**：M1 现状召回段 = 存在声明 + 召回流程 + 两 tool 用法全文；M3.5 已在沉淀侧执行「提示词最小化」纪律（存在声明 + 时机规则 + 技能指针），召回侧不对齐 = token 纪律缺口（M3.5 SC-4 拆分断言已预告变更归本提案）。
5. **检索实现不可替换**：匹配/排序逻辑是服务内私有函数（`rankEntries` 模块私有，fix-35 降私）——升级检索方式只能原位改写，无对照验证通道（升级前后谁更好无法并排回答），未来向量实现（Tier 2/3）与可选组件降级无插入点。

### Evidence

- **代码事实**：`rankEntries`（recall-service.ts:75–96）= `KEYWORD_WEIGHT×命中关键词数 + TITLE/SUMMARY_WEIGHT×子串位`；`matched.length !== queryKeywords.length → continue`（AND 缺一排除）；无 IDF、无软匹配；`selectRowsByDomain` 域前缀 SQL 段匹配。服务已有类型面接口（`KnowledgeRecallService = Pick<KnowledgeService,...>`）与工厂注入缝（`indexService` 可注入测试替身）——接口化是自然延伸而非重造。
- **cordis 事实**：cordis 已在产品依赖栈（`apps/host` pin `@deepseek-ai/cordis` 4.0.4 + `cordis-plugin-loader` 1.0.5）；knowledge 插件本就是 cordis 插件（profile `cordis.patch.yml` 产品行 `@dsh-forge/knowledge`）；服务 provide/inject 有契约测试先例（pin-07：真实 cordis runtime + core/knowledge 插件注入面）——**接口化走 cordis 服务面零新增依赖**。
- **M3.5 摊牌事实**：M3.5 InScope-8 ④ 显式将「召回增强分层记账」移交本提案（Tier 1 首发）；Out of Scope 列四件零依赖项与本提案 InScope 一一对应。
- **可放大器**：M3.5 老项目冷启动批量导入使库存**瞬间数百条**且提取产出标签有方差——exact-AND 的漏检概率随标签方差放大（探索 §6.2：「导入的条目可被找到」直接受损）。
- **机制事实**：FTS5 内建于 better-sqlite3（默认编译开启），`bm25()` 为 SQL 原生排序函数——分级软匹配**零新依赖**可实现（探索 §6.2 调研）。

### Urgency

- 观察窗口就在 M3.5 之后：批量导入完成即 dogfood 真实查询密度上升，漏检可观察（探索 §1）——Tier 1 紧随 M3.5 的时序裁决即源于此（M3.5 冷启动导入后的召回质量观察 = 本里程碑验收输入）。
- 每次漏检都在教 agent「知识库没用」——召回信任一旦流失，沉淀↔召回飞轮双向受损（沉淀的条目找不到 = 沉淀动力同步衰减）。
- 检索升级若无对照通道，Tier 1 效果只能靠体感——配置控制召回方式 + 日志实现标识使「同一查询新旧实现谁更好」可回答、可回溯（对比验证即验收方法）。

## Proposed Solution

五件交付 + 一笔锚点记账：

1. **检索实现接口化与可插拔（架构地基，2026-10-07 用户定向）**——RecallService 拆为**固定壳 + 可替换检索实现**：
   - **固定壳**（横切面不动）：项目守卫、召回日志写入、索引缺失静默重建联动、域前缀/status 过滤、排序与置信解耦——实现切换时横切面语义零变化。
   - **检索实现接口**（contracts 定义）：承载 search 的匹配与排序核心；`readAbstract`/`heatByEntry` 为缓存直读，不入变化面。
   - **双内置实现经 cordis 服务注册**（provide/inject，dsh shell 同源机制）：`keyword`（现状管线迁置——exact-AND，**降级兜底 + 对照实现**）与 `bm25`（Tier 1，**新默认**）。
   - **配置控制召回方式**（用户定向：方便对比与验证）：配置面 = **dsh 设置对话框 > 「Forge 设置」区块**（2026-10-07 用户定向；M3 既定交付面——产品 client 插件经 `settings.general.item` / `settings.section` slot 注入，注入缝已源码核实，非 fork）；配置项选择实现（默认 bm25，可切 keyword 对照）；作用域与行形态入定缝项。M3 弹性裁切时降级 = 配置文件 + 文档指引（服务层配置读取不依赖 UI，见 Constraints）。
   - **召回日志记录实现标识**：`recall_logs` query 快照内嵌实现 id（零 schema 变更）——同一查询切实现重跑即可对比，日志可回溯（M7 召回日志页签天然按实现分组消费）。
   - **降级链**：所选实现不可用（未注册/初始化失败）→ 回退 keyword 实现 + 关键日志记账——降级零阻断（mneme 先例）的接口化表达。
   - **外部实现独立插件包动态装载 = Tier 2 可选组件装载形态**（机制同源：同一服务接口即装载契约，届时独立包装载零改消费方；本里程碑不交付外部包形态，深度裁决见 Assumptions Challenged）。
2. **Tier 1 分级检索（FTS5 BM25）实现**：
   - 新增 FTS5 缓存表 = 索引缓存派生件（随 `rebuildIndex` 同步重建，rowid ↔ entry_id；索引内容 = keywords + 域路径段——索引侧天然预分词，unicode61 分词器即可）；**常维护**（与实现激活解耦，配置切换零迁移——目标约束，形态终裁入定缝项）。
   - 查询侧：`keywords[]` 直入 MATCH；`text` 经**词表子串扩展**（词表 = 索引缓存闭集：全部 keywords ∪ 域路径段，纯 JS——CJK 复合词展开为词表命中项 OR 组合）→ `MATCH ... ORDER BY bm25(...)` **分级排序**（IDF 加权，稀有标签权重更高）。
   - **exact-AND 语义退役为非默认**（keyword 实现保留为对照/兜底，见交付 1）；`text` 标题/摘要子串 = **词表外词兜底通道**保留（代码标识符类查询词仍可命中）。
   - 不变项：域前缀过滤、status 过滤（M3.5 交付面）、`recall_logs` 执行点日志口径（M7 观测仪器连续性）、排序与置信解耦裁决（score = 相关度，置信阈值 M5）。
   - **诚实边界**：BM25 是词面检索——同义/改述（「上线」vs「部署」）与中英跨语言在**索引层不命中**（Tier 2 向量语义，探索 §6.1 字段性质分工）；**查询侧由查找技能的同义扩展缓解**（交付 3——agent 掌舵层零依赖，SOP 实测先例），索引侧彻底解 = Tier 2。本实现解决词面匹配质量：软匹配、分级、CJK 复合查询。
   - **返回体附命中明细**：每命中条目附命中词项与通道（`match_detail` 先例——总纲「召回可解释·命中理由」的落地形态；agent rerank 据此判断采信与回读优先级）。
3. **查找技能·两步法**（knowledge 技能集交付；经验提取 2026-10-07——transform-and-agent-search SOP 先例）：方法论 = ① **查询构造 = 关键词提炼 + 同义/相关词扩展**（会话 LLM 零依赖——「盐雾↔耐腐蚀」类词面失配实测有效）→ ② `search`（结构化 keywords/text/域）+ agent 复核 rerank（据命中明细判断采信）；**零命中纪律 = 禁断言「不存在」，换词/再扩展重试**（SOP 第 2 节先例）；技能正文 = 方法论唯一事实源（提示词只存指针——SOP.md ↔ 提示词常量双写纪律先例）；四步法（改写 → 域向量定位 → 关键词筛选 → rerank）为 Tier 2 演进锚（探索 §6.4 已定稿管线——查询改写步与本技能步骤① 同源递进）。
4. **召回侧提示词瘦身**：召回段最小集 = 存在声明 + 召回时机规则 + 查找技能指针；两 tool 用法细节降载 tool 自描述（hint 与工具名/描述/参数说明同源 = tools/ 定义对象单一事实源，M1 既例）。
5. **零命中 UX 与 hint 改进**（M3.5 移交项）：`search` 零命中返回体附替代路径 hint（相邻域提示 / 词表近邻提示 / 兜底通道指引）；`read-abstract` 未命中 hint；浏览页搜索零命中反馈同构（M1 UX 改进移交项）。
6. **Tier 2/3 锚点细化 + 总纲回写**：
   - **向量载具定向（2026-10-07 用户定向：向量使用 SQLite 插件）= SQLite 向量扩展（vec0 虚拟表暴力 KNN）**——Tier 2 首个向量场景即引入（与嵌入闭包同属可选组件一次交付，+1 三平台二进制在 ~100MB 模型 + 数百 MB 运行时闭包旁为噪声；Tier 3 零迁移，无 JS→扩展二次改造）；具体包（sqlite-vec vs SQLite 官方 vec1）随落地时稳定度终裁，入定缝项。
   - Tier 2 形态注记：**向量实现 = 经检索实现接口插入的 cordis 插件**（可选组件独立装载，交付 1 机制同源）。
   - 总纲**两处**改写：§知识库工程机制·延后锚点 bullet 与 §演进路书 P5 表行——最轻路径「宿主进程内 ONNX 嵌入 + flat 余弦」→「进程内 ONNX 嵌入 + **SQLite 向量扩展 KNN**」（flat 暴力检索语义与零外部服务纪律均不变，载具换名）；触发条件细化为「dogfood 真实查询中关键词召回漏检可观察（零命中但人工判定应有命中，召回日志可回溯）或单库 >5k 条」（探索 §4）。
   - 演进路书插 M3.6 行；探索文档自 M3.5 目录迁入本提案目录。

### Innovation Highlights

诚实说明：BM25/FTS5、两步检索法（检索 → rerank）均为业界标准。本方案的特点：

- **召回实现可插拔（cordis 服务面）**：固定壳（守卫/日志/降级链）+ 可替换实现——配置控制召回方式使同一查询跨实现可对比可回溯（日志实现标识）；Tier 2 向量实现 = 「再插一个实现」（可选组件装载形态预铺，机制同源零改消费方）。
- **查询侧同义扩展（agentic-search SOP 先例）**：同义/改述缝的零依赖缓解放在 agent 掌舵层（技能步骤①——会话 LLM 提炼关键词 + 扩展同义词），索引侧彻底解留给 Tier 2 向量——掌舵与引擎分工，避免为语义泛化提前引入嵌入闭包。
- **字段性质分工**（探索 §6.1 洞察）：索引侧字段天然预分词（keywords = 标签、域路径 = 切段）→ 词面分级检索；散文字段（域描述，每库仅几十条）→ 向量语义——按字段性质分配检索技术，而非全条目单一嵌入通道；查询侧 CJK 缝用**闭集词表子串扩展**解，不引入中文分词器依赖与自定义 tokenizer 原生扩展。
- **检索栈全收敛 SQLite**：FTS5（better-sqlite3 内建）+ vec0 扩展（进程内加载）——零外部服务、零自持检索数学，与宪法单机轻依赖纪律同构。
- **降级零阻断**（dsh-mneme 先例）：所选实现不可用 → keyword 兜底；Tier 2 向量组件不可用 → 退回词面实现——检索永不失效。

## Requirements Analysis

### Key Scenarios

1. **多词软匹配**（happy）：agent 查 `keywords=[前端, 部署]`，库内仅有「前端」标签条目 → keyword 实现零结果；bm25 实现命中 + 分级排序（含「前端」稀有标签者排前）。
2. **实现对比验证**（happy，用户定向）：用户在 dsh 设置对话框 > Forge 设置切换召回方式（bm25 ⇄ keyword）→ 同一查询重跑对比结果；recall_logs 按实现标识回溯两实现的命中面差异（M7 页签可分组）。
3. **CJK 复合查询**：`text=「前端部署」` → 词表子串扩展命中词表项「前端」→ MATCH 命中含「前端」标签的条目。
4. **词表外词兜底**：查询含代码标识符（`recall-service` 类，词表外）→ 该词无 MATCH 贡献，但 `text` 子串通道命中标题/摘要。
5. **零命中路径**（SOP 先例：零命中 ≠ 不存在）：全词未命中 → 返回体 hint 给相邻域与替代路径 → agent 按查找技能换词/再同义扩展重查（禁直接断言「不存在」；多轮仍零命中方可报告未命中）。
6. **agent 召回全链**（happy）：开发会话遇项目问题 → 召回时机规则触发 → 查找技能提炼关键词 + 同义扩展 → `search` 软匹配命中（返回体含命中明细）→ agent 据明细 rerank → `read-abstract`。
7. **降级**：所选实现未注册/初始化失败 → search 仍可用（keyword 兜底）+ 关键日志在案。
8. **边界**：
   - 查询词含 FTS5 MATCH 语法特殊字符 → 转义防语法错/注入；
   - 词表子串扩展误命中（过短查询词 OR 展开噪声）→ 最小长度阈值/展开项数上限（参数设计期定）；
   - 外部修改对账触发 `rebuildIndex` → FTS 表随重建同步（一致性）；配置切换实现 → 无需重建/重启（共享缓存底座 + FTS 常维护）；
   - 精确性回退感知：原 exact-AND 精确查询现返回更多软命中——分级排序 + limit 护栏，断言排序首位 = 最强命中；
   - M3.5 延期：本里程碑实施时序顺延（管线手术对象含 M3.5 status 过滤面），设计稿可先行。

### Non-Functional Requirements

- **零新依赖**：package.json runtime 依赖零新增（cordis 已在栈、FTS5 内建）；产物零新增原生扩展——SC 断言。
- 检索延迟：数百至数千条规模毫秒级（与现状同数量级）。
- token 纪律：召回提示词段最小化（能力降载 tool 自描述与技能正文，非删能力）。
- `recall_logs` 口径连续：新管线执行点日志写入不变（query 快照/命中行/哨兵行 + 实现标识——M7 观测面数据源不断流）。
- 实现切换零迁移：配置切换后无需重建索引/重启即可用所选实现检索。

### Constraints & Dependencies

- **前置 = M3.5 交付面**（实施时序前置，强烈建议严格紧随）：
  - status 过滤（`unconfirmed` 不入召回）——检索管线手术在同一管线上做，M3.5 先落地避免返工；
  - 写后索引联动（M3.5 InScope-1）——FTS5 表随同一联动更新（增量 or 批量后重建，形态随 M3.5 定缝项 2 裁决对齐）；
  - `knowledge_domains` 缓存表——零命中 hint 的相邻域提示数据源 + Tier 2 域向量载体挂点（本里程碑只读消费，不改结构）。
- **cordis 服务面**：已在依赖栈（`@deepseek-ai/cordis` 4.0.4，apps/host pin）；provide/inject 先例 = pin-07 契约测试（真实 runtime + knowledge 插件注入面）——零新增依赖。
- **配置面依赖 = M3「Forge 设置」区块**（dsh 设置对话框通用设置下方，slot 注入缝已核实）——UI 载体为 M3 交付面，本里程碑新增「知识召回」配置行；**降级路径**（M3 弹性项裁切、区块降级为配置文件时）= 本配置项同步走配置文件 + 文档指引——服务层配置读取不依赖 UI 在场（SC-6 以配置值层断言为基线，UI 断言随区块在场启用）。

## Alternatives & Industry Benchmarking

### Industry Solutions

- 关键词相关度标准 = BM25（Lucene/Elasticsearch 默认相关度函数）；SQLite 生态内建路径 = FTS5 `bm25()`（探索 §6.2）。
- 可插拔检索后端：Elasticsearch/OpenSearch 的 similarity 插件、数据库引擎的可替换执行器——「接口 + 注册 + 配置选择」是标准形态；本方案将其下沉到单机 cordis 服务面。
- agent 检索方法论：两步检索（检索 → 复核 rerank）为 agent 检索公开方法论常态；改写-检索-重排 = RAG 标准管线（Tier 2 四步法原型，探索 §6.4）。
- 向量存储业界主流 = 独立向量服务/库（Qdrant/Chroma ❌ 违零外部服务纪律）；单机嵌入式 = SQLite 向量扩展（sqlite-vec，探索 §2.1）。

- **InScope-1 检索实现接口化与可插拔**（架构地基）：
