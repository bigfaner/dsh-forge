# 评审 Note 实现期事实回填以单源门槛兜底

> 提案引用的枚举/词表存在实现期才可完全定谳的归属缺口时，不要求提案期强判定，也不判 Blocker——改为在提案中内置单源映射门槛，缺口被门槛兜住、实现期必然回填。

## 规则

- **适用**：提案引用的枚举/词表存在实现期才可完全定谳的归属缺口（如场景码 → 状态三态映射的个别码归属）。
- **做法**：提案写明「实现前以 `<SINGLE_SOURCE>` 常量单源列出全量映射表，逐项断言」；评审以 Note 记缺口、不判 Blocker。
- **闭合**：实现期以单源常量 + pin 测试（逐项断言防漂移）闭合缺口；闭合前该交付不得结算。

## 判据（正反例）

- ✅ 场景码归属缺口：`FORGE_PROGRESS_SCENARIOS` 单源映射表 + `FORGE_LOOP_SCENARIO_PHASE` 全量映射 pin 测试，评审 Note 不阻塞。
- ❌ 提案期强行拍板全部归属（信息不足，拍错即返工）。
- ❌ 评审判 Blocker 要求提前定谳（门槛已兜住的不构成阻塞）。
- ❌ 实现期散落字面量映射、无常量单源、无 pin 测试（门槛空转）。
