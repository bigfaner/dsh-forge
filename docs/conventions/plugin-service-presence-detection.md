# 跨插件服务在场性检测（实时求值纪律）

> dsh 一切皆插件，插件可中途装卸。凡消费**其它插件提供的服务**（如 expert-squad 的 `experts`），在场性检测必须**每次消费点现查**——检测结果永不缓存。

## 规则

| 面 | 要求 |
|---|---|
| 检测 | 每次消费点调用期求值（`ctx.reflect.get` 防御读取 + try/catch）；无 memoization |
| 消费 | systemPrompt 段 → text 回调每回合求值；消息组装 → 组装那一刻求值一次 |
| 缺席 | 服务缺席/异常/非函数面 = 该消费点回落既有缺省形态（空串/回落模板），零固定税 |
| 快照例外 | 已发出的消息文本允许携带求值时快照——消息即事实，不回改；后续消费点各自现查 |

## 判据（正反例）

- ✅ `forge:commander` 段：`text: () => present() ? 话术 : ''`——每回合现查，插件卸载下一回合即失效。
- ✅ P8 评审指示：收口消息组装那一刻求值 `expertsPresent()`，与渲染同刻无窗口。
- ❌ 装配期探测一次存变量供后续消费（插件中途卸载后仍按在场行为）。
- ❌ 消费点读装配期缓存的布尔值（同上，快照只允许存在于已发出的消息文本内）。

## 消息快照的边界

消息发出后插件卸载，已发指令不会变——这是消息的本质。主会话按过期指令行动时的最坏错位（如委派工具已不在）由自然回落承接，不算检测缺陷；修复责任在**下一个消费点**现查。
