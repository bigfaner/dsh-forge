# 验收规则参考示例

`acceptance.md` 验收规则（规则 1-6 于 2026-10-23 固化，规则 7 于 2026-10-24 增补）的归纳缘起与具体判例（2026-10-23 ask 面板验收误判「通过」、用户复测即破——以此为主判例）。

## 规则 1 可见性断言

**判例**：ask 面板经整页 append 渲染在 100dvh chat 根之下（`askTop = 844 = 视口高`、`bodyScrollH = 1688`）——DOM 存在但用户完全不可见。探针只断言 `.ask-card` 数量 > 0 即判「面板出现」，验收通过后用户复测即破。

**正例**：断言三元组——节点存在 ∧ `getBoundingClientRect()` 与 viewport 相交 ∧ `offsetHeight > 0`；截图随证据归档。

## 规则 2 版本/实例同一性

**判例**：回归实例一天内多次重启（每次换端口/token），手机页面持旧 bundle（缺推送直开逻辑）连新实例；用户报告「面板不出现」时，第一步未确认其实例身份与页面构建版本，排查走了弯路。

**正例**：验收前固定并记录端口/token/启动日志行；涉及页面的断言前强制 reload 或校验 bundle 版本标记；收到问题报告先问「哪个实例、页面何时加载」。

## 规则 3 现场保真

**判例**：ask 挂起期间实例被回收，pending 随之消亡、会话留下 interrupted——「工具挂起后消失」被误读为正常流程分支。

**正例**：验收窗口内不重启/不回收实例；一旦中断，涉及流程整体重跑，不引用中断前的任何中间态作结论。

## 规则 4 全链闭环

**判例**：ask 桥修复后只断言「面板出现」即验收通过；「作答回灌到 agent」与「composer 恢复」两段未验——后续实际是回灌正常、但恢复态与可见性组合暴露新问题。

**正例**：五段逐段断言——①请求到达（host 侧证据）②面板可见 ③用户操作被接受 ④结果回灌（agent 侧证据）⑤UI 恢复预期态。缺任何一段不判通过。

## 规则 5 维度扫全

**判例**：「所有预设模式都支持问题面板」裁决下，修复后只验了单一会话路径，未按预设逐项过。

**正例**：把裁决中的全称量词展开成用例清单（突击/远征/每个内置预设至少一条），逐条打勾后才能收口。

## 规则 6 探针卫生

**判例**：①reader 可见性探针的选择器误中 topbar（className 含匹配词），误报「打开成功」；②探针 token/端口串场连到错误实例，枚举到旧数据误导定性；③hero 富化整树重建使 fill 撞上已分离节点，脚本超时被误读为页面故障；④PSK 展示密钥派生漏位填充（51 字符 vs 52），激活恒报 `psk:length`，误查为 host 门故障。

**正例**：探针脚本首跑先自证（选择器命中唯一性、零脚本异常）；页面 `pageerror`/console error 监听必挂且随结果一并输出；等待一律用显式条件（waitForSelector/轮询断言），禁止「固定 sleep 一次就取值」；密钥派生对拍 host 侧展示口径（base32 位填充不可省）。

## 规则 7 隧道域归因（2026-10-24 增补）

**判例**：①隧道 401 一律先疑「密钥轮换/配对失效」——实为同页重建传输 seq 归零撞 host 防重放水位（`3579f34f`），401 群混杂轮换误报文案；②抽屉打开慢归因「公网天然慢」——实为同一打开窗口 grouped 重复调用两次 + 串行渲染 + 零缓存（`ef6afa2a`），修复后温开 273ms；③把启动模式探测的 `forge-stream unauthorized（sid/epoch 缺席）` 日志当故障——那是激活前无材料的预期噪音。

**正例**：隧道域 401 归因先取信封三元组（sid/epoch/seq，fetch 包装取证）——世代冲突（重建后批量 401）与重放伪影（单帧、相邻有 ok）处置完全不同；延迟类报告先做分段时间线（点击→各 RPC 起止→渲染），「肉眼可见」量化到毫秒再定位；host 日志 `[pair-diag]` 行是隧道域归因的单源（`acceptance.md` 隧道归因判据表）。
