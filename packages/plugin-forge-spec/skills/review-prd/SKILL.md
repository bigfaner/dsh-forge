# PRD 评审（review-prd）

PRD 生成后、ui-design 前。核心三问见下；需求层评估，不做技术选型。只出报告不改 PRD，返工权归 write-prd。

## 执行机制：独立 subagent

- 主会话只做两件事：**组装简报**（PRD 工件路径、上游 proposal 路径；不含讨论过程与预期结论）与**转呈结果**。
- subagent 不继承主会话上下文，结论以自己读到的文档与代码为据；报告落盘 `prd/review/report.md`（feature 目录相对路径），主会话不改报告，只做后续处置。

## 评审三问

1. **需求合理吗**——每条需求追溯到上游 proposal 的真实诉求（无中生有、或偏离 proposal 已裁决的方向 = 问题）；目标是真需求还是伪需求（为方案找需求、为求全凑功能）；范围与需求对等（多做的砍、缺的补）；Out of Scope 显式且不藏关键风险。
2. **用例充分吗**——角色×用例矩阵覆盖完整：每个角色有主流程用例；每条 In Scope 需求至少一个用例承载；关键边界（失败/异常/权限/并发/迁移）有对应用例或显式排除；用例图（若有）与文字规格一致。
3. **用户故事合理吗**——每条故事可客观核验（Given/When/Then 无歧义词：快、友好、合理）；故事间无重叠无矛盾；验收标准与 In Scope 双向对齐（每条 AC 源自某条故事，每条故事有 AC 承接）；背景中的每个角色至少一条故事。

## 门核对（M1/M2/M4）

除评审三问外，按下列门逐项核对；任何一条不过 = Blocker。触发判据与 write-prd 的 AC 分档口径一致。

### M1 真机取证门核对

- **核对项**：强制域任务（交付物含运行期装配面——进程、网络端点、真实调度/时钟、对外部系统/硬件的真实副作用）的 AC 必含**真机端到端取证条目**，写明**取证方式 + 取证环境**；缺失 = Blocker。
- 豁免域（纯逻辑/纯文档）无此要求，不判缺陷。判据是**交付物性质**，不随 AC 文案是否「提到 UI」漂移。
- **判定正例**：某交付面为 Web server 的任务，AC 只写「单测覆盖全部 handler、契约测试全绿」而无真机端到端取证条目 → 判 Blocker；同任务 AC 含「真实服务端启动后经真实 HTTP 端点走完整请求闭环，截图与响应记录归档 walkthrough/（取证方式=端到端走查，取证环境=本机真实运行时）」→ 通过。

### M2 裁决清单段核对

- **核对项**：涉 UI/交互面的 PRD 必含「待用户裁决清单」段——列出微文案、布局终态、触屏交互词汇等规格中不存在、只有用户能判的决策点（无决策点写「无」）；缺段 = Blocker，段内留空不写「无」也 = Blocker。
- 非 UI 面的 PRD 无此段，不判缺陷。视觉 AC 基准须为目标产品的既定视觉基准（实机形态），mockup 只当布局草图。
- **判定正例**：涉触屏交互的 PRD 无「待用户裁决清单」段 → 判 Blocker；同 PRD 补段列出「下拉刷新手势 vs 显式刷新按钮」等决策点（或写「无」）→ 通过。

### M4 批次末文档门

- **核对项**：每批次收口时核对**规格文档 / 实现口径 / 摘要三方一致性**——PRD/规格、代码实际行为、任务摘要三处对同一机制的口径一致；批次内不一致未清零 = Blocker。通道级/方案级裁决转向时，同一提交内须含旧口径文档回改与已建代码处置决定（弃/改/留）清单，悬置「先实现后裁决」= Blocker。
- **判定正例**：批次内规格已改为「游标 host 单点」，但任务摘要仍写「客户端游标竞速」且代码按旧口径实现 → 三方不一致判 Blocker；同批次内文档回改、代码处置清单与摘要同步更新一致 → 通过。

### M6 判例正例（super-composer）

核对取证条目、裁决清单与归档时，以下列正例形状为参照（与 write-prd 正例判例同源）：

- **真机取证结算门 AC**：真实宿主 + 真实 dist 驱动走查、样式逐项自检、截图归档 `walkthrough/`（判例 = super-composer AC12）。
- **用户裁决台账段**：裁决逐条落档、可追溯（判例 = super-composer §6-§8 形态）。
- **walkthrough 分批归档**：按批次/场景子目录留盘，验收记录与实现同步产出。

## 输出与处置

报告问题三级：

| 级别 | 判据 | 处置 |
|---|---|---|
| **Blocker** | 需求错位 / 用例或故事覆盖有洞 / AC 不可核验 | 返工 write-prd 并重新 upsertFeatureDoc，重评清零才放行 |
| **Question** | 权衡可辩，agent 无法单方裁定 | 交互语境 `ask_user_question` 裁决；派发语境呈报于任务输出 |
| **Note** | 不阻塞的改进建议 | 留档 |

- 每个问题附**证据**（PRD 段落 / proposal 段落 / 用例矩阵位置）；断言必须具体，不接受空评。
- 放行判据 = Blocker 清零且 Question 全部有裁决；报告尾记录放行结论。
- 交互语境：Blocker 清零后向用户呈报放行结论，经确认进入 ui-design。派发语境：worker 即独立上下文直接执行，无 Blocker 按简报结算。
