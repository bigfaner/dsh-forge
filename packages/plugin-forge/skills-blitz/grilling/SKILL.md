# Grilling（突击提案探索）

职责界线 = 事实与决策的界线：技术要点（触点、复用、对齐、量级）是事实，探索代码库作答；选型与取舍是决策，问用户。

<HARD-GATE> 禁止写代码或执行任何实现动作——本技能只产出 proposal 文档及其 proposal 域记录行。 </HARD-GATE>

<HARD-RULE> **事实自己查，决策才问人。** 凡能从环境（代码库/工具/文档）查到的是事实——自己去查，不问用户；凡取舍（方案取舍、接受红旗、转远征）是决策——必问用户，不沉默假设。 </HARD-RULE>

## 流程

```
建设计树 → 分轮访谈 → 终局确认 → 五段成文 → 一致性检查 → 用户批准 → 注册
```

### Step 1：建设计树

检索代码库相关特性、文档、提案与近期历史，把问题组织成设计树：每个决策节点挂着依赖它的子决策。树根 = 根本需求界定（「我理解的需求是 X；备选 Y、Z」）；根未裁决树不往下长。

### Step 2：分轮访谈

**每轮只问当下就能问的问题**：前置决策已定、不依赖本轮其他未决问题的，才进本轮。每轮经 `ask_user_question` 一次打包发出：

- 每题编号（Q1/Q2/…）、推荐答案置首；措辞让「是」即接受推荐。
- 依赖本轮仍未决问题的，留到下一轮。
- 用户答完一轮即更新设计树：已决节点解锁其下游问题；推翻早前假设则回溯重决。

**事实查证不阻塞提问**：问题需要环境事实时派子代理去查，查证期间只有它的下游问题等待，其余照问。突击典型事实（结论落提案「改动影响范围」段）：

- 触点细化到 **file 粒度**——预期要动的文件路径清单，拿不到不成文。
- 复用核销——先核销官方同语义机械（工作区 AGENTS 约定）；「官方没有」以读懂为前提。
- UI/DB 对齐门——触及 UI 或 DB 变更面，对齐结论落提案文档后才成文。
- **官方核销结论**——触及外部/官方机械装配面时，核销结论（源码位置、声明方式、生命周期、并发/持久化语义）作为事实落提案「改动影响范围」段；纯逻辑/纯文档提案不要求。
- **真机取证方式**——交付物含运行期装配面（进程、网络端点、真实调度/时钟、对外部系统/硬件的真实副作用）时，取证方式与环境作为事实先行核实落提案；纯逻辑提案不要求。
- 可行性红旗（改动面超突击量级 / 需自建机制 / 外部依赖取证成本高）——事实呈现后转为决策：建议转远征，用户裁决。

**Need Gate**：深入任何特性细节前按序检查——有更简单的替代？真实需求是什么？为什么是现在？用户否决则记 `Challenge Override`，不再纠缠。

### Step 3：终局确认

终止 = 没有遗留可问的问题：全分支裁决完毕，零沉默假设——未问出口的问题不得默认成立，未呈出的备选不得默认排除。逐条复述问答供用户审核，末尾必附「有没有我该问而没问的？」；更正即回溯重决。确认前不进成文。

### Step 4：五段成文

提案目录与存储布局见 forge:pipeline 系统提示段「文档位置/目录树」；五段构成（不含风险段）以该段突击语义为准。「改动影响范围」段 = 事实结论：**file 粒度触点清单 + 复用核销结论**。意图推断（new-feature / enhancement / refactor / cleanup / fix / doc）给出推理过程，用户可否决。

方案段只写目标形态，不留调整修复叙事；关键术语随首次出现以定义句固化。

**条件强制段**（涉 UI/交互面的提案才加段，非涉面提案无此段不判缺陷；短平快提案不启用）：

- **待用户裁决清单**——列出规格中不存在、只有用户能判的决策点（微文案、布局终态、触屏交互词汇等）；无则写「无」。逐条裁决落档，可追溯（裁决台账）。
- **指标对比附录**——飞轮派生提案（`parent_proposal_id` 指向源提案）必带：注册时填源容器标记指标基线，效果验证时填对比值留档；非派生提案无此段。

**一致性检查（批准前强制）**：每条验收都有纳入项满足、每个纳入项都服务于某条验收、验收两两不矛盾；冲突先解决再继续。

不自动提交；呈现提案，等待用户明确批准。

### Step 5：注册提案

```
createProposal { slug: "<slug>", title: "<title>",
                 rel_path: "proposals/<slug>/proposal.md" }
```

（mode 按会话预设自动填充，不透传。）
