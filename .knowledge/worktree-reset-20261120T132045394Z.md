# 共享 worktree 并发协作三判例：reset 丢基线恢复 × 环境会话差异 × 裂脑档案

来源：plugin-forge-combo 收口批复盘（2026-11，035 轮事故 + 1.24 环境定谳 + fix-38 裂脑根修）。

## 判例一：并发 reset 丢基线（035 轮）

共享 worktree 被并发会话 `reset moving to main` 覆盖——含全部在途修复的 302 提交链从工作树消失（悬空未并）。恢复配方：
1. **reflog 定锚**：`git reflog` 找回悬空 HEAD（对象未 GC 即可恢复）；
2. **detached checkout 恢复工作树**（`git checkout --detach <sha>`）——不动任何分支 ref，并发方提交无损；
3. **分支保护**：把基线链固化到命名分支（forge-combo-baseline-116）防二次丢失；
4. **两线归一**：合并进容器分支时冲突按「架构方向 + 迁移终位」裁决（新架构面 + 迁移终位对齐裁决方向），语义分叉（同功能两代实现）留人工合并裁决（AGENTS 5.1 口径）。
预防：多提案并发时**分 worktree** 或约定 HEAD 操作协调；陈旧 index.lock（零活跃 git 进程）可安全清除。

## 判例二：worker 会话环境特异（1.24）

worker 子进程内 electron GUI 主进程写临时 userData 拒绝访问 0x5（node 同目录写正常、主会话同二进制探针 WRITE_OK）——环境红定位先做**会话差异二分**：主会话最小探针复刻 → 绿则 worker 环境特异（台账挂账）→ 债务 spec 由主会话代跑取证（同机同二进制证据等价，如实标注来源）。

## 判例三：裂脑假档案（fix-38 ①）

e2e TMP 隔离链重定向 USERPROFILE → desktop main userData 派生落 USERPROFILE 分支 → carrier 落假档案、CLI 真实消费面用真档案——**「缺件 fatal」实录全出自裂脑假档案世代**，真实档案世代实测无 fatal。处方：carrier spawn 显式回传真实 APPDATA/USERPROFILE；「套件内不复现」类红优先怀疑双档案裂脑（复现差异族：手动链 vs 套件环境先 diff 环境变量派生链）。
