# 现象（同一容器两形态）

overview-dockkit-alignment 容器交叉评审连环捕获两形态同根因：
1. **bump 缺位**：t2/t3/t5 三个 commit 改 plugins/project 源码但未同步 bump package.json（AGENTS 5.2 明文纪律），仅 t1/t4 有 bump——版本账目断链。
2. **结算未提交**：f2-test-gaps 任务结算 success（自报质量门全绿、files 声明齐备），但三个测试文件在盘未 commit——worker 结算证据与 git 实况脱钩。

# 根因

worker 结算的默认证据链 = 自报（测试绿 + files 清单），不含「盘上 git 实况与声明一致」的机械核验；两形态都是自报面绿、实证面缺。质量门（compile/lint/test）全绿对这两类缺口零检出力——测试绿不证明产物已入库、不证明版本账目齐。

# 第三形态：重复 bump（同一包被多卡各 bump 一次）

plugins-remediation-m1-legacy-retirement（2026-11-28）：拆解时主会话在**每张**涉及 project 包的任务卡 context 里都写了「project patch +1，只 bump 一次」——每张卡的 worker 各自读到自己那条，各自 bump。project 0.42.2 → 0.42.3 → 0.42.4 → 0.42.5，三次跳，而 spec AC 写的是「各 patch 位加一」（终态应为 0.42.3）。

根因同族：**结算证据自报不核 git 实况**——每张卡自报「已 bump」，没人核「这个包在本批里已经被 bump 过几次」。

规避：
- 多卡同批改同一包时，**bump 指令只写一张卡**（通常是首张或末张），其余卡 context 写「本卡不 bump，由 X 卡承载」
- 或在收口门卡核对终态版本与 spec 口径，不一致时前向修正
- 每卡写「只 bump 一次」是无效指令——worker 只看自己那张卡，不知道别卡有没有 bump 过

# 规避判据（主会话收口核验清单）

- 主会话核收一律 `git status --short <范围>` + `git log -G '"version"' -- <pkg>/package.json` 实证，不信结算自报。
- 发现结算缺口不重派大任务：先亲验工作物真实性（实跑测试），工作物真实则只派**提交收口级** P0 微任务（指名路径 add、单提交、hash 回填）——本次 19s 收口实证该径成本极低。
- bump 纪律：源码改动 commit 时点自检「本 commit 是否改了 `packages/plugins/*/package.json` 之外的包源码」，是则 bump 同提交落。
- 多卡同包：`git log --format=%h -- <pkg>/package.json` 数本批内的 bump 次数，对照 spec 口径。
