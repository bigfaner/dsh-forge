# 共享 worktree 并发脱钩：提交落点核验拒收的处置配方

来源：input-history-migrate-and-upgrade / 1.1 结算落点拒收（settle-cwd-pin）/ fix 链轮次，2026-11。

## 症状族

worker 提交后结算报 `[settle-cwd-pin] 提交落点核验故障：容器检出不在分支上（detached HEAD）`——提交本体完好（git log --all 可见），仅落点无分支。

## 根因形态

多会话/多线共享同一 worktree 时，他线的 `reset`/`checkout <sha>` 会把检出切到游离态（reflog 形态：`reset: moving to main` → `checkout: moving from <branch> to <sha>`）。commit 本体不丢，落点核验（要求附着分支）拒收。

## 处置配方（按序）

1. `git reflog -12` 还原脱钩时序——区分「他线脱钩」与「自己操作残留」；
2. `git branch --show-current` 为空 + `worktree list` 核对本 worktree 归属分支；
3. 修复 = `git checkout <本分支>` 回附（若分支被他线 reset 到异常位，先核拓扑再动）；
4. 续跑前 `git status -sb` 确认 `## <branch>` 附着态；
5. 循环侧 `dispatchTask(resume: true)` 续跑——中断任务按任务描述接续，已落提交不重做。

## 纪律

- 禁以 `checkout -B` 强改分支指向来「修」脱钩——先 reflog 取证再最小动作；
- 并发线共享 worktree 场景，worker 提交前预检 `git branch --show-current` 空值即上抛（机械化工单见派生提案 task-loop-evidence-ledger-hardening）。
