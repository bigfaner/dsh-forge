# 同族第四例（真机 Console 探针定谳，2026-11-24）

overview-dockkit-alignment 容器 2.4 修口前：官方宿主 `forgeSpecs.list` 返回**双层信封** `{ok, value:{ok, value:[cards]}}`——plugins/spec 与 plugins/task-loop 的 `@Remote` 端点方法自返 Result 信封（`return ok(...)`），官方 gateway serve 层 `encodeRpcResult` 对 value 零检视再包一层。project 五族端点返裸值所以单层正常；client 侧 `invokeEnvelope` 只解一层，把内层 Result 当 cards 用。

真机三现象同根：概览点 Spec 子 tab 整片空白（`specStatusCounts` 遍历崩，非降级错误条）、Spec 列表异常、任务子 tab 恒空数据（键族聚合/git 归拢/lib 单源整条链其实工作正常，只是返回形状被第二层信封盖住）。

# 假绿根因（第四种形态：契约快照自洽）

前三次是替身/夹具形状与生产分叉。这次不同：**契约快照测试里 host 返什么、client 就按什么解**——两端在测试内自洽，永远绿，从未对过官方 gateway 真实的折叠语义。测试内手写的 serveWrap/clientUnwrap 包完自己解，是同义反复。

# 修口（经官方源码核销，非信注释）

- 端点成功返裸值；typed 失败 `throw new RemoteError(code, message, details)`（`@deepseek-ai/dsh-typert-protocol` 真类）。
- 承重假设：gateway `rpcFailure` 对 RemoteError 按**结构标记** `isDSHRemoteError === true` 保真折叠 code；普通 Error 折 `gateway/internal`（官方 `gateway/index.ts` rpcFailure 段 + `protocol/remote-error.ts` marker 判据）。
- 注意：project 五族 `unavailable()` 抛的是**普通 Error**，其 code 实际被折成 `gateway/internal`——typed RemoteError 是更强的新形态，不是「对齐 project 先例」。

# 判据（检清单第五、六问）

- **@Remote 端点禁自返 Result 信封**——serve 层已包，自返即双层。
- 回归钉必须经**官方真路径**（`remoteErrorOf` / 真 codec），禁测试内手写复刻；`failureOf` 须钉结构标记，只查 `typeof code === 'string'` 不够——带 `.code` 的普通 Error 测试仍绿、真机 code 丢失。
- 「反例必红」用**变异实验**验证而非信注释：本例把 RemoteError 退化成带 code 的普通 Error → 16 用例转红，加固才算成立。

# 真机取证方法（静态推演到极限时）

页面全局挂着 face 锚（`__dshForgeRemoteFace`），Console 直接调 `svc.list()` 打印 RAW 形状——一击定谳。本例静态推演链路每环都「理论上闭环」，是 RAW `{ok,value:{ok,…}}` 直接定位到层。
