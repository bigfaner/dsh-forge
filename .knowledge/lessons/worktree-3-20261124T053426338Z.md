# 现象

dsh-forge 官方宿主项目概览任务/spec tab 空数据翻车：会话 cwd = worktree 检出（如 .forge/worktrees/plugins），task-loop 单源 `deriveProjectKey(cwd)` 把循环任务落到 worktree 键（`Z-project-…-worktrees-plugins@hash`）；概览按项目身份查询 `keyOf(projectId)` = `deriveProjectKey(项目注册工作区根)` 主根键——**任务/spec 数据落 worktree 键、概览查主根键，两头各自都是设计正源，拼起来恒空**。

# 根因

dsh 生态存在两套并行的项目身份键：①会话侧 cwd 绑定派生键（task-loop 单源，worker 会话归属语义）；②宿主侧项目注册根键（概览/forgeProjects 查询语义）。worktree 会话的循环产物天然落①，项目级视图查②——快照读族不做键族归并就恒空。

# 修口方案（用户裁定 A，e99337af）

- **快照族按键族聚合**：list/stats/graph/follow 解析身份后扩为主根键 + forge.worktrees 注册面全部 worktree 键，多键合并（cards 按 taskId 去重保首见序、stats 八态求和、edges 按三元组显式去重、follow 逐键）；worktrees 注册缝缺席 fail-soft 回退单键 + 诊断留痕。
- **写路径零外溢**：claim/transition/detail/validate 等操作面维持单键 keyOf——聚合不进写路径。
- **forgeFs 特例留痕**：listDir 显式 dirPath 入参零身份键、facts 归属正确——零改动；快照族聚合不盲目外扩。

# 规避判据

- 凡「会话产物」对「项目级视图」的数据通道，必查两侧身份键是否同源；worktree 会话常态下默认错位。
- 聚合只做读快照族，写面单键不动；多键合并的每个去重分支必须配可失败反例（同 id 双键场景——worktree 检出含同 .forge 是常态不是边角）。
