## 判例

expert-builtin-redistribution 收口（2026-11-23）：13 任务中 7 个（编码/测试/文档类）结算 success 但**零提交**——改动全部滞留工作区；另有 5 个任务正常各自提交。结算面不校验 commit 与改动落盘，success 回执 ≠ 交付完成。

## 收口配方

1. 循环结束先 `git log <起点>..HEAD` + `git status` 对照结算清单——按任务号点名找提交；零提交任务的改动都在工作区。
2. 分批指名路径提交（迁移面/测试面/文档面分批）；**提交前必查 index 是否已有他人暂存项**——本次曾裹挟一个已暂存的无关删除（apps/host worktree-rpc.test.ts），靠 `git show --stat` 逐 commit 复核发现后 amend 剔除；add 指名路径不会防住已暂存项。
3. 质量门证据若采集于未提交状态，提交后须复跑针对性 vitest 复锚（被测快照 = HEAD 才算数）。
4. 环境面残留（临时引导层/复制副本）不在 git 面，单独清点删除。

## 归因提示

worker 零提交高发于 coding-refactor/test/doc 类型外的混合任务与长简报任务；评审阶段把「结算-提交对账」列为固定核对项可拦住。
