# 官方宿主集成红的多轮根因共同面——机械假设先行、源码核销滞后

## 事后归纳

host-integration-fixes 循环 9 轮 fix 链中，门 1（概览 tab 可见性）连续五轮红的根因演进：键控撞车 → 遮蔽方向反 → 页型注册面收编错位 → 订阅通道未核销 → 装配期取 face → 会话绑定语义错位。回看共同面：**每轮修的都是「对官方宿主机械的未核销假设」**——dockkit 页型注册与 keyed body 两段的双段语义、插件侧 slots face 的 subscribe 可用性、官方会话-工作区绑定时点，均为假设先行、真机红后才回头核销官方源码。

## 教训

- AGENTS 1.1「承重假设依赖前必须到官方包源码核销」在插件 UI 装配面同样铁律：页型/keyed 两段注册、订阅面形状、inject face 到达时序，写方案前逐一到官方 renderer 源码核销（本案后期的 slots-keyed-probe 探针法是对的，但应在第一轮红之前做）。
- 真机红的排查顺序应为：先官方宿主差异面（dev 宿主对照复现分域）→ 再我方注册链——r2 前多轮在产品侧空转的根因是未先分域。
- 修复期反复红时，停下来做一次性全机械核销探针（probes/），比逐轮盲试便宜（本案例探针后连收三门）。
