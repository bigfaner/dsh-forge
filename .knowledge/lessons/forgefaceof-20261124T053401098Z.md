# 现象（同族两例，同容器连环暴露）

overview-dockkit-alignment 容器：
1. **forgeFaceOf 漏网**（真机翻车）：G3/G1 新增 forgeSpecs/forgeDirs 消费走 `seam.resolver()`，生产 resolver = `forgeFaceOf` 归一（仅五硬族）；单测自装替身 resolver（stub face 自带两族）全绿——真机「官方 forge remote 面缺席」。修口 = forgeFaceOf 可选族归一（FORGE_REMOTE_OPTIONAL_NAMESPACES 在场即并入、缺席不门控、inject 边不加外插件硬依赖）。
2. **listDir 契约假设未核销**（评审捕获）：1.2 复用 forgeFs.listDir 列举 spec 目录文档——既有契约「仅子目录入列、文件不入列」，纯文件目录真机列空，用户需求不可达。复用前零契约 pin 阅读。修口 = 契约扩展文件入列（kind 可选缺席按 dir 解释，向后兼容）。
3. **同型结构自查救场**（评审 E）：f5 键族聚合的 lazyWorktreesFace 组合根（三级劣形收窄）零测试——评审按 forgeFaceOf 漏网同型结构点名，补组合根 pin（两插件复制实现以 pin 对锁+留痕理由收敛欠账）。

# 根因

替身（stub resolver / fixture）形状由测试自定，生产组合根（归一函数、端点契约、装配缝劣形收窄）是另一份代码——两者无机械对锁时静默分叉；测试全绿只证明「替身世界自洽」。

# 规避判据（检清单）

- 测试替身必须**复刻生产组合根的归一/收窄函数产物形状**：要么替身走真实归一函数（生产形状全链测——forgeFaceOf→install→client），要么对归一函数本身配 pin（三级劣形逐级反例）。
- 复用既有端点/通道前**先读契约 pin**（DTO 注释 + host typert pin 测试），契约假设未核销不得开工。
- 评审检清单固定问一句：「归一函数/组合根取法本身有没有测试触达？替身是否绕过了它？」
