# 现象（覆盖真空族——评审补齐三类）

overview-dockkit-alignment 评审 B 五关口复核发现本循环新增面三条覆盖真空，均属「新代码面交付时零/弱测试」同族：
1. **P1-a 新表行零 pin**：typert-transport SEG_NAMESPACE 新增 `specs: 'forgeSpecs'` 行 + rpc specs 切片 invokeRemote 路径零测试触达——既有测试只走 projects 通道与整 face 缺席，恰好没测「新增的一行 + face 在场但单边缺席」的可选边降级。
2. **P1-b 新文件零测试且同族不对称**：host/tools/register.ts 全文件零测试（resolver 三腿解析 + 缝缺席降级），而同族 forge-paths 侧有同构「缝缺席」测试——同族成对交付面只测了一半。
3. **P2-c 装配闭包间接覆盖**：createForgePathsToolFace 装配闭包（reflectOf 惰性现查 + onDeclareDiag 桥接）仅经下层函数间接覆盖，接线层零直测。

# 判据（评审检清单——新增面三问）

拆解/评审新增代码面时逐面问：
- 新增「表行/映射行/通道」→ 必须有触达该行自身的 pin（整面测试不算）+ 单边缺席降级行为测试；
- 新文件与既有文件同族（如 pairs：forge-paths/register）→ 同构测试成对补齐，不允许「一半有一半无」的不对称；
- 装配闭包/接线层 → 下层函数覆盖不算覆盖，惰性求值/桥接需直接单测。
