# 判例：拆解漏承接提案触点表交付项（bug 92686d15 → a968006d + 欠账变体 4d34bf0b/90562813）

> 版本 2：同族三次复发后的扩展——新增「时序依赖面」漏法与「欠账闭环」执行期变体；对账门配方补全。

## 现象（三起同族）

1. 首发拆解漏 3 项：横切追加（createSpec 挂链）无归属任务、仅触点表出现的交付（inventory 改写）漏承接、散文要求（emitDiag 埋点）未落 AC——独立 spec-reviewer 对账才发现。
2. 复发：v2 六态 CHECK 落地与 M3 现役动词 v1 四态值域的**跨任务时序依赖**无任务承接（重接线），1.3 落地即阻塞；v1→v2 存量行值映射正本缺席。
3. 执行期变体：worker resume 如实上报欠账后无人承接，循环带欠账全绿收口（详见 worker-success 条目）。

## 根因

拆解映射单位 = 设计文档章节，交付承诺单位 = 触点表 + 时序依赖 + 全局纪律——三个枚举面不同源且无对账机械。漏法形态学（五类）：
- **横切缝**：跨章节边界的小追加，两头不认领；
- **无章节缝**：仅触点表行、无设计章节的交付；
- **散文缝**：藏在设计文档步骤散文里的要求（埋点等）；
- **时序缝**：新底座 + 既有消费方的适配（迁移 CHECK ↔ 现役值域、值映射）——「底座任务 AC 须含消费方回绿门」或单列重接线任务；
- **欠账缝**（执行期）：上报不闭环。

## 规避（拆解收尾对账门，两清单 + 一纪律）

1. 正反向对账：proposal 触点表逐项 ↔ 任务并集 AC 双向核对；识别「新底座 + 既有消费方」形态时显式排适配任务或并入底座 AC 回绿门。
2. 全局纪律 AC 注入 checklist：埋点/质量门 run-once/版本 bump/收尾卫生逐任务核对。
3. 欠账闭环纪律：循环收口前扫 resume 提取欠账清单，显式处置。
4. 事后独立评审用的正是这两张清单——前移到拆解当场即缺口当场暴露。
