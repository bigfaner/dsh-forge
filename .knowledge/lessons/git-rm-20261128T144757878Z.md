# 删壳包的三面清点

## 问题

退役一个壳包（如 `packages/contracts`、`packages/path-key`）时，只做「`git rm` 包目录 + 改指 import + 同步 lock/tsconfig」会漏三类东西，且每一类都要靠评审或全量门才暴露：

1. **包源码树内的测试**：`git rm -r packages/<pkg>` 会把 `src/*.test.ts` 一并删掉。被测真源若已迁到别处（如 `lib/api/src`）继续存活，测试却没有跟过去——覆盖断链。判例：contracts 的 6 个测试（592 行，含「契约层零逻辑」结构守卫）随壳删除，`lib/api/src` 无对应测试（bug `b0a1d9de`）。
2. **文档与注释**：conventions 正本的工件清单 / 测试分池表（bug `110bfa23`）、lib 源码头注释（bug `b6b113db`）——同族 `20dea95d` 在一个批次里出现三次。
3. **盘面残留**：`git rm` 后被忽略的构建产物（`dist/`）仍留在盘上，`Test-Path packages/<pkg>` 为 True，规格 AC「目录已删」字面不成立。

## 清点步骤（删壳前）

- 列出包树内全部 `*.test.ts`，逐个决定去向：随真源迁入新位（修 import 路径）/ 结构守卫按新位现状重定允许清单 / 确属被测物消亡才退役并记理由；
- 旧包名全仓 grep：`git grep -n "<old-pkg-name>\|@dsh-forge/<old>"`，逐条分类为「现存陈述（必改）」与「历史叙述（保留并列出）」；
- 删包后用 `Test-Path` 核对目录不在盘上，残留的忽略产物一并清掉；
- 打包脚本的机检（如 package-release 的成员锚校验）同步：成员是否带某目录应以其 `package.json` 声明为准，不无条件要求。

## 测试判例

- 退役理由：contracts / path-key 包内测试随包删除；其中 5 个真源测试迁入 `lib/api/src`，定位守卫按 lib/api 现状重建（提交 `e1e381d9`）。
- 覆盖真空（评审发现，已补）：迁入真源的测试覆盖；「契约层定位」结构守卫。
