# 现象与翻车

容器 worktree（如 `.forge/worktrees/plugins`，分支 plugins）与主仓检出（`Z:\project\dsh\dsh-forge`，可能停在 main 旧快照）是**两份独立工作树**。本仓多 worktree 并行是常态——主仓检出随时落后于任一 worktree 分支。

判例：md-mermaid-plugins-migration 评审轮，proposal-reviewer 与 architect **两路专家先后**误读主仓 main 快照，产出相反结论（Blocker-1「productPluginPackageLinkPath 无 /plugins 分支会产出断链」）——实况 worktree 源码 `runtime-packages.ts:84` 分支在场（project/spec 先住户表项实证），Blocker-1 经质询对证撤销。整轮浪费一次质询 + 一份报告修订。

# 规避

- 评审/深挖任务简报**显式携带 worktree 绝对路径 + 「勿读主仓检出」禁令**（本仓后续任务简报已成惯例）。
- 证据行号与文件内容对不上时，先核「读的是哪棵树」（`git -C <路径> branch --show-current`）再下结论。
- 质询对证是有效收口手段：两路独立评审产出相反结论时，优先怀疑评审对象错位而非实现。
