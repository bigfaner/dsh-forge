# 现象

expert-squad client 束（浏览器面）import lib-util（node:fs/crypto/path）——bundle-client esbuild 报「Could not resolve node:fs」四错，freshness 门中止整条打包流水线。诱因 = 跨包收口提交把 host 面纯函数（RemoteResult 信封解包）收口到 lib-util 单源时，client 面两消费点未隔离 node 依赖。

# 根因

client 束 = 浏览器运行面，node 内建真实缺席——esbuild 报错只是把运行时必炸提前到构建期。**platform:node 标志是错药**：构建通过、运行时必炸。

# 规避判据

- client 面收口进共享 lib 的纯函数必须**零 node 内建依赖**（含传递依赖）；node 依赖的 host 面函数不进 client 可达图。
- 修法 = client 侧本地内联纯函数（逐字等价仅落位迁移）或挪 host 半；禁 platform:node 掩盖。
- 收口跨面单源前先问「这个函数被谁 import」——host-only 函数进共享 lib 时应分层（node 子路径导出 + 浏览器安全根入口，lib-path project-root 已有先例）。
