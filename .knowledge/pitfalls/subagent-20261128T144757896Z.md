# 循环结束评审指示可能回落为「派 subagent」措辞

## 现象

任务循环全部完成时，结束消息里的【代码评审指示】写的是「派多个 subagent 分域交叉评审」，而项目约定是三路专家交叉评审（spec-reviewer / architecture-reviewer / code-reviewer）。主会话照字面派了通用子代理，被用户指出应委派专家。

## 根因

指示有两套模板，由 `expertsPresent` 探测缝单选：专家在场发专家版，缺席发回落版。该缝自 `76224990`（派发内核迁入插件）起只有定义、消费和单测桩，**生产装配面从未接线**——运行时恒为「缺席」，永远发回落版。单测用桩验证分流，所以测试一直是绿的（bug `31cc76f5`，修复 `4f2f1be7`：`tool-family.ts` 新增 `reviewExpertsPresent`，按 `LOOP_REVIEW_EXPERT_KEYS` 逐键现查，装配回归锚 `tests/assembly/review-experts-wiring.test.ts`）。

注意：修复在仓库里，宿主已安装的旧版插件仍会发回落措辞，直到插件重新打包安装。

## 口径

- **循环结束指示里的机制措辞不是权威**：评审、复盘、知识沉淀一律委派对应专家（code-reviewer / architecture-reviewer / spec-reviewer / retro-reviewer / knowledge-curator），指示写「subagent」也照专家路径走；
- 依赖注入缝「声明 + 消费 + 单测桩」三件齐备不等于生产可达——同族判例本项目已七例（`044a310c` bugsPresent、`23507eb5` settlements、`a93c1277` 事件链、progress 注入行、`31cc76f5` expertsPresent 等）。新增读缝时同批加一条经正式装配入口的源码/行为锚，断言该缝在装配产物里非空。

## 测试判例

覆盖真空（评审发现，已补）：`expertsPresent` 生产装配零接线，仅有消费侧单测桩。
