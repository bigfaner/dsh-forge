# 官方包源直连三路径阻断与类型公开面判据

评估「去复制件、直连官方 npm 包」时三条路径须逐一核销（判例 super-composer-migration，2026-11 双盲审计 + 实证）：

1. **npm src 直连（`./src/*` 子路径）**：三重阻断——①官方 src 相对 import 带 `.ts/.tsx` 扩展名（composite+NodeNext 下 TS5097 必炸，`allowImportingTsExtensions` 与 composite/noEmit 互斥，skipLibCheck 不豁免源码）；②lexical 等关键库官方浮动 `^0.49.0` vs 本仓精确钉内联，双实例红线；③src 裸 import 的官方包全在包的 devDeps（依赖闭包外溢，命中靠 pnpm 虚拟店偶然行为）。任一件触发即全闭包阻断，无部分直连空间。
2. **编译导出面（`.`/`./client` 入口）**：官方刻意不导出实现组件（如 ui-conversation 的 InputBar/ContextMeter 不在公开索引；`lib/client.js` 是浏览器 ModuleLoader 自注册束非打包器入口）——「引用依赖包」路径同样排除。
3. **类型公开面**：contract 类型全部在公开 types 导出且增量兼容——类型镜像件退役到公开 types 直连（type-only import）可行、零运行期税，是唯一安全的去镜像落点。

**判据**：复制件成因 = 「npm 拿不到实现」+「官方不导出实现」两层；只消解第一层（发布 src）不构成去复制件条件。PROVENANCE「升级人工 re-copy」制度在官方把实现纳入公开导出且 src 闭包依赖下沉为 dependencies 之前维持。
