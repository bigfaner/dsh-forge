# 文档族专家档案无 pwsh：循环文档任务无法提交

## 事实

任务类型到默认专家的映射（`lib/api/src/dto/forge.ts` 的 `DEFAULT_EXPERT_MAPPING`）：

| 任务类型 | 默认专家 | 档案 tools 是否含 pwsh |
|---|---|---|
| `doc` | tech-writer | 否 |
| `doc-drift` | drift-auditor | 否（有 write） |
| `doc-review` | doc-reviewer | 否 |
| `doc-summary` | summary-distiller | 否 |
| `doc-consolidate` | doc-consolidator | 否 |

这些专家能读、能改文件，但**不能执行 git commit、不能跑门禁、不能取 commit_hash 回填台账**。循环结算要求提交与质量门，于是 worker 把内容做完后只能 `blocked` 上浮。

## 判例

容器 `plugins-remediation-m2b-iron-rule-settlement` 的 fix-6（type=`doc-drift`）：drift-auditor 完成两份 conventions 正本修订后 219 秒即阻塞，原因为「无 shell 工具不能 commit」；主会话核对 diff 后代提交并结算。bug `dc63b938`（修复待裁决：给文档专家补 pwsh / 派发面前置拦截 / 维持主会话代提交）。

## 临时口径（bug 修复前）

- 需要落盘并提交的文档改动：派 `coding-fix` 等带 pwsh 的类型，或在简报里指名带 pwsh 的专家；
- `doc-drift` / `doc-review` 只用于「只审计、产报告」的任务；
- 已经派出去的：worker 阻塞后由主会话读 diff、代提交、回填 bug、结算，不重派。

## 测试判例

覆盖真空（已发现）：类型 → 专家工具面的一致性没有任何机械校验，派发后才发现不匹配。
