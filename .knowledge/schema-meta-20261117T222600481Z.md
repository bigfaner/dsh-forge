# 共库多插件 schema_meta 分域版本线机制

## 裁决：分域版本线，锚域不锚表集合

多插件共写一个 SQLite（forge 集成形态 forge.db，域前缀分表）时，schema 迁移版本线必须**按域分行**——schema_meta 形状 (domain, version) 复合主键，各插件 openDatabase 传 domain 选项、版本门只读自身域版本线；缺席 domain 保持全局单版本线语义零变化。

## 为什么不是全局版本线（复发族判例）

全局单版本线下，任一插件先行迁移抬升版本号，其余插件开库即拒（「版本 2 超支持上限 1」）。plugin-forge-combo 循环实证该族**三度复发**：
1. bug e62f3458：spec/knowledge 先迁移抬库 → task-loop 拒开（全局判读）；
2. bug 34645ce2：knowledge 抬全局线 → spec 无 domain 读法次 boot 拒开；
3. （前置根因）四件各自持有一份版本判读/建表实现——修复前判读点分散是复发温床。

终态配方（单源下沉）：
- 机制单源在 `@dsh-forge/lib-db` openDatabase（domain 选项 + 分域 schema_meta/migration_digests 复合主键 + 指纹认领归位）；
- 消费方（project/spec/task-loop/knowledge）只传 domain 参数，**零本地版本判读**；
- 旧形状整表重建 + 指纹认领兜底；版本门只判读本域线。

## 规避纪律

- 新持库域接入共库时：禁复制任何一件的版本判读/DDL 模板（「复制即带病」）——一律走 lib-db domain 选项；存量四件 v1 迁移中的旧形状死语句已列为清理项（恒 no-op 但即温床）。
- 正本：主提案 plugin-combo-rearchitecture R3-dba 处方「schema_meta 分域版本线 + 迁移串行单点，版本线身份锚域不锚表集合」。
