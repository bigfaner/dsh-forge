# 叙述消息样例全谱——run-tasks-host-command

> 从 [implementation-blueprint.md](implementation-blueprint.md) §3 抽离（2026-10-11）。
> 主会话叙述消息全部形态——notify 模块实现规格与测试锚。**通道分流（decisions #28，2026-10-11）**：常规进行事件（①-⑫）经 inject() notice 注入——零模型回合（不唤醒会话），对话流 context 行+≤120 字符摘要；终局事件（⑬-⑰，每循环 1–2 条）经 followup() 完整消息；裁决问询不经主会话。文案规格通道无关。

## 统一骨架与文案原则

- **通道分流**（用户裁决 2026-10-11，decisions #28）：常规进行事件（样例 ①-⑫）→
  inject() **notice 形态**——不唤醒会话（**零模型回合**）、对话流渲染 context 行
  （producer 归因）、折叠行 ≤120 字符摘要（boundContextSummary 截断）、展开全块、
  详情落盘带路径；模型于下次自然回合作为前置上下文消化。终局事件（样例 ⑬-⑰，
  每循环 1–2 条）→ followup() 完整骨架消息（#24/#27 全套规则在此适用）。裁决问询
  不经主会话（既定）。
- **骨架**：类型行 `[forge·X]` / 任务源 / 任务键 / 事实（摘要）/ 剩余 / 详情路径
  （异常时）/ 系统动作（异常时）/ `下一步动作:` 行（每条必有，末行）；所有行
  **key: val 单冒号格式，值内零冒号**（用户裁决 2026-10-11——值内用逗号/破折号，
  不与键冒号混淆）；
- **下一步动作行**（用户裁决 2026-10-11 定稿——由"提示/指示"两行方案两次修订而来，
  见 decisions 27）：**单行合并**，封闭两值——`无`（不需要任何处理）或
  `提示用户"<指令文本>"`（需要转达时）；**动作语义自定向**：动作宾语在用户侧
  （"提示用户执行 X"——agent 执行的是"提示"这一转达，X 由用户决定是否执行），
  agent 不会把 X 据为己有——杜绝 agent 自动执行指令导致的消息→执行→消息无限循环；
- **文案原则**（用户裁决 2026-10-11，全面排查）：**简要、直观、明确——不增加用户与
  agent 心智负担**。用户视角动词；机制词零出现（"处置代理""宿主循环""adopt""退避"
  "follow-up"等——机制细节见 blueprint/decisions，消息面不出现）；用户只需知道三件
  事：**发生了什么 / 系统做了什么 / 要不要我管**；
- **行动指示**：封闭枚举、全部"无需处理"族（agent 零猜测/不闲聊/不自作主张；控制权
  不经叙述传递）——含防自动执行变体；
- **长内容落盘**：`logs/<slug>/<taskKey>/<序号>-<事件类型>/`——一个任务一个
  文件夹、一次问题事件一个子文件夹（如 `001-blocked/`：自增序号+事件类型后缀；同一
  事件的 error.log/settlement.json/triage.md 内聚，多轮问题不混档；多模态可扩展）；
  叙述仅带本次事件子文件夹路径；
- **分级呈现三档**：叙述摘要 / 事件子文件夹（人/agent 按需读）/ 裁决问询全文。

## 一、常规路径

### ① 启动·从头执行（notice）

```
[forge·启动] 任务源: m2-pipeline（feature）
状态: 从头执行 — 按依赖顺序逐个执行（待执行 6）
下一步动作: 无
```
