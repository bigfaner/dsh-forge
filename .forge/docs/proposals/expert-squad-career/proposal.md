# 专家履历档案：派发工作记录与迭代优化事实

> 前置：[expert-squad](../expert-squad/proposal.md)（专家团插件，档案创建/管理/取用）。本提案承接其剥离项——履历是派发链产物，须待委派侧（使用方，expert-squad-forge）落地后才有数据源。

## 1. 需求

专家被取用派发后，其执行过程（哪些任务、委派的主会话与子会话、产出）散落在会话流里，无法作为**迭代优化专家人设**的事实依据。需要一份 append-only 的履历档案，回答：这位专家做过什么、效果如何、人设该怎么改。

## 2. 方案（概要，随委派侧落地再细化）

- **数据源**：使用方派发链在委派时点写入履历事件（任务摘要、主会话/子会话引用、终态），存储归专家团档案层或独立存储——归 tech-design。
- **消费**：面板详情查看履历时间轴；人设迭代时以履历为事实依据（哪些任务频繁失败 → 修人设/白名单）。

## 3. 改动影响范围

- 专家团插件：履历写入/查询缝（或由使用方直写档案层）。
- expert-squad-forge：派发时点写入履历事件。

## 4. 验收方向

1. 一次委派在履历中留下任务与主/子会话引用。
2. 面板详情可见履历时间轴。
3. 履历不阻断派发主链（写失败降级不阻塞）。
