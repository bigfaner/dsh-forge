# dsh-forge M3.5 — UI Functions

> Requirements 层：定义 UI **要做什么**。基线 = M1 知识视图现状（工具栏 = 范围 Pill + 搜索框、域树左轨 224px、auto-fill 卡片网格、详情抽屉——现状无状态维）。M3.5 交付最小面：**全部在浏览页签内扩展（信息架构零扩张——现有页签不动）** + 左栏徽标 + 上游内建模式选择器引用；状态 chips / 提取 chip / 域树 chip / 上下文条 / 待复核徽章为既有页面上的新增件。视觉语言统一：chip = 状态标记，域树节点（域级待确认）与知识卡片（条目级 status）同语言。

## UI Scope

知识视图 · 浏览页签（existing）内四组扩展——待确认状态视图（状态 chips + 队列批量操作）、域树待确认 chip 就地裁决、域上下文条、待复核徽章与处置；工具栏「从项目提取」chip 与源 / 范围配置（existing·工具栏）；左栏知识库入口待确认徽标计数（existing·左栏）；新会话模式选择器「知识沉淀」hero chip（上游内建，预设声明后自动出现——零自研，仅引用）。共 7 个 UI Function，无一新增页签 / 页面。

## Navigation Architecture

- **Platform**: web

### Primary Navigation

不变：左栏（官方 ui-sidebar 壳）品牌行 + PanelRow「知识库」（M3.5 增徽标计数，不加行）+ 工作区浏览区；中区（官方 main 面板互换）会话 ⇄ 知识 ⇄ hero，知识视图页签结构不动；右栏 dock 不动。新会话模式选择器 = 会话 hero 面内建件（上游机制，M3 已交付门控）。

### Secondary Pages

| Page / 浮层 | Entry | Return |
|------|-------|--------|
| 待确认状态视图（浏览页签内过滤态） | 工具栏状态 chips 点「待确认」档 | 再点 chips / 切域 / 清除过滤 |
| 域 chip 裁决浮层 | 域树「待确认」chip 点击 | Esc / 取消（裁决动作即提交点） |
| 源与范围配置浮层 | 工具栏「从项目提取」chip 点击 | Esc / 取消 / 确认即发起会话 |
| 详情抽屉（existing） | 卡片点击（M3.5 增待复核徽章与处置入口） | Esc / ✕（既有行为） |

> 无新增 dock 页签、无新增路由——一切交互在知识视图浏览页签与两个浮层内闭合。

## UI Function 1: 待确认状态视图（浏览页签内 · 队列形态）

### Placement

existing-page: 知识视图 · 浏览页签——工具栏状态过滤 chips（**新建维度**——现状仅范围 Pill + 搜索框；首档 `unconfirmed`）+ 进入该过滤即队列形态（卡片网格切换为可勾选队列）。

### Interaction Flow

1. **进入**：工具栏点状态 chip「待确认」→ 列表过滤为 `unconfirmed` 条目 → 呈队列形态（行 / 卡片带勾选位）；再点同一 chip 退出回普通浏览。
2. **批量操作**：单条勾选 / 域级全选 / 跨分页保持选择集 / 分页（服务端分页——千条级不卡顿）；操作条随选择集出现——**确认入库**（批量翻转 `draft`）/ **改域** / **编辑摘要** / **三分文标记**（合并候选三选一最简版）。
3. **单条过**：行内逐条确认（日常顺手沉淀单条场景——Story 3）；可改域 / 编辑摘要后确认。
4. **计数联动**：确认后条目移出队列；左栏徽标计数递减（UF-4）。
5. **空态**：无待确认条目时 chips 呈 0 计数禁用态（0 计数 chip disabled——沿 M2 概览 chips 先例）；不显引导文案（空队列非错误）。

### States / Notes

- `unconfirmed` 条目在**普通浏览态（未过滤）也可见**（文件先行——浏览可见、召回不可用是准入语义，非隐藏语义）。
- 未确认条目不参与 `search` / `read-abstract`（服务端 status 过滤，UI 无第二套过滤逻辑）。
- 批量交互细节（分页粒度 / 全选范围）= 设计期定缝项 14。

## UI Function 2: 域树待确认 chip 与就地裁决

### Placement

existing-page: 知识视图 · 浏览页签——左轨域树（~224px）目录名右侧「待确认」chip；点击就地展开裁决浮层。

### Interaction Flow

1. **挂起条件（派生）**：目录含 `unconfirmed` 条目且**无已确认条目**才挂 chip——混合目录不挂（已确认域的新条目走 UF-1 队列，不在此裁决）。
2. **点击 chip** → 裁决浮层，**对照呈现两侧描述**（均读 DB）：拟建域与最接近的既有域——对齐判断更准。
3. **三选一裁决**（均经能力面）：
   - **确认** → 域转正，域内全部待确认条目一揽子翻转 `draft`（一揽子裁决降低逐条负担）；chip 消失、徽标递减。
   - **对齐既有域** → 选定目标域 → 条目移动、status 不变（仍待条目级确认，移入 UF-1 队列）；目标域选择交互 = 定缝项 13。
   - **拒绝** → 物理删除域内未确认条目文件 + 空目录清理（无墓碑）；确认对话防误删（一次确认，不可撤销——重提由增量重跑兜底）。
4. **视觉语言**：chip 与卡片 status 标记同语言（状态标记一律 chip 形态）。

## UI Function 3: 域上下文条

### Placement

existing-page: 知识视图 · 浏览页签——工具栏之下、卡片网格之上（位置线框如下；呈现场所 = 卡片区上方单行条，域树内联与 tooltip 均已否决——描述偏长挤占树宽 / 发现性差触屏不友好，用户裁决 2026-10-06）。

```text
┌────────────────────────────────────────────────────────────┐
│ 知识视图 · 浏览页签                                          │
├─────────┬──────────────────────────────────────────────────┤
│ 左轨224px│ 工具栏   [🔍 搜索] [状态chips] [✎ 从项目提取]      │
│         ├──────────────────────────────────────────────────┤
│ 域树     │ ★ 域上下文条 ★ ←── 位置：工具栏之下、卡片之上      │
│ ▸ 编程/  │ │ 编程/ — Java 服务端开发约定与经验（≤50字）      │
│ ▸ 测试/  │ └────────────────────────────────────────────┘ │
│         ├──────────────────────────────────────────────────┤
│ (纯导航, │ 卡片网格（auto-fill 多列；域描述永不作卡片）      │
│  无描述) │ ┌─────┐ ┌─────┐ ┌─────┐                          │
│         │ │卡片 │ │卡片 │ │卡片 │                            │
│         │ └─────┘ └─────┘ └─────┘                          │
└─────────┴──────────────────────────────────────────────────┘
出现时机：仅选中具体域；「全部知识」态不显示此条。
```

### Interaction Flow

1. 选中域树具体域节点 → 上下文条呈现该域描述（DB 存储；≤50 字单行承载）。
2. 「全部知识」态（未选域）不显示此条。
3. 无描述的域（外部创建与存量域）**不渲染上下文条**——不报错、不显占位文案（缺省定案 2026-10-06）。
4. 描述编辑经确认面 / 写入面（本里程碑不在域树内联编辑）。

### States / Notes

- 域描述**不作为知识卡片**出现在卡片网格（仅呈现于上下文条）；域树节点本身纯导航、不内联描述。
- 描述只存 DB（用户裁决 2026-10-10——`_domain.md` 文件形态退役，知识目录零产品自有文件）；描述长度 ≤50 字为写入面校验上限（拒收 vs 截断 = 定缝项 5 残留）。

## UI Function 4: 左栏知识库入口待确认徽标计数

### Placement

existing-page: 左栏「知识库」入口（PanelRow）——入口名右侧计数徽标（总纲「待审核徽标」既定设计**前移启用**；M4 审核台复用同位）。

### Interaction Flow

1. 存在 `unconfirmed` 条目 → 徽标呈计数；计数 = 0 → 不渲染徽标（零值不占位）。
2. 产出条目（agent 落盘）→ 计数 +1；确认 / 拒绝 → 计数递减；域一揽子确认 → 批量递减。
3. 点击入口行为不变（切知识视图）；徽标仅计数提醒，不新增跳转语义（积压治理 = 常显提醒，非通知机制）。

### States / Notes

- 计数口径（仅 `unconfirmed` 还是含其他待处理态）= 定缝项 15；首档 = `unconfirmed` 条目数。

## UI Function 5: 「从项目提取」chip 与源 / 范围配置

### Placement

existing-page: 知识视图 · 浏览页签——工具栏右缘「✎ 从项目提取」chip（产品自绘配置浮层）。

### Interaction Flow

1. 点 chip → 配置浮层：**源与范围**——结构化文档 / 现状代码 / git 历史（可选可裁剪；空 / 浅 git 仓走降级路径）。
2. 确认 → 发起编排（riding M3「打开新会话」绑定入口先例）：blank 会话 + 选择沉淀模式 + 以配置合成首消息预填（首消息自动发送 vs 预填不发送 = 定缝项 10）→ 会话建立。
3. 取消 / Esc → 关闭浮层，零副作用。
4. 提取空结果（空源项目）→ 会话内反馈空结果（非错误态）。

### States / Notes

- chip 仅在**当前项目已注册**时可用（知识库与项目绑定不变——工具按注册项目解析）。
- 配置合成格式沿用 M2 dispatchPrompt 先例（定缝项 10 裁决格式细节）。

## UI Function 6: 待复核徽章与处置

### Placement

existing-page: 知识视图 · 浏览页签——知识卡片（热度徽章同位语言）与详情抽屉。

### Interaction Flow

1. 浏览面打开时读取时计算双信号（`updated` 陈旧度 + 热度骤降对比窗）→ 超阈值条目卡片与详情呈**待复核徽章**；未超阈值不标注（噪声纪律）。
2. 徽章无点击展开语义（被动标记，非通知）；处置入口在**详情抽屉**：
   - **发起修订** → 发起沉淀模式重跑该域（进入提取链，域范围预填）；
   - **归档** → status 翻转 `archived`（经能力面；一次确认）。
3. 归档后条目退出默认浏览（按 status 过滤语义），不物理删除。

### States / Notes

- 双信号阈值与对比窗 = 定缝项 11；读取时计算、无后台 watch（总纲 SC2 纪律——UI 不引入任何监听机制）。
- 徽章与置信降权（M5）语义分工：本里程碑徽章仅为编辑性提示，不参与排序。

## UI Function 7: 新会话模式选择器「知识沉淀」（上游内建 · 引用）

### Placement

existing-page: 会话 hero 面模式选择器（上游内建 hero chip）——预设声明后自动出现，**零自研 UI**；门控已由 M3 前置解（`ui-settings` 工厂开启行首启预置 + 老用户增量补行）。

### Interaction Flow

1. 新会话 → 模式选择器出现「知识沉淀」（出厂第三预设声明即获座位）。
2. 选定 → blank 会话以沉淀模式建立（blank-session 锁：一会话一模式；恢复 / 分叉按投影重建同款组合——M3 已实证语义）。
3. 其余交互（会话内执行、分批、续跑）= 沉淀模式会话行为面，非 UI Function（见 PRD 流程一）。

### States / Notes

- 本 UF 仅为登记引用——交付物是预设工件（组合 + persona + 技能行），UI 面零改动。
- 沉淀模式运行时工具面不含 forge task 命令 tools（SC-3 运行时断言，对齐 M3 SC-2 强度）。
