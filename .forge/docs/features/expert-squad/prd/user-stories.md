# 用户故事：专家团插件

角色：终端用户、上层应用开发者。

## 终端用户

### US1 对话式招募专家
**当**我对主会话说「招募一个代码评审专家，工具只留读写与检索」**时**，我要它经专家团完成建档，**以便**不写文件、不碰源码就得到可委派的专家。
- Given 专家团插件已启用
- When 我在主会话发出招募指令（岗位、信条、工具白名单）
- Then 专家档案落专家目录并出现在面板列表；委派入口立即可用

### US2 文件直编热刷新
**当**我直接编辑专家目录里的 `.md`（改信条、换工具白名单）**时**，我要改动在不重启的前提下于下一次派发生效，**以便**像改文档一样调优专家。
- Given 专家 X 已存在且此前可派发
- When 我修改其 `.md` 并保存（含模型经 edit/write 修改）
- Then 5s 内新内容生效；下次派发按新履历/白名单执行

### US3 面板详情查看与编辑
**当**我在面板点开某专家卡片**时**，我要在 Dialog 中查看其履历与白名单，并可切到编辑模式修改岗位/信条/白名单，**以便**不读原始 `.md` 就能了解并维护这位专家。
- Given 专家 X 存在
- When 我点击 X 的卡片，在 Dialog 中查看并点 [编辑] 修改信条后 [保存]
- Then 查看态呈现履历时间轴与白名单 chips（不暴露 frontmatter）；编辑态预填字段，保存校验（裸 `{{`、空岗位字段级报错）通过后写档案、Toast 热刷新生效、卡片同步刷新

### US4 对话式委派任务
**当**我在主会话向某专家委派任务**时**，我要它在隔离子会话中按其履历与工具白名单执行并回显成果，**以便**主会话上下文不被消耗且专家恪守本职。
- Given 专家 X 启用、工具白名单 W
- When 我在会话中委派任务 T 给 X
- Then 子会话按 X 的 persona 执行 T；W 外工具不可见且调用被拒；成果回显于会话流

### US5 追问续聊
**当**专家回传成果后我追加追问**时**，我要在同一专家的上下文内继续对话，**以便**不用重述背景。
- Given US4 的委派已完成
- When 我对该专家发追问
- Then 续聊发生在原子会话上下文内，回复能复述该次任务的关键经过或结论（证明读到同一上下文，非重新作答）

### US6 禁用专家
**当**我禁用某专家（对话或面板）**时**，我要它立即不可被取用与派发但档案保留，**以便**临时下线而不删除积累的履历。
- Given 专家 X 存在
- When 我禁用 X
- Then 取用 API 对 X 返回不可用、派发被拒；重新启用后恢复

### US7 坏档案不扩散
**当**我写入一份坏档案（缺 frontmatter/坏 YAML/裸 `{{`）**时**，我要它被拒绝且不影响其余专家，**以便**手滑不拖垮整个专家团。
- Given 专家团中有 N 个正常专家
- When 新增第 N+1 个坏档案
- Then 坏档案被拒且给出原因；其余 N 个照常可取用可派发

## 上层应用开发者

### US8 服务键取用与派发
**当**我的 dsh 应用 inject 专家团服务键**时**，我要经字符串键取档案、经通用委派 API 派发，**以便**不引入任何专家团源码依赖。
- Given 专家团插件已安装启用
- When 我的应用经服务键请求档案并派发任务
- Then 行为与终端用户经会话委派一致

### US9 随包内置专家
**当**我的插件包随包分发 `experts/` 目录并经通用 root 注册 API 声明**时**，我要包内的专家被专家团收编可派发，**以便**给用户提供开箱即用的领域专家。
- Given 我的插件已安装且声明了内置专家目录
- When 用户在专家团中查看/委派
- Then 内置专家出现且可派发；升级我的插件后用户的禁用状态保持

### US10 同名遮蔽定制
**当**我想改造一个内置专家**时**，我要在 user/project 层放同名档案遮蔽它，**以便**定制不碰上层插件包。
- Given 内置专家 X 存在
- When 我在 project 层创建同名 X
- Then 取用与派发命中的是 project 层版本；删除后回落到内置版本

### US11 独立环境可装载
**当**专家团插件装进没有任何特定上层应用的 dsh 环境**时**，我要它能完成一次通用派发，**以便**证明它是基础能力而非某应用专属。
- Given 干净 dsh 环境、plugin-manager 安装
- When 启用并派发一个通用任务
- Then 全链路可用，源码与档案 schema 零上层业务词汇

### US12 面板浏览与检索
**当**我打开专家团面板**时**，我要浏览全部专家（含禁用态）并按名称/技能标签搜索过滤，**以便**快速定位目标专家。
- Given 专家团中有启用与禁用的专家若干
- When 我在列表搜索框输入关键字 / 切换状态过滤
- Then 列表只显示匹配项；每张卡片可见状态灯、名称、岗位、信条摘要

### US13 查看专家详情
**当**我在列表点开某专家卡片**时**，我要在详情抽屉看到其履历时间轴、工具白名单与技能标签，**以便**不读原始 `.md` 就了解这位专家能干什么。
- Given 列表中存在专家 X
- When 我点击 X 的卡片
- Then 详情抽屉展示履历时间轴（正文渲染）、白名单与标签 chips，不暴露 frontmatter 技术细节；提供编辑/禁用/委派操作位

### US14 HR 预设代招
**当**我对 HR 预设的会话说「招一个数据库迁移专家，工具只留读写与检索」**时**，我要 HR 经专家团管理工具完成建档，**以便**用专职人格代办招聘管理、而非自己记指令格式。
- Given HR 预设已装配且绑定了专家团管理工具（招募/修改/禁用/取用列表）
- When 我向 HR 发出招募/修改/禁用指令
- Then HR 调管理工具完成操作，结果可在面板验证；HR 无委派工具，向其要委派时明确告知应走委派入口

### US15 并发与竞态下的一致性
**当**档案正被编辑（或热刷新进行中）而恰有派发发生**时**，我要派发读到的是某一时点的一致档案快照，**以便**执行中的专家不会用到半成品履历。
- Given 专家 X 的档案正被修改且存在进行中的派发
- When 新派发取用 X
- Then 取到的是完整且通过校验的档案版本（旧版或新版，不含混合内容）；坏档案在任何时点都无法进入派发
