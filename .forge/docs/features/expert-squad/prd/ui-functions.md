# UI 功能：专家团管理面板

落位：`new-page` —— dsh desktop 工作台 `main` 槽 keyed 面板（单一入口模式，annotutor 先例）；委派、招募、追问一律走既有会话流（`existing-page:conversation`），不入面板。

v2 范围修订（用户裁决）：大卡片网格（人设摘要三行 + 技能/白名单两组 chips + 更新时间页脚）；详情 Dialog 查看/编辑双模式；无入职向导、无委派按钮——修改/委派经会话对话；**[召唤] = 打开 HR 预设官方会话（复用 chat-view 切 HR 预设）**。

## 导航架构

- 工作台面板入口（`main` 槽 keyed 行）→ 专家团面板（卡片网格为主视图）
- 面板内仅一层：卡片网格 → 详情 Dialog（查看 ⇄ 编辑）
- 招募/修改/委派/追问经会话对话完成（主会话或 HR 预设）；面板头部留指引文案，不设招募/委派按钮

## F1 专家卡片网格（主视图）

```
┌────────────────────────────────────────────────┐
│ 专家团  [搜索____] [全部▾]        [召唤]    │
├────────────────────────────────────────────────┤
│ ┌───────────────────┐ ┌──────────────┐             │
│ │● 代码评审员        │ │● 架构顾问     │             │
│ │  [code-reviewer]  │ │ [arch-advisor]│             │
│ │ 资深评审           │ │ 方案设计      │             │
│ │ 信条三行截断…   │ │ 信条三行截断…  │            │
│ │ 技能标签        │ │ 技能标签       │            │
│ │ [review][tsc]  │ │ [design]      │            │
│ │ 工具白名单(强制) │ │ 工具白名单(强制)│            │
│ │ [read][edit]…  │ │ [read][grep]  │            │
│ │────────────────│ │───────────────│            │
│ │ 更新昨日          │ │ 更新…          │            │
│ └───────────────┘ └───────────────┘            │
├────────────────────────────────────────────────┤
│ 4 位专家 · 显示 4                               │
└────────────────────────────────────────────────┘
```

- 大卡：状态灯、名称 + **英文标识 chip**（`name` 正本，见名知义）、岗位（禁用附「· 已禁用」且整卡降透明度）、人设三行截断、技能标签 chips、工具白名单 chips（等宽字体）、页脚 = 更新时间
- [召唤] 按钮 → 切换到 HR 预设官方会话（复用既有 chat-view，不自建消息 Modal；会话默认绑定用户当前打开的工作区——dsh-forge 形态工作区按 workspaceId/cwd 归属解析对应项目后再绑定），建档回执后列表联动刷新
- 搜索按名称/英文标识/技能标签即时过滤；状态筛选为 select 组件（全部/启用/禁用 三态）
- 头部布局（用户裁决 2026-10-25）：「专家团」标识右侧 = 搜索框 + 状态筛选 select（左置）；[召唤] 按钮独占右侧——筛选与召唤空间分离
- 四态：骨架卡片 / 空态（指引找 HR 招募）/ 错误条（重试）/ 数据
- 点击卡片 → F2 Dialog

## F2 详情 Dialog（查看/编辑双模式）

```
┌─ ● 代码评审员 [code-reviewer] ─ [编辑] [✕] ┐
│ 资深评审 · 启用中                           │
│ 简介：Runs code review on diffs…（何时委派我）│
│ 人设（Persona）：承接代码评审任务，输出按    │
│ 严重度分级的意见清单；不代写完整实现；        │
│ 以最小改动为美，先证后评…                   │
│ 工具白名单 [read] [edit] [grep]            │
│ 技能标签 [review] [tsc]                    │
├───────────────────────────────────────────┤
│                                 [禁用/启用]│
└───────────────────────────────────────────┘
```

- 查看态：meta / 简介（何时委派我）/ 人设（Persona · Markdown 渲染）/ 工具白名单 chips / 技能 chips——不暴露 frontmatter 其余技术细节
- 编辑态（点 [编辑]）：岗位 / **简介 Textarea（默认 1 行、最多 3 行自适应；上限 120 字）** / 人设（**Markdown 文本域：默认 6 行、最多 50 行自适应，自动换行**，派发时由使用方组装为 `SubagentStartRequest.persona`）/ 工具白名单与技能标签（**multi-select 控件**：box 显已选 chips + 下拉勾选菜单，技能可新增），预填；**统一排序：工具在上、技能在下**；[保存] 校验（裸 `{{`、空岗位字段级报错）通过后写档案 + Toast 热刷新生效，回查看态；**英文标识 `name` 不可改（键正本）**；Dialog 加大（宽 680 / max-height 88%）
- [禁用/启用] 即时生效，状态灯与卡片同步
- 履历（工作记录）**不在本期**——归独立提案（派发链产物）

**档案语义分层**：`name` 英文标识 = 键正本（派发字符串键，不注入内容）；简介 = 何时委派我（模型选人依据，一句话）；人设（Persona）= Markdown 自由输入，派发时组装进 `SubagentStartRequest.persona`（通道一由插件委派工具组装，通道二由使用方组装）。

## 对话式操作（会话流，`existing-page:conversation`）

- 招募：对 HR 预设说「招募一个 XX 专家」→ HR 经管理工具建档 → 面板列表刷新可见
- 修改：对话或面板 Dialog 编辑，两路同写档案正本
- 委派：**通道一主会话对话式**——向专家说任务，插件委派工具组装派发（continuable 子会话），成果回会话流；**通道二代码式**——使用方经取用 API 自行派发（归消费提案）

## 非功能（UI 侧）

- 视觉对齐 DESIGN.md 与官方组件（复用官方件，产品层只做组合注入）
- 样式注入遵循插件样式生命周期契约（factory 同步段或自管 disposer，二选一）
