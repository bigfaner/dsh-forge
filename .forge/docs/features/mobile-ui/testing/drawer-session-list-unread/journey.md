# Journey：抽屉会话浏览 · 未读对账 · 连接状态

**用户故事**：US-5 浏览抽屉会话列表（批次②）。

## 搭建前置条件

- 已配对手机端打开对话主视图；host 存在多个项目、多个会话，其中含未读会话与置顶会话。
- 抽屉打开即拉取 read-state；存留期 15s 轮询生效。

## Happy Path

1. **用户点顶栏 ☰ 打开抽屉** → 预期：抽屉浮层呈现项目树分组会话列表，折叠规则同桌面端，不展示会话数量与归档项。
2. **用户查看置顶会话** → 预期：置顶会话（📌）排在其项目分组顶部。
3. **用户查看未读徽标（含存留期）** → 预期：双级未读徽标与 host read-state 游标一致（抽屉打开即拉取）；抽屉保持打开期间 host 侧新产生的未读在 15s 轮询周期内最终一致更新。
4. **用户点开未读会话** → 预期：进入会话，本地未读即时归零；下次拉取时游标对账一致。
5. **用户点底部连接状态并在弹层中断开** → 预期：弹层展开显示连接详情；断开后状态显示为已断开（impl-screen-4-disconnected 形态）。

## 边界用例

1. **（引步骤 3）打开抽屉瞬间 host 刚写游标**：分叉前置 = 本地徽标与 host 游标短暂不一致 → 下次拉取（15s 轮询）对账后收敛一致（最终一致，不要求实时）。
2. **（引步骤 5）归零后再拉取**：分叉前置 = 用户已读后本地归零、host 游标尚未推进 → 下次拉取以 host 为准对账，不出现已读会话徽标复活或永久误清。
3. **（引步骤 1）无任何会话**：分叉前置 = host 无项目/会话 → 抽屉呈现空态，无残留分组骨架。
4. **（引步骤 5）已断开状态点连接状态**：分叉前置 = 连接已断开 → 弹层仍可查看详情，重连/断开操作不产生双重断开异常。
5. **（引步骤 5）断开后打开抽屉**：分叉前置 = 断线期间打开抽屉 → 列表以最近缓存呈现，徽标不伪造更新；恢复后对账。

## Journey Invariants

- 未读徽标与 host read-state 游标最终一致：打开即拉取 + 15s 存留期轮询 + 写游标后本地即时归零、下次拉取对账。
- 抽屉折叠规则与桌面端一致；不展示会话数量与归档——桌面裁剪例外须显式可见于规格，不得静默增删。
- 断开连接是状态变更动作：只影响手机端连接面，不改变宿主循环行为。
