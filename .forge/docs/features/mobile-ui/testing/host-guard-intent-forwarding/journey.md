# Journey：手机端意图全部经 host 守卫落地（贯穿旅程）

**用户故事**：US-10 宿主守卫不受手机端影响（贯穿批次①②③）。本旅程是横切旅程：以其他旅程的动作面（暂停/派发/分支切换）为素材，验证「意图转发 → 守卫裁决 → 回执呈现」全链。

## 搭建前置条件

- 已配对手机端 + host 任务循环运行中；可在手机端触达暂停/派发/分支切换三类意图。
- 桌面端同 host 在线，可观察循环行为作为对照基准。

## Happy Path

1. **手机端发起分支切换意图（hero）** → 预期：意图送 host 守卫，校验通过才执行落地；拒绝时手机端仅收到确认框数据。
2. **手机端发起暂停意图（任务浮层）** → 预期：host 校验通过后任务暂停；桌面端看到的循环状态与手机端一致（单一事实源在 host）。
3. **手机端发起派发意图** → 预期：host 校验通过后派发执行，循环推进由桌面端同源逻辑决定。
4. **桌面端观察全程循环行为** → 预期：循环无任何因手机端操作而改变行为的路径——手机端动作只是经守卫后的合法意图注入。

## 边界用例

1. **（引步骤 1）守卫拒绝分支切换**：分叉前置 = host 建会话守卫拒绝 → 失败只回传确认框/提示数据；不出现手机端臆测的半切换状态。
2. **（引步骤 2）暂停意图与桌面端并发**：分叉前置 = 桌面端同时操作同一任务 → 正确性由 host 单点保证，两端口径收敛一致，客户端竞速不改变落点。
3. **（引步骤 3）派发意图在数据 stale 时发出**：分叉前置 = 手机端数据已过期 → 按钮置灰意图发不出；若绕过 UI 直发，host 守卫仍拒绝。
4. **（引步骤 2）手机端断线期间意图补发**：分叉前置 = 意图发出后手机端断线 → host 侧按守卫结果独立落地，恢复后手机端以 host 状态对账呈现。

## Journey Invariants

- **守卫单点**：手机端任何动作意图（暂停/派发/分支切换/会话创建）一律经 host 守卫校验后才执行；手机端零校验、零直接落地。
- **失败只回传数据**：校验失败时手机端只收到确认框/提示数据，不猜测、不降级执行。
- **循环主权**：任务循环行为只由桌面端逻辑决定，不存在任何因手机端操作而改变循环行为的代码路径。
